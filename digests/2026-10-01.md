## AWS What's New

**[Amazon Bedrock Managed Agents, powered by OpenAI, is now available in preview](https://aws.amazon.com/about-aws/whats-new/2026/09/bedrock-managed-agents-preview/)**
Developed jointly by AWS and OpenAI, Bedrock Managed Agents (BMA) brings OpenAI's Agents API to AWS-native infrastructure, handling state preservation, tool selection, code execution, and multi-step coordination entirely within AWS. Agents run under existing IAM identities and governance controls, with durable sessions spanning multiple steps and decisions.

**[Amazon RDS now adds full snapshot size information to the Console and API](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-rds-full-snapshot-size-available/)**
RDS Snapshots now expose full snapshot size via the `FullSnapshotSizeInBytes` field in the DescribeDBSnapshots API and a dedicated column in the console. Since RDS snapshots are incremental, this fills a gap where customers could see per-snapshot incremental sizes but not the total restore footprint.

**[OpenAI GPT-6.1 Sol is now generally available on Amazon Bedrock](https://aws.amazon.com/about-aws/whats-new/2026/09/openai-gpt-6-1-sol-on-amazon-bedrock/)**
GPT-6.1 Sol, an upgrade to GPT-6 Sol, is now generally available on Amazon Bedrock. According to OpenAI, it approaches GPT-6 Astra performance on agentic coding, computer use, and professional work at roughly one-fifth of the cost.

**[Amazon Connect Customer now lets business users manage more reference data to adjust contact center configurations in real time](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-connect-manage-data-tables/)**
Amazon Connect data tables now support up to 20,000 values per table for configurations such as operating hours, escalation rules, AI agent prompts, and queue assignments. Administrators can export tables, bulk-edit records, move tables between Connect instances, and load reference data from external systems.

**[Amazon WorkSpaces Applications introduces unified graphics images](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-workspaces-applications-unified-graphics-images/)**
A single image type now works across all supported graphics instance families (G4dn, G5, G6, G7), replacing the previous model where each GPU generation required its own dedicated image. This simplifies fleet management and lowers friction when adopting newer GPU hardware.

**[AWS Service Availability Updates](https://aws.amazon.com/about-aws/whats-new/2026/09/aws-service-availability/)**
Several AWS services are moving to Maintenance status and will be closed to new customers starting October 29, 2026; existing customers may continue using them. Affected services include Amazon Chime SDK SIP Media Application, among others detailed in the announcement.

**[Amazon RDS for PostgreSQL announces Extended Support minor versions 13.23-rds.20260514, 12.22-rds.20260514 and 11.22-rds.20260514](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-rds-postgresql-extended-support/)**
Extended Support minor versions are now available for PostgreSQL major versions 11, 12, and 13 on RDS, delivering critical CVE fixes and bug patches beyond each version's standard support end date. Upgrades can be performed via Blue/Green Deployments or in-place upgrades.

**[Amazon Aurora now supports PostgreSQL 18.6, 17.11, 16.15, 15.19, 14.24](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-aurora-postgresql-18-6-17-11-16-15-15-19-14-24/)**
Aurora PostgreSQL-Compatible Edition adds support for five new minor versions across major releases 14 through 18, incorporating PostgreSQL community bug fixes and Aurora-specific enhancements. Upgrades are available via scheduled maintenance windows and automatic minor version upgrade settings.

**[Amazon Bedrock expands Claude model availability to India, South Korea, and Singapore](https://aws.amazon.com/about-aws/whats-new/2026/09/claude-region-expansion-in-sk/)**
Claude Opus 5, Sonnet 5, and Haiku 4.5 are now on Bedrock in India; Opus 5 and Sonnet 5 in South Korea; Sonnet 5 in Singapore. The expansion addresses data residency requirements for regulated industries — financial services, healthcare, and public sector — that need in-country inference.

# 🤖 AI & Machine Learning

## AI Engineer

**[The State of AI in Software Development: Data from 400+ Orgs — Justin Reock, DX](https://www.youtube.com/watch?v=Se8jHLliLXE)**
DX's dataset of roughly 200,000 engineers reveals that AI coding tools are moving the wrong metrics in unexpected ways: deployment frequency is rising, but change failure rate has become more volatile, and developer confidence in their own changes is falling even as code maintainability improves.

- **PR size inflation is a risk signal.** Average PR size grew from about 44 to 72 lines — a proxy for AI-generated code entering review queues and a leading indicator of review quality degradation.
- **Juniors use AI most; staff engineers use it best.** Junior engineers are the heaviest users, but staff-level engineers save comparable time while consuming fewer tokens — suggesting more targeted, higher-leverage usage patterns at seniority.
- **Code generation was never the bottleneck.** Median PR throughput gains are around 7.7%, and even top performers didn't reach 2x improvement, because writing speed was not the constraint.
- **Volatility in failure rate is the underreported story.** Rising deployment frequency combined with a more volatile change failure rate means AI is amplifying both delivery speed and delivery risk at the same time.

**[The Chief AI Officer: Scientist, Architect, Coach — Rania Khalaf, WSO2](https://www.youtube.com/watch?v=9cJrbj23fOA)**
The CAIO role is among the fastest-growing in tech and one of the least defined — without an operating model it defaults to owning everything AI touches. Rania Khalaf, drawing on two years as CAIO at WSO2 and approximately twenty years at IBM Research where she ran about a third of the global AI research organization, offers a three-part framework to make the role tractable.

- **Three sliders, not three silos.** Scientist, Architect, and Coach are not separate job descriptions but dials whose settings shift based on company type, AI maturity, and organizational context.
- **The scope problem is structural.** Because AI permeates the entire business, the CAIO's mandate expands by default; the framework's primary function is preventing that expansion from becoming unmanageable.
- **Company type and AI maturity determine the dial settings.** The framework is not a fixed configuration — what ratio of Scientist to Coach is right depends on where the organization sits in its AI adoption curve.

**[The Death of the Code Review: What the Data Actually Says — Laurie Voss, Arize AI](https://www.youtube.com/watch?v=_mi3alkqy4s)**
Autonomous coding agents are creating a structural mismatch: developers using them wrote 741% more code but shipped only 30% more software, because human code review is now the binding constraint — and reviewer effectiveness collapses past roughly 400 lines while agents routinely open 10,000-line PRs.

- **The review ceiling is a hard constraint.** Reviewer effectiveness collapses past about 400 lines; "review harder" does not scale against agents that open PRs an order of magnitude larger.
- **741% more code, 30% more software.** The ratio between code written and software shipped is the clearest quantification of where AI's productivity gains are being absorbed.
- **Benchmark-passing does not equal production-ready.** METR's finding that roughly half of SWE-bench-passing PRs would not pass human review illustrates the gap between evaluation performance and real-world deployability.
- **The industry is responding with structural changes.** Evidence in the talk includes OpenAI's zero-human-code product as one of several approaches being taken to redesign the review process rather than scale the existing one.

**[Your Agents Are in Solitary Confinement: Why MCP & A2A Aren't Enough — Vlad Luzin, Band](https://www.youtube.com/watch?v=UOcHfR3_tys)**
Running multiple AI agents in parallel today requires a human or a script to act as message router between stateful processes — MCP and Agent-to-Agent protocols don't solve the fundamental distributed-systems problem of agents working together as peers.

- **Bigger context windows don't fix the single-agent bottleneck.** Expanding what one agent can hold in memory doesn't enable real coordination between agents with separate, evolving state.
- **Loop engineering is a workaround, not a solution.** Handing routing to a script rather than a human is a marginal improvement; it still doesn't allow agents to collaborate natively.
- **Human messaging platforms carry the wrong assumptions.** Slack, Discord, and WhatsApp were designed for human interaction patterns and are not appropriate substrates for agent-to-agent coordination at scale.
- **Agent connectivity is a distributed systems problem.** Solving it requires infrastructure built for the problem — not repurposed chat protocols or prompt engineering.
