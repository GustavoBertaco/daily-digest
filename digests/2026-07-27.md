# 🤖 AI & Machine Learning

## AI Engineer

**[The Messy Reality of Scale: Synthetic Data and Pre-Training — Marah Abdin & Robert McHardy, poolside](https://www.youtube.com/watch?v=KhYifX22yhE)**
Natural code data runs out at scale; poolside's answer is a synthetic generation pipeline that manufactures more of it — but the hard part is engineering the data to actually teach the model, not just fill a training bin.

- **Difficulty calibration is the core constraint.** Tasks must sit in a productive learning zone — neither trivial (the model already solves them) nor so hard that no useful gradient signal returns. Getting that axis right is what separates useful synthetic data from noise.
- **Templates plus supplementary context anchor generation.** Rather than generating from scratch, the pipeline pairs templates with contextual material, keeping outputs grounded while spreading variety across an axis of phrasing.
- **Multistage pipelines multiply existing assets.** The system ports existing data into new shapes — swapping character styles or plots, converting single prompts into multi-turn conversations — rather than treating synthetic generation as a blank-slate problem.
- **An orchestrator polices every generation.** A dedicated orchestration layer acts as a quality gate, screening outputs before they enter the training pipeline and preventing degraded samples from propagating into pre-training data.

**[Evals-Driven Development for a Mental Health AI Coach — Akele Reed & Dave Revere, SonderMind](https://www.youtube.com/watch?v=O72p-rBb2bA)**
In clinical AI, vibes-based evaluation carries real consequences. SonderMind replaced intuition-driven iteration with a structured evals-driven loop grounded in continuous human therapist feedback, treating safety and effectiveness as co-equal objectives from the start.

- **A clinical feedback loop converts therapist judgment to machine-readable signal.** Human therapist insights are translated into evaluations that run automatically across thousands of conversations, making qualitative clinical expertise a scalable, systematic input rather than a one-off review.
- **The Ethics Engine separates guardrails into discrete modules.** Safety rules are implemented as components that can evolve independently as clinical guidelines change, avoiding the brittleness of a monolithic safety layer.
- **Moving from single-prompt to closed-loop agents.** The architecture shifted from one-shot prompting to agents operating in a closed loop, allowing the system to self-correct within a conversation rather than committing irrevocably to a first output.
- **Safety and effectiveness must be co-evaluated, not traded off.** The playbook runs both dimensions through every evaluation cycle — optimizing for effectiveness alone in a mental health context introduces real harm risk that the eval framework is explicitly designed to surface.

**[Loop Engineering from First Principles — Kyle Mistele, HumanLayer](https://www.youtube.com/watch?v=xIt_mTQp6mY)**
The failure modes of coding agents — unreviewably large diffs, silent correctness errors — are loop problems, not prompt problems. Kyle Mistele's argument is that the fix comes from borrowing the sense-act-measure cycle of control theory, not from refining instructions.

- **Prompting is not the lever.** A 40,000-line pull request that nobody can review and that quietly does the wrong thing isn't caused by a weak prompt; it is caused by the absence of iteration boundaries that constrain each step's scope.
- **Control theory as the design template.** A thermostat continuously senses the gap between actual and desired state, emits a bounded control signal, and measures again before acting further. Agent loops should follow the same structure.
- **Infrastructure as code already approximates this pattern.** IaC tooling — declare desired state, apply a diff, observe actual state — already embeds the sense-act-measure discipline. Agent frameworks can adopt it directly.
- **Reviewability is the implicit quality criterion.** If a single agent iteration produces output too large or opaque to verify, the loop boundaries are wrong regardless of how capable the underlying model is.

**[Why Large? Tiny LMs & Agents on Edge/Robotics — Cormac Brick, Google](https://www.youtube.com/watch?v=hacEQHHhu2Q)**
The binding constraint for edge AI is RAM, not compute — and it is getting worse, not better. Google AI Edge's work shows that aggressive quantization and sub-2B parameter models can deliver practical language model capability on severely memory-constrained hardware.

- **RAM, not FLOPS, sets the ceiling.** Phone makers are shipping less RAM this year and a 6GB Raspberry Pi now costs 2.5 times its launch price. Every model size decision for edge deployment must be driven by the RAM budget, not available compute.
- **2.9-bit quantization as the working calibration point.** A 2-billion-parameter Gemma quantized to 2.9 bits per weight runs on a Raspberry Pi at roughly 8 tokens per second — low, but functional for a broad class of agentic tasks.
- **Qualcomm NPU opens the vision pipeline.** At NPU speeds, frame-level vision processing becomes feasible on the same class of devices, making edge robotics and always-on visual sensing tractable without a server in the loop.
- **The economics favor tiny models and are worsening.** As commodity edge hardware gets more expensive, the case for RAM-efficient, sub-2B parameter models strengthens — the constraint is structural, not temporary.
