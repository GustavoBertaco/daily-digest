# 🤖 AI & Machine Learning

## AI Engineer

**[AI-Generated Code Is Already Competing With Human Code — Daksh Gupta, Greptile](https://www.youtube.com/watch?v=474j-n1Ltxc)**
Greptile analyzed over a million pull requests a month to answer a concrete question: are AI-generated PRs actually any good in enterprise codebases? By April, more than a quarter showed signs of being written largely or entirely by AI agents — up from under 1% a year earlier.

- **The scale of adoption is now measurable.** Reviewing PRs from companies including NVIDIA, Coinbase, and Scale, Greptile found AI authorship moved from statistical noise to a material fraction of enterprise output within twelve months.
- **Named agents, quantitative comparison.** Codex, Claude Code, Devin, and Cursor are measured against human-written PRs on four dimensions. The comparison is enterprise-scoped — not synthetic benchmarks, but production pull requests from large organizations.
- **"Vibe-coded" has reached the enterprise.** The question has shifted from whether AI code can pass review to whether it holds up in high-complexity, production-grade codebases at scale.

**[Get Out of the Model's Way — Kevin Hou, Google Antigravity](https://www.youtube.com/watch?v=buHC7bQE1X4)**
Kevin Hou, who leads engineering at Google Antigravity — Google DeepMind's agentic coding product — argues the best product strategy is to remove friction from the model rather than constrain it. The headline demonstration: 93 subagents, 12 hours, 2 billion tokens, and under $1,000 to build an operating system kernel from scratch that runs Doom.

- **The core operating principle.** "Give Messi the ball and get out of the way." A product designed to amplify the model improves automatically every time the underlying model does — compounding returns without product changes.
- **Tooling has evolved through discrete phases.** Hou traces autocomplete in 2022, agents in 2024, agent managers in 2025, with the current generation implying orchestration at scale as the next step.
- **Under $1,000 for a Doom-running kernel.** The benchmark is a concrete cost and complexity anchor: highly complex, long-horizon agentic work is now within reach of very modest compute budgets.

**[Software Engineering Is Becoming Factory Engineering — Zach Lloyd, Warp](https://www.youtube.com/watch?v=tUPPVhBBcoM)**
Zach Lloyd — Warp founder and former Google Docs engineering lead — hasn't written a line of code in six months and is still shipping constantly. His thesis: software engineering is turning into factory engineering, and every serious project will eventually run a software factory the same way every project now runs CI/CD.

- **The CEO as factory operator.** Lloyd is both evidence that the thesis is real (he leads a dev tools company and has delegated all coding) and the most credible narrator for what factory engineering means in practice.
- **Open-sourcing as distribution.** Warp went open-source after five years closed, reaching 60,000+ GitHub stars and over 800,000 active developers. The move reflects how dev tools now acquire users when AI lowers the cost of building alternatives.
- **Cheapness creates the factory opportunity.** Lloyd frames the move to factory engineering as an inevitable response to software becoming cheap to build — the same shift that made CI/CD standard for every project.

**[GLM-5.2: Open Weights, Near-Frontier Intelligence — Zixuan Li, Z.ai](https://www.youtube.com/watch?v=9JFGohx4E7U)**
Z.ai introduces GLM-5.2, an open-weights model that lands between Claude Opus 4.7 and 4.8 on the hardest long-horizon coding and agentic benchmarks. Its non-thinking mode outperforms GLM-5.1 with thinking enabled, and it leads other open-weight models on the Artificial Analysis Intelligence Index.

- **The capability bar for open weights has moved.** Sitting within the operational range of current Claude Opus versions means open-weight models are now viable for hard agentic work, not just simpler tasks.
- **Non-thinking mode beats prior-generation thinking.** The default serving mode outperforming the previous generation's reasoning mode is a meaningful efficiency signal — full capability without paying thinking-mode latency and cost.
- **Z.ai's roots go back to 2021.** The GLM name comes from a 2021 paper that placed Z.ai among the earliest LLM labs, context that matters for evaluating how much institutional research depth sits behind the model.
- **Not just a coding model.** Li explicitly frames GLM-5.2 beyond the coding benchmark narrative, though the snippet cuts off before detailing the broader application scope.

**[Orchestras, Not Factories: How the Fastest Builders Work — Charlie Holtz, Conductor](https://www.youtube.com/watch?v=TRfzFJCJ7ZE)**
Charlie Holtz, co-founder and CEO of Conductor — a desktop app for running many coding agents simultaneously — pushes back on the "software factory" framing from a position of having watched the fastest builders work up close. His counter-thesis: the best teams run like orchestras, not assembly lines.

- **Don't compete with the default.** Stay near the frontier but avoid building workflows popular enough for the big labs to absorb into their defaults. The durable advantage lies in what the defaults won't do for a specific context.
- **Slop-free zones are non-negotiable.** Migrations, documentation, and skill files should always get careful human review regardless of how much else is delegated to agents — these are the artifacts where accumulated errors compound.
- **How you feed the model matters.** The snippet cuts off mid-sentence but the framing positions context and feedback design as a distinct skill, separate from prompting.

**[Scale the Judgment, Not the Model — Andrew Orobator, Reddit](https://www.youtube.com/watch?v=6MudaeKdBSk)**
Andrew Orobator, a senior Android engineer at Reddit, argues that swapping in a smarter model is the least effective lever available. The real bottleneck is the judgment surrounding the model: the tests, gates, and review processes that determine whether outputs are usable.

- **Judgment is implicit in humans, explicit for agents.** Engineers absorb what "good" looks like through years of accumulated context; agents need that judgment spelled out in the repo before they can do useful work. This is the real setup cost of agent adoption.
- **Skills as codified institutional knowledge.** "Skills" in this framing are not model capabilities but documented institutional judgment turned into executable artifacts — the things a new engineer would have to learn the hard way, made legible to an agent.
- **Work logs as institutional memory.** The snippet cuts off before completing the description, but positions work logs as a mechanism for preserving and transmitting context across agent sessions.

**[No, That's Not a Software Factory — Ryan Cooke, WorkOS](https://www.youtube.com/watch?v=HvboD89DyQ8)**
Ryan Cooke from WorkOS found that a standard software factory — sandbox, prompt, merge PR — produced results indistinguishable from engineers running Claude Code on their laptops. The fix was to build WorkOS's engineering process into the factory itself, not just give the factory a task runner.

- **The baseline factory is table stakes.** A sandboxed agent that merges PRs automates the easy part. The value lies in the orchestration layer and the institutional context that surrounds execution.
- **Measure outcomes, not AI activity.** Counting PRs merged or lines of AI-generated code is the wrong signal. The right question is whether you are shipping more value to customers — a distinction that changes what the factory needs to optimize for.
- **TARS lives where work happens.** WorkOS's agent is embedded in Slack, Linear, and GitHub rather than a separate portal, aligning agent access with the surfaces where engineering decisions are actually made.

**[What It Actually Takes to Build a Software Factory — Tereza Tížková, Factory](https://www.youtube.com/watch?v=vGCJ7diEtrw)**
Tereza Tížková of Factory — which runs software factories for enterprises including EY and Adobe — defines one as the entire software lifecycle running autonomously: collecting signals, prioritizing, building, validating, and improving. Writing code, she notes, is the easy part.

- **Lifecycle scope, not coding scope.** The mistake is treating a software factory as a swarm of coding agents. The hard problems are signal collection, prioritization, and validation — the work that happens before and after the code is written.
- **Stay agnostic on tooling.** The first of Tížková's three principles: fit how teams already work and route between models automatically. Locking into a specific model or workflow creates fragility as the frontier shifts.
- **Enterprises as the proving ground.** Deployments at EY and Adobe place these principles in high-stakes, compliance-sensitive environments — the context where the difference between a coding swarm and a real software factory becomes most visible.
