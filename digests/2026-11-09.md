## Daniel Pink

**[The Preschooler Drawing Experiment](https://www.youtube.com/watch?v=7jL_ok_iUVs)**
A 1973 psychology experiment reveals why anticipated rewards undermine intrinsic motivation — the damage isn't done by rewards themselves but by converting a voluntary act into a transaction you're owed for.

- **The promise, not the prize.** Children who drew for a promised reward later spent roughly half as much free time drawing; those who received a surprise reward afterward showed no drop in engagement.
- **Foreknowledge is the mechanism.** The only children who lost interest were those who knew the reward was coming in advance. Without that prior knowledge, the same external reward left motivation intact.
- **Intrinsic motivation is quietly vulnerable.** The love for the activity didn't disappear abruptly — it left when the act became transactional. The experiment's power is that this shift was measurable weeks later.
- **Foundational reference.** Lepper, Greene & Nisbett (1973) — the overjustification effect study that underpins much of subsequent motivation research.

## AI Engineer

**[How Financial Planners With Zero Coding Experience Built Their Own Agents](https://www.youtube.com/watch?v=EaOit1mmR9g)**
Matt Ragone, a financial planner at wealth management firm Range who leads AI adoption, describes how a non-technical planning team built functional agents — enabled by standardized processes and centralized client data rather than coding skill.

- **Standardization is the prerequisite.** Uniform processes and client data already in one place gave the team a foundation that made agent-building tractable without engineering support.
- **Agents draft in parallel with human work.** The system produces cash flow analyses, insurance reviews, and tax reviews while planners are on calls with other clients — multiplying throughput without adding headcount.
- **Certified planners review all output.** A CFP reviews everything the agent drafts; the agent handles production, not final judgment.
- **Domain expertise, not code, was the lever.** Non-technical practitioners built agents using their own process knowledge, lowering the bar for teams with deep domain expertise but no engineering background.

**[Your Coding Agent Can't Undo Its Own Mistakes](https://www.youtube.com/watch?v=BT1Mo-fD-g0)**
Tanmay Sah and Dolly Sah identify a systematic gap in today's coding agents: completing a task and reversing it are independent capabilities, and current agents are weak at the latter.

- **Git is not an undo system.** Code reversion covers only file changes — external API calls, runtime configuration changes, and notifications triggered during a task can't be rolled back through version control.
- **Retrying is not reversing.** Agents often re-attempt failed operations, but re-execution doesn't undo side effects already in progress.
- **Capability gains can cost recoverability.** Their UndoBench and EvoUndo research found that 42% of changes improving an agent's task performance also degraded its ability to recover from mistakes.
- **The key number.** 197 of 478 capability-improving changes broke recovery ability — suggesting raw performance optimization and reversibility are in tension by default.

**[Your Company Has No Model of Itself. Agents Can Build One](https://www.youtube.com/watch?v=jDwc0aXTAFg)**
Joao Wenzel of Citadel Securities describes an agentic approach to building institutional memory — borrowing the robotics concept of a "state estimator" to approximate the organizational knowledge that usually lives in a single person's head.

- **The institutional knowledge problem.** Every organization has an informal expert who knows the real state of things — reorgs, which projects are actually on track. This system tries to replicate that by ingesting decks, Slack, meeting notes, code changes, and agent traces.
- **State estimator as architecture.** Borrowed from robotics, the system maintains a probabilistic belief about organizational state and updates it as new evidence arrives — not a static knowledge base.
- **Facts age deliberately.** The system deprioritizes stale information, treating organizational state as dynamic rather than permanent.
- **Self-grading closes the loop.** The system grades its own predictions against what actually happened, enabling the organizational model to improve over time.

**[Don't Vibe Code Your Agent Infrastructure](https://www.youtube.com/watch?v=_0SQh8a1Osk)**
Akshat Bubna, CTO of Modal, argues that agent infrastructure requires deliberate design — not improvised approaches — and walks through the specific primitives that agentic workloads actually need.

- **Each agent needs its own workspace.** Shared environments cause interference; isolated workspaces keep agent states clean and prevent cross-contamination.
- **Persistent state without idle cost.** Agents may need to maintain state for days between actions; infrastructure should support this without billing for unused compute.
- **Dynamic resource sizing.** Agentic workloads are bursty — infrastructure must stretch and shrink with demand, with GPU access on demand rather than reserved allocation.
- **Security requires explicit controls.** Shared file systems enable agent collaboration but need network controls to prevent credentials and data from leaking between agents.
- **Observability is load-bearing.** The risk of improvised infrastructure is building something that works until it fails silently — observability is what makes the difference detectable.

**[Your Financial Agent Needs to Show Its Work](https://www.youtube.com/watch?v=gdzsJZJ6DDs)**
Anirudh Veeraragavan, lead security engineer at Fieldguide, argues that in regulated finance, agent correctness is necessary but insufficient — the decision process must be defensible and auditable.

- **Correctness is table stakes; auditability is the bar.** For a bank reconciliation audit, an agent must show how it reached its answer, not just what the answer is.
- **Authorization guards human-reviewed work.** A control prevents the agent from overwriting anything a human has already reviewed, preserving review integrity.
- **Execution records enable replay.** Storing individual step outputs lets auditors replay and compare agent decisions at any point — not just inspect the final output.
- **Citations are version-pinned.** Each citation is tied to an exact document version, so the evidence the agent relied on can be located and verified independently.
