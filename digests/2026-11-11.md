## The Pragmatic Engineer

**[The value of AI is not doing the same thing faster](https://www.youtube.com/watch?v=LDcRdpVvmgQ)**
Titus Winters, co-author of *Software Engineering at Google*, joins The Pragmatic Engineer to argue that AI's true value is not speed but tractability — enabling work that wasn't possible before.

**[Software correctness and programming languages with Sean Allen](https://www.youtube.com/watch?v=OrXKvOjR-vI)**
Sean Allen, Distinguished Engineer at Antithesis, examines the software-correctness fundamentals being amplified by AI-assisted development — deliberately avoiding the phrase "AI" throughout to force a return to what type systems, compiler guarantees, and concurrency models actually provide.

- **Language choice is a correctness statement.** The episode tours OCaml, Ada, F#, and Pony not as a comparison exercise but as a map of how different language communities have drawn the boundary between "compiler says no" and "runtime surprise."
- **Ada's compiler guarantees as a template.** Ada's decades-old approach to embedding safety constraints in the type system gets revisited as a concrete model for what modern languages could borrow when reliability is non-negotiable.
- **Pony's capability-based concurrency.** Pony's ownership model eliminates data races at the type level — the episode surfaces this as a live alternative to the GC-induced latency and concurrency bugs common in mainstream runtimes.
- **Garbage collection assumptions need revisiting.** The conversation questions whether GC trade-offs still make sense as workload predictability requirements evolve, tying memory management directly to correctness guarantees.

- **One number to remember.** Rumination is often a bigger predictor of depression outcomes than the original stressor — a finding that reframes where mental-health interventions should be targeted.

## AWS What's New

**[CloudWatch PromQL alarms now support EC2 and Application Auto Scaling](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-alarms-autoscaling-group-actions)**
CloudWatch alarms using PromQL can now trigger EC2 and Application Auto Scaling step and simple scaling policies, letting teams scale Auto Scaling groups directly from OpenTelemetry metrics with the same queries used for dashboards. Target tracking policies are not yet supported for PromQL alarms.

**[Amazon OpenSearch Service now lets you validate and roll back version upgrades](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-service/upgrades/)**
Clone-based upgrades let you run a new OpenSearch version alongside your existing cluster, validate it, and cut over only when satisfied — with the option to cancel before cutover or roll back afterward. This addresses the irreversibility risk of in-place version migrations.

**[Amazon Bedrock AgentCore now offers a Web Search API](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-bedrock-agentcore-web-search-api/)**
The InvokeWebSearch API on Bedrock AgentCore is now generally available, enabling applications, agent loops, and data pipelines to run web searches with a single API call against Amazon's own web index — no resources to provision. Each result includes a text extract and ranked ordering.

**[Amazon CloudWatch Logs announces account-level retention policies](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-log-retention/)**
A single account-level policy can now govern log retention across all log groups or a prefix-matched subset in an AWS account, replacing per-group manual configuration. Policies can target all log groups or groups whose names start with a specific prefix, such as `/aws/lambda`.

**[AWS Glue adds 100 new native connectors for popular SaaS applications](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-glue-adds-100-new-native-connectors/)**
AWS Glue now supports 100 new native connectors for SaaS and REST API sources — spanning generative AI, finance, payments, marketing, HR, and IT operations — using the same permissions model as existing Glue jobs. Teams no longer need custom code to ingest from these sources.

**[AWS STS now supports cross-partition federation for AWS identities](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-sts-cross-partition)**
AWS STS can now federate IAM identities across partitions — for example, from commercial regions to AWS GovCloud — letting workloads obtain temporary credentials in a different partition without storing long-term credentials. This removes the previous requirement for separate credential management at partition boundaries.

**[Amazon Quick is now AWS Quick](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-quick-aws-quick/)**
Amazon Quick, the enterprise AI workspace, is rebranded to AWS Quick to reflect its AWS-native security and governance foundation. Amazon Quick Sight becomes AWS Quick Sight; no action is required for existing customers.

**[Amazon Connect Customer launches evaluation form templates](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-customer-evaluation-form-templates/)**
Amazon Connect now ships pre-built evaluation form templates for customer service, inbound sales, and self-service scenarios, reducing time to deploy automated assessments of human and AI agent performance. Templates include behavioral questions such as whether an agent showed empathy toward a customer's issue.

## AI Engineer

**[The Agents Were Fine. Everything Around Them Broke. - Joey Wang, Harvey](https://www.youtube.com/watch?v=ktbAVYsAxpk)**
After 10,000 agent-written pull requests at Harvey, the bottleneck was never the agents — it was the surrounding infrastructure. Joey Wang describes Spectre, Harvey's internal cloud agent platform, and the cascade of failures that emerged once agents began operating at scale.

- **Platform owns "after" so engineers own "which."** Harvey separates agent selection (the engineer's choice) from post-submission orchestration (the platform's responsibility), reducing blast radius when something goes wrong.
- **Every action must be callable by another agent.** Making all platform actions composable lets agents drive other agents — but that composability is exactly what triggered the downstream failures.
- **Alert storms become horizontal scaling events.** Once agents could trigger agents, a single alert spun up hundreds of tasks and a full cluster — standard alerting infrastructure wasn't built for that fan-out pattern.
- **Merge queues are a throughput chokepoint.** At agent-generated PR volumes, the merge queue became the binding constraint — a failure mode invisible until CI/CD infrastructure is stress-tested by agent velocity.

**[60% of Our Data PRs Now Merge With No Human Review - Chetas Joshi, Robinhood](https://www.youtube.com/watch?v=MQiojLnK-E0)**
Coding agents made data pipeline pull requests cheap to produce, but human review couldn't scale to match. Robinhood built a hybrid reviewer agent that handles the majority of approvals, saving roughly 132 engineering hours a month.

- **Deterministic checks run first.** The reviewer separates what scripts can verify from what requires model judgment — structurally limiting the surface area where the model can be wrong.
- **60% of PRs merge without a human.** That is Robinhood's operational threshold after tuning; anything flagged as high-risk still requires human sign-off.
- **The reviewer itself must be evaluated.** Building an agent to review other agents creates a meta-evaluation problem: Joshi covers how they assess the reviewer's own quality over time.
- **132 engineering hours saved per month.** The concrete ROI grounds the architecture decisions and justifies maintaining the hybrid rather than pursuing full automation.

**[An Agent That Fixes Its Own Mistakes - Saloni Gandhi & Ziwei Guo, LinkedIn](https://www.youtube.com/watch?v=yH7_SIIgI-Y)**
LinkedIn's career-AI agent builds a continuously evolving picture of each member from profiles, preferences, goals, and activity. The notable engineering is the closed feedback loop: the agent evaluates its own outputs, identifies failure patterns, reflects on root causes, and uses GEPA to refine its own instructions.

- **Self-evaluation as an operational loop, not a one-time audit.** The agent continuously assesses its outputs against quality criteria, making improvement part of the runtime rather than a periodic offline process.
- **Failure pattern identification precedes root-cause work.** Surfacing systematic failures across output samples is the prerequisite to meaningful reflection — reacting to individual errors misses the structural signal.
- **GEPA for prompt refinement.** GEPA (Gradient-based Evaluation and Prompt Adaptation) is the specific method used to translate root-cause analysis into updated instructions.
- **The roadmap targets the full harness, not just prompts.** The team's next phase moves beyond prompt tuning to improving the agent's overall architecture, framing prompt-level work as only the first layer of improvement.

**[Stop Chatting With Spreadsheets — Francesco Galletta & Felippe Felisola Caso, Monzo](https://www.youtube.com/watch?v=ATMcd9tkhhc)**
Getting fast answers from an AI financial analyst is easy; getting answers trustworthy enough to inform real financial decisions is the hard problem. The speakers build a live financial-analyst agent and articulate five design principles for AI you can trust with money.

- **Five principles: shared domain, consistency, evidence, accountability, verification.** These are tested against a concrete use case — planning a wedding budget — during the live build, not asserted abstractly.
- **Calculations belong in code, not in the model.** The model handles structural reasoning; arithmetic goes to a deterministic layer. Mixing the two is where financial agents break trust.
- **Evidence and accountability are first-class requirements.** A trustworthy financial answer must cite sources and preserve an audit trail — returning a number without provenance is not an acceptable output for financial use cases.

**[Your Self-Hosted LLM Needs to Say No - Harshul Jain & Parv Khatri, Audible & SAP](https://www.youtube.com/watch?v=ntVpbyDTYaQ)**
Coding agents fan out, retry, and burst — and a self-hosted inference layer will accept every request, burying high-priority work under agent-generated load. Jain and Khatri make the case for admission control as the missing layer in self-hosted LLM infrastructure.

- **Admission control decides what to refuse before it hits the GPU.** Accepting everything and prioritizing later is the wrong model; the decision point must move upstream to prevent queue saturation.
- **Grounded in 55 systems papers and 8 real production incidents.** The recommendations are drawn from documented infrastructure failures and research, not theoretical analysis.
- **Five questions to ask any admission policy.** A concrete pre-deployment checklist covering fairness, latency guarantees, and burst tolerance — usable immediately when evaluating admission approaches.
- **Agent traffic patterns are fundamentally different.** Fan-out and retry behavior from coding agents creates traffic profiles that commodity rate-limiting and queuing systems were not designed to handle.
