## AWS What's New

**[AWS Certificate Manager now supports ACME issuance through AWS PrivateLink](https://aws.amazon.com/about-aws/whats-new/2026/10/AWS-Certificate-Manager-ACME-Privatelink)**
ACM now supports PrivateLink for ACME public certificate issuance, routing TLS certificate requests and renewals over a private network path within AWS rather than the public internet. Existing ACME clients require no changes; setup only requires creating a VPC interface endpoint to the ACM ACME service.

**[Amazon Redshift adds support for creating and refreshing Apache Iceberg materialized views](https://aws.amazon.com/about-aws/whats-new/2026/10/redshift-iceberg-materialized-views)**
Redshift can now create and refresh Apache Iceberg materialized views, pre-computing expensive joins and aggregations into Iceberg tables stored in S3 or S3 table buckets registered in the AWS Glue Data Catalog. Results are immediately queryable by any Iceberg-compatible engine including Athena and Apache Spark via standard SQL syntax.

**[GLM 5.3 by Z.ai is now generally available on Amazon Bedrock](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-bedrock-glm-5-3/)**
Z.ai's GLM 5.3 is now generally available on Amazon Bedrock, targeting agentic coding and long-horizon software engineering work. It is a mixture-of-experts model with 753B total parameters and approximately 40B active per token, built on the GLM 5.2 base model with improvements driven by scaled post-training.

**[AWS IAM Identity Center now supports network access controls for Identity Store](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-identity-store-network-controls/)**
IAM Identity Center now supports network access controls for Identity Store, allowing administrators to restrict Identity Store API and SCIM API access based on the originating network. This covers both the custom-application API used to manage and look up users and groups and the external identity provider provisioning workflows.

**[AWS Control Tower AFT now supports plan-only customization runs](https://aws.amazon.com/about-aws/whats-new/2026/09/aws-control-tower-aft/)**
Account Factory for Terraform (AFT) now supports plan-only customization runs, letting administrators preview Terraform changes across managed accounts before applying them. Previously, invoking customizations always triggered a full apply with no preview step, making it difficult to validate expected outcomes.

**[AWS Continuum for Penetration Testing now supports continuous penetration testing integrated directly into your CI/CD pipeline](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-continuum-penetration-testing/)**
AWS Continuum for Penetration Testing (formerly AWS Security Agent) now integrates continuous automated penetration testing into CI/CD pipelines in public preview, shifting security testing left without requiring third-party pentest vendors. This builds on the existing on-demand penetration testing capability, making automated security checks a standard pipeline stage.

**[Amazon EC2 introduces shared tags for Amazon Machine Images](https://aws.amazon.com/about-aws/whats-new/2026/10/ec2-ami-shared-tags)**
EC2 now supports AMI tag sharing: owners prefix any tag key with `ec2:SharedTag/` to make it automatically visible to all accounts the AMI is shared with, whether per-account, across an organization, or publicly. This removes the need to build and maintain custom tag replication workflows.

**[AWS Advanced Ruby Driver Wrapper is generally available](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-ruby-driver-wrapper-available/)**
The AWS Advanced Ruby Driver Wrapper is now generally available for RDS and Aurora PostgreSQL and MySQL-compatible databases. It reduces RDS Blue/Green switchover, Aurora Global database switchover, and failover times, and supports AWS Secrets Manager authentication and IAM token-based authentication.

**[AWS Client VPN now supports device posture assessment](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-client-vpn-device-posture/)**
Client VPN now supports device posture assessment, verifying that connecting devices meet security and compliance requirements before granting network access. The feature integrates with existing device posture providers including CrowdStrike, adding a device trust check on top of existing certificate, SAML, and Active Directory authentication.

**[AWS Batch now supports Amazon EKS access entry authentication](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-batch-access-entries/)**
AWS Batch now supports EKS access entry authentication for compute environments, providing an API-driven alternative to the `aws-auth` ConfigMap for granting IAM principals access to Kubernetes clusters. Configuration uses the `CreateComputeEnvironment` or `UpdateComputeEnvironment` APIs with the `accessEntry` field.

## AI Engineer

**[Harness Engineering: How to Build a Software Factory — Dru Knox, Tessl](https://www.youtube.com/watch?v=X6l4lpA0_NY)**
Dru Knox, head of product and design at Tessl, lays out harness engineering (also called loop engineering) as the discipline that takes a team from using coding agents to operating a software factory — where agents produce what users receive and engineers build and improve the factory itself.

- **Three metrics define a factory.** Knox measures factory maturity by autonomy, automation, and quality — without all three moving together, a team has assisted development, not a factory.
- **Inner, outer, and meta loops structure the work.** Engineering work decomposes into the inner loop (what the agent does per task), the outer loop (how the team iterates on the agent's work), and the meta loop (how the factory improves itself over time).
- **The field changes weekly.** Knox names the pace of change as a primary reason harness engineering is hard — practices that work today can become stale quickly, making the meta loop critical to staying current.
- **Engineers build the factory, not the product.** The structural shift: the engineer's job moves from writing code to specifying, supervising, and improving the system that writes code.

**[Cooking with Codex — Charlie Guo & Gabriel Chua, OpenAI](https://www.youtube.com/watch?v=FwiS44-xyYw)**
Charlie Guo and Gabriel Chua demonstrate Codex's agentic workflow by starting from a Slack conversation and producing a working macOS live translation app in four minutes and two seconds, using the build to show how context, plugins, and supervision compose in practice.

- **Four minutes from conversation to shipping app.** Four minutes and two seconds after receiving a Slack conversation as input, Codex produced a working macOS live translation app — a live German translation confirmed the result.
- **Context + plugins + supervision is the full stack.** The demonstration makes explicit that the conversation supplies the idea, plugins supply development practices, and a human supervisor remains in the loop — none of the three is optional.
- **Repository history is usable context.** A second demonstration turned repository history into a shareable site about the Agents SDK, expanding what counts as meaningful input beyond text prompts.
- **Informal phone-to-code requests work.** One demo requested an IKEA-style repository visualization from a phone, showing the agent accepting casual, informal input and producing structured output.

**[How AI Agents Pay: Checkout in ChatGPT and Google AI Mode — Sam Parsons, PayPal](https://www.youtube.com/watch?v=c5U-XbbEN-g)**
Sam Parsons, senior staff engineer at PayPal working on PayPal Enterprise Payments (formerly Braintree), walks through the emerging payment infrastructure for AI agent commerce — three concrete patterns merchants can implement today to accept payments initiated by AI agents without requiring customers to visit their site.

- **Instant Checkout in ChatGPT uses the Agentic Commerce Protocol.** Merchants build an MCP app that integrates with ChatGPT; the customer checks out within the chat interface without visiting the merchant's site.
- **Google AI Mode uses the Universal Commerce Protocol.** Merchants only stand up an endpoint — no MCP app required — and Google Pay handles the checkout, reducing the merchant integration surface area.
- **The next customer may never visit your site.** Agent-initiated commerce removes the visit entirely, moving the merchant's primary surface from UX to APIs.
- **The framing is from the payment processor layer.** Parsons works on the infrastructure underpinning both patterns, making the account of what is actually happening at the payment layer unusually detailed.

**[Advanced Workshop: Mastering AI Observability — Doug Guthrie, Braintrust](https://www.youtube.com/watch?v=hfEczxdNyvU)**
Doug Guthrie uses a batch of 968 real support traces to show how Braintrust's observability tooling connects to the active work of improving a deployed agent — closing the loop from production failure patterns back to better evaluators.

- **968 traces reveal two concrete failure modes.** Order lookup failures and broken escalation calls surface immediately from the sample batch, giving the workshop grounded diagnosis rather than a hypothetical starting point.
- **Offline baseline before online grading.** The workflow sequence matters: build a Python support agent on the OpenAI Agents SDK, add tracing, establish an offline evaluation baseline, then publish custom scorers.
- **Online automations then grade incoming production traces.** Once scorers are published, incoming traces are graded automatically, turning observability from an incident-response tool into a continuous quality signal.
- **Topics and custom facets are distinct discovery mechanisms.** Topics groups patterns across tasks, sentiment, and workflow issues; a custom facet targeted a specific failure category — discovery and diagnosis are separate stages.

**[How Many Credentials Should Your AI Agent Have? Zero. — Jim Clark, Docker](https://www.youtube.com/watch?v=ZUZVNKFSmTM)**
Jim Clark, principal software engineer at Docker, argues that agent safety is not a property of the harness loop itself but of what flows into it — credentials, context, and tool access — and uses MCP gateways and sandboxes as the architectural answer.

- **The harness is a simple loop; safety lives at the boundary.** Clark's core claim: the loop is not where you enforce safety — the sandbox boundary is, and that is the right abstraction to invest in.
- **Decompose agents by role.** A newsroom example splits agents into researcher, fact-checker, and publisher sandboxes, each with access only to what its specific role requires.
- **Just-in-time credentials reduce exposure.** A coding agent only receives signing keys at commit time, not for the entire session — reducing the credential exposure window to the minimum necessary for each operation.
- **Agents run long enough that supervision stops.** Once agents operate autonomously for extended periods, the credential design question becomes unavoidable: passive oversight is not an answer.

**[What Is an Inference Engine, Anyway? — Charles Frye, Modal](https://www.youtube.com/watch?v=woIYJYd_etI)**
Charles Frye uses a real traffic spike on a museum placard generator to make inference engine internals legible — connecting the symptoms an application developer observes to the SGLang and vLLM machinery running behind the API.

- **Two symptoms indicate two different bottlenecks.** Longer waits for the first token indicate a prefill bottleneck; slower tokens afterward indicate a decode bottleneck — reading the dashboard correctly precedes the fix.
- **Adding replicas relieves the request queue.** In the traffic spike example, additional replicas absorbed the queued requests — a concrete, operationally actionable resolution for the specific bottleneck shown.
- **The inference pipeline is sequential.** A request moves through server IO, tokenization, scheduling, model execution, and detokenization — identifying which stage is saturated determines the right intervention.
- **The scheduler is the control point.** The scheduler controls what reaches the GPU, making it the lever for latency and throughput tradeoffs under load.

**[Your LLM Judge Is a Confident Liar: Building Better Verifiers — Browserbase](https://www.youtube.com/watch?v=xLxhT2ZI7UM)**
Miguel González Fernández, tech lead for Browserbase's agent platform, and Corby Rosset, researcher at Microsoft Research, present research showing that LLM judges bundled with popular web benchmarks are systematically wrong — reporting 74% agent success where a better verifier measured 38%.

- **The gap is not marginal.** Official judge: 74% success. Better verifier: 38% success. A 36-point gap means benchmark progress may not reflect real capability improvement.
- **Training against a broken judge produces better liars.** Optimizing against a confidently wrong judge improves benchmark scores without improving agent behavior — the verifier choice shapes what the training loop actually rewards.
- **Deterministic evals stopped scaling.** As agents improved, deterministic evaluation methods lost discrimination, pushing the field toward learned verifiers for computer-use and web benchmarks.
- **The problem is specific to web and computer-use agents.** The research focuses on the verifier challenge for browser-based agents, where defining and measuring ground truth is harder than in code-execution tasks.

**[From Vibes to Production: Evaluating and Shipping AI Agents That Work 201 — Laurie Voss, Arize AI](https://www.youtube.com/watch?v=F0TNSmbo5hE)**
Laurie Voss demonstrates an improvement loop for a production agent, starting from a concrete failure — a toy store agent unable to filter by price — and using observability, diagnosis, and a coding agent to close the gap.

- **Missing tool features are a root cause class.** The agent failed to find toys under $6 because the search tool had no price filter — the bug was in the tool, not the model or the prompt.
- **Observability must precede diagnosis.** Adding traces via Arize AX to the Wonder Toys application makes the failure path visible before any fix is attempted; the sequence matters.
- **Skills extend the coding agent's reach.** Repository skills helped the coding agent add tracing and query the resulting trace data, making the fix itself agent-assisted within the same workflow.
- **Agents can fail silently.** The diagnosis reaches beyond exceptions to behavioral patterns — agents may appear to operate normally while systematically failing a class of requests.

**[From Raw Documents to AI-Ready Data — Leo Platzer & Jeff Koss](https://www.youtube.com/watch?v=wzWNYDY7toc)**
Jeff Koss and Leo Platzer, co-founder and former CTO of Deasy Labs (acquired by Collibra), use a manufacturer's legal-ops chatbot over 80,000 SharePoint files to show why chatbot POCs stall at scale — and what data preparation pipeline bridges the gap.

- **40 curated files vs. 80,000 real files is the cliff.** A pilot on hand-picked files worked; pointed at the full corpus it fell apart. The gap is data quality, metadata, and structure — not the model.
- **AI-assisted taxonomy and metadata tagging is the intervention.** The demo uses AI to build taxonomies, tag documents with evidence and confidence scores, and detect sensitive data — shifting data prep from manual curation to semi-automated quality control.
- **The problem is data governance, not just AI.** Deasy Labs was acquired by Collibra, positioning the tooling in the data governance space — the POC-to-production gap is a governance failure with an AI surface.
- **Stalled POCs are not model failures.** The explicit framing: the chatbot pilot failed because of data readiness, not model capability — a diagnostic lens that changes where teams invest.

**[From Vibes to Production: Evaluating and Shipping AI Agents That Work 101 — Laurie Voss, Arize AI](https://www.youtube.com/watch?v=qZj7sqmidqA)**
Laurie Voss identifies why a naive LLM correctness judge fails for a financial analysis agent — it graded without the agent's research context — and shows how supplying the right context to the evaluator produces actionable signal.

- **The judge lacked the agent's context.** A correctness judge rejected all 13 reports because it graded from its own knowledge while the agent used live web research — a context mismatch, not a model failure.
- **A faithfulness evaluator with sources produces useful signal.** Supplying collected research sources to a faithfulness evaluator split 13 reports into 6 faithful and 7 unfaithful — a workable result where the correctness judge produced only noise.
- **The evaluator choice defines what the metric means.** The same agent behavior reads as 0% success with a correctness judge and 46% success with a faithfulness evaluator — the measurement instrument shapes the apparent result.
- **OpenTelemetry + OpenInference is the instrumentation stack.** The agent is built with the Claude Agent SDK and instrumented with OTel and OpenInference to send traces to Arize AX — the tool choices are explicit and reproducible.
