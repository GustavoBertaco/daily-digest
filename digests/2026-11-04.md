**[Amazon Connect Customer now supports Model Context Protocol (MCP) tools in flows](https://aws.amazon.com/about-aws/whats-new/2026/10/connect-flows-mcp-tools/)**
Amazon Connect flows can now invoke MCP tools through a new External Tool block, connecting to third-party applications via Amazon Bedrock AgentCore Gateway without writing custom Lambda functions. This allows the same tools used in agentic experiences to be reused directly in contact center flows for data retrieval or action triggers.

**[Amazon Connect Customer now supports Cases and External Tool events in the Wait block](https://aws.amazon.com/about-aws/whats-new/2026/10/connect-wait-block-cases-tool-events/)**
The Connect Wait block now accepts Cases field conditions and External Tool invocation completions as trigger events, alongside existing Lambda responses. Flows can pause until a case field meets a specified condition or an external tool call finishes, reducing unnecessary transfers and enabling more context-aware interactions.

# 🤖 AI & Machine Learning

## AI Engineer

**[Make Your AI Agents Predictable With Graph Engineering - Zachary Blumenfeld, Neo4j](https://www.youtube.com/watch?v=g_NgCLTibiM)**
Zachary Blumenfeld of Neo4j argues that giving agents an explicit graph of logic to follow — rather than unstructured text — makes their behavior predictable, governable, and portable across environments.

- **Graphs impose structure on agent decision logic, not just data.** Graph engineering applies an established idea — routing through explicit nodes and edges — specifically to control how agents sequence decisions, addressing unpredictability at the architectural level.
- **Three distinct graph types serve separate roles.** Blumenfeld distinguishes multiple graph types covering skills, decision history, and knowledge, each serving a different aspect of agent reasoning and control.
- **Past decision traces compile into reusable skill graphs.** Recording prior agent decisions and compiling them into graph-shaped skills makes past behavior reproducible and auditable after the fact.
- **Predictability, governance, and portability are the three named payoffs.** Agents following a graph can be audited (governance), reliably reproduced (predictability), and migrated between platforms without retraining (portability) — three distinct enterprise concerns addressed by one structural choice.
- **A loan-approval demo grounds the approach in a regulated domain.** Blumenfeld demos the technique on a loan-approval agent, a context where unpredictable behavior carries direct compliance risk.

**[Your AI Agents Shouldn't Care Where They Run - Nikhil Harithas, Factory](https://www.youtube.com/watch?v=XIHZpZtYCzo)**
Factory rebuilt its coding agent, Droid, to run entirely within a customer's own cloud — addressing the hard requirement from banks and heavily regulated enterprises that agents cannot execute on third-party machines or borrow user credentials.

- **The identity and compute assumption breaks in regulated industries.** Agents running on vendor infrastructure using the user's credentials are not viable for financial services and similar sectors — the deployment model has to change, not the customer's requirements.
- **A compute gateway and relay decouple agent execution from the host platform.** Factory's gateway routes Droid's execution into the customer's cloud; the relay handles communication back, enabling bring-your-own-compute without rewriting the agent.
- **Bring-your-own-key model calls keep all data inside the customer's perimeter.** LLM API keys stay with the customer so model requests never transit Factory's infrastructure.
- **Snapshots and forking support reproducibility and recovery.** Capturing execution state as snapshots allows the agent to fork, retry, or resume without losing context — important for long-running coding tasks.
- **Open-sourcing the portability layer signals a broader ecosystem intent.** Factory plans to release the compute abstraction layer as open source, allowing other agent builders to adopt the same host-agnostic pattern.

**[Better Search Took This AI Agent From 36% to 98% Accuracy - Aamir Shakir, Mixedbread](https://www.youtube.com/watch?v=3Ad73Onx3Aw)**
Aamir Shakir of Mixedbread argues that retrieval quality, not model capability, is the primary bottleneck limiting agent accuracy — and that the conventional OCR-chunk-embed-vector-search pipeline systematically loses information before the model ever sees the data.

- **The standard retrieval stack destroys information at every step.** OCR, chunking, text embedding, and vector search each introduce lossy transformations, leaving agents with degraded inputs regardless of model quality downstream.
- **Multimodal, late-interaction retrieval preserves structure the standard stack discards.** Processing documents in their native visual format and scoring relevance at the token level rather than the embedding level captures tables, layouts, and figures that chunked text misses.
- **A customer's answer accuracy went from 36% to 98% after switching their search approach.**
- **Intel earnings reports ground the problem in a dense, mixed-layout document type.** Financial documents with heavy tables and visual structure expose the limits of text-only embeddings in a concrete, recognizable context.

**[You Can't Tell What's Real Anymore. Here's What Comes Next - Cristóbal Valenzuela, Runway](https://www.youtube.com/watch?v=q4ITwvlFplQ)**
Runway co-founder and CEO Cristóbal Valenzuela traces video generation from 128×128-pixel experiments in 2019 to footage indistinguishable from reality today, then argues that next-frame prediction at scale trains models to internalize how the physical world works — with applications reaching well beyond filmmaking.

- **Next-frame prediction is implicitly a physics and world-model curriculum.** Training a model to predict the next video frame forces it to learn object permanence, causality, and physical dynamics — capabilities that generalize beyond video generation.
- **Real-time, interactive generation defines a new interface layer.** When generation runs fast enough to be interactive, the model becomes an interface: anything on screen can become a live, editable simulation rather than a static artifact.
- **Continuum is an early research prototype for screen-to-interactive-video.** Runway's Continuum prototype lets any on-screen content become a live, interactive video — a concrete early signal of the world-interface model direction.
- **Robotics is a downstream beneficiary of world models.** Models that learn video dynamics can serve as simulators or world priors for robotic systems, connecting media generation research to embodied AI.
- **Seven years of compounding progress is the frame.** The arc from 128×128 pixels in 2019 to imperceptible-from-real video in 2026 sets the pace context for where the next seven years could lead.

**[Your Company Should Train Its Own AI Models - Will Brown, Prime Intellect](https://www.youtube.com/watch?v=5SRjPT2Eo7A)**
Will Brown of Prime Intellect argues that companies using generic foundation models are missing the compounding value sitting in their own operational traces, feedback, and workflows — data that could produce models retaining and applying institutional knowledge across sessions.

- **Session amnesia is a data problem, not a model capability problem.** Agents restart blank because companies never capture institutional knowledge in a persistent, trainable form — the fix is a continuous training loop, not a larger base model.
- **Evals function as test cases for decision models.** Business logic and decision outcomes are formalized as evals structured like software regression tests — reproducible, versioned, and grounded in actual company workflows.
- **Widget-style interfaces convert daily decisions into training signal passively.** Small UI surfaces that capture routine choices accumulate labeled training data as a byproduct of normal work, eliminating a dedicated annotation pipeline.
- **Nightly training runs make the model a living record of company knowledge.** Continuous training rather than a one-time fine-tune keeps the model current as workflows and decisions evolve over time.
- **$300K is Brown's cost anchor for a custom model.** An example model trained for approximately $300,000 provides a rough order-of-magnitude reference for teams evaluating whether to build rather than rely on a third-party model.
