**[Distributed databases with Peter Mattis](https://www.youtube.com/watch?v=0GzwuYGvKA4)**
Peter Mattis — co-founder and CTO of Cockroach Labs, original creator of GIMP, and former engineer on Gmail and distributed storage at Google — reflects on a career spanning open source, hyperscaler infrastructure, and founding a database company, while examining why a veteran who shipped roughly 100K lines of database-grade production code per year pre-AI feels even more productive today without any drop in quality.

- **The pre-AI baseline is unusually high.** Mattis regularly shipped approximately 100K lines of database-grade code to production each year before AI tools existed. That benchmark makes his claim of increased productivity with AI substantive rather than casual — he is not a low-output engineer discovering a marginal speedup.
- **Breadth of systems experience is the thread.** GIMP to Gmail to Google's distributed storage to CockroachDB is an unusual range. The episode draws on how exposure to correctness-critical systems at very different scales informs architectural thinking.
- **Keeping systems fast, reliable, and correct simultaneously is the central tension.** The episode explicitly frames this as the core problem the conversation explores — the distributed-systems triangle that forces hard tradeoffs at every layer.
- **AI as amplification, not substitution.** The framing — "even more productive today, with no drop in quality" — positions AI tools as multiplying existing engineering rigor rather than replacing judgment. The productivity gain is on top of, not instead of, the craft.

## AWS What's New

**[Amazon WorkSpaces Core Managed Instances adds support for NVIDIA Blackwell GPU](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-workspaces-cmi-g7/)**
WorkSpaces Core Managed Instances adds Graphics G7 instances powered by NVIDIA RTX PRO 4500 Blackwell Server Edition GPUs and Intel Xeon 6 processors, delivering up to 2.1x better performance for graphics-intensive workloads compared to previous-generation G6. Target workloads include CAD/CAM, 3D rendering, scientific visualization, video editing, and AI-assisted design.

**[AWS CLI now supports bulk skill updates and version checks for the Agent Toolkit for AWS](https://aws.amazon.com/about-aws/whats-new/2026/09/aws-cli-agent-toolkit-update-skill/)**
Two new CLI commands extend the Agent Toolkit for AWS: `aws agent-toolkit check-skill-updates` compares all installed skills against the latest registry versions, and `aws agent-toolkit update-skill --all` updates every outdated skill in a single command. The Agent Toolkit includes the AWS MCP Server, which provides secure agent access to AWS services.

**[Amazon S3 Vectors introduces metadata pre-filtering for up to 5x higher recall on filtered search](https://aws.amazon.com/about-aws/whats-new/2026/09/s3-vectors-introduces-metadata-pre-filtering/)**
S3 Vectors now evaluates metadata filters before running similarity search rather than after, returning up to 5x more matching vectors when filters are selective. A new `$startsWith` prefix-match operator supports filtering on paths, URLs, and similar hierarchical values. The improvement directly benefits RAG, agentic, and semantic-search pipelines that filter on attributes like tenant, category, or time.

**[Amazon Managed Grafana now supports creating Grafana 13.2 workspaces](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-managed-grafana-now-supports-creating-grafana-13-2-workspaces)**
Amazon Managed Grafana supports new workspaces on Grafana 13.2, incorporating features from versions 13.0 through 13.2. Notable additions include Git Sync for version-controlled dashboards, dynamic dashboards, and PromQL query support in the CloudWatch data source plugin. Git Sync allows a workspace to be linked to a Git repository, enabling tracking, reviewing, and reverting dashboard changes as code.

**[OpenAI GPT-6 Astra now supports UltraFast mode on Amazon Bedrock](https://aws.amazon.com/about-aws/whats-new/2026/09/openai-gpt-6-astra-ultrafast-on-amazon-bedrock/)**
UltraFast is a premium speed tier for GPT-6 Astra on Amazon Bedrock delivering up to 6x faster inference and up to 300 tokens per second, according to OpenAI. It is targeted at latency-sensitive production workloads where throughput speed is the primary constraint.

**[AWS Parallel Computing Service now supports scaling logs](https://aws.amazon.com/about-aws/whats-new/2026/09/aws-pcs-scaling-logs/)**
AWS PCS adds scaling logs that record each state transition per compute node — instance launches, node registrations, scale-downs, and launch failures with their reasons. The logs are designed to answer questions like why a node group failed to reach its target size or which launches failed for capacity reasons, making HPC cluster scaling issues easier to diagnose.

**[Amazon Aurora serverless now scales faster to support agentic AI and other bursty workloads](https://aws.amazon.com/about-aws/whats-new/2026/08/aurora-serverless-instant-16-acu-scaling/)**
Aurora Serverless can now add up to 16 ACUs to current capacity within a second and continue scaling up to 256 ACUs as the workload grows, then scale back to zero when idle. The announcement specifically calls out agentic AI applications — which generate bursts of activity followed by long idle periods — as a primary target use case.

**[Amazon Aurora and RDS now support AMD-based R8a instances](https://aws.amazon.com/about-aws/whats-new/2026/09/aurora-rds-amd-r8a/)**
Aurora and RDS add R8a database instances powered by 5th-generation AMD EPYC processors on the AWS Nitro System, with each vCPU mapping to a physical CPU core for consistent per-core performance. High I/O workloads benefit from up to 75 Gbps of network bandwidth and 60 Gbps of Amazon EBS bandwidth.

**[Amazon RDS now supports AMD-based M8a instances](https://aws.amazon.com/about-aws/whats-new/2026/09/aurora-rds-amd-m8a/)**
Amazon RDS for PostgreSQL, MySQL, and MariaDB adds M8a instances powered by 5th-generation AMD EPYC processors, with each vCPU corresponding to a physical CPU core. Like R8a, M8a instances offer up to 75 Gbps network bandwidth and 60 Gbps EBS bandwidth and are built on the Nitro System.

**[Amazon Bedrock expands Claude models in-region support in the UK (London)](https://aws.amazon.com/about-aws/whats-new/2026/09/claude-region-expansion-lhr/)**
Amazon Bedrock now supports in-region inference for Anthropic's Claude Opus 5.5 and Claude Sonnet 5 in the UK (London, eu-west-2) region. The expansion targets financial services, healthcare, and public-sector customers that require data to remain within the United Kingdom.

## AWS Blog

**[Amazon S3 Tables now support all Apache Iceberg V3 data types](https://aws.amazon.com/blogs/aws/amazon-s3-tables-now-support-all-apache-iceberg-v3-data-types/)**
S3 Tables now supports all data types in the Apache Iceberg V3 specification, allowing tables to be created as V3 or upgraded from V2. V3 additions include deletion vectors, row lineage, and new types such as variant, nanosecond timestamps, geometry, and geography.

**[Amazon S3 Vectors now supports metadata pre-filtering for higher recall on filtered searches](https://aws.amazon.com/blogs/aws/amazon-s3-vectors-now-supports-metadata-pre-filtering-for-higher-recall-on-filtered-searches/)**
The AWS Blog provides additional implementation detail on the S3 Vectors pre-filtering launch: each vector can carry up to 2 KB of filterable metadata, a single query supports up to 100 filter constraints, and the feature carries no additional cost and requires no re-indexing of existing vectors.

**[Amazon Aurora PostgreSQL now supports direct querying of Apache Iceberg and Parquet data in your data lake](https://aws.amazon.com/blogs/aws/amazon-aurora-postgresql-now-supports-direct-querying-of-apache-iceberg-and-parquet-data-in-your-data-lake/)**
Aurora PostgreSQL can now query data stored in Apache Iceberg and Apache Parquet formats in a data lake directly alongside operational data, using existing PostgreSQL applications and tools. The capability eliminates the need to ETL structured data from the data lake into the operational database, reducing complexity in applications that span both stores.
