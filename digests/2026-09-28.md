# 🤖 AI & Machine Learning

## AI Engineer

**[I Turned Coding Agents Into a Strategy Game — Ido Salomon, AgentCraft](https://www.youtube.com/watch?v=YIVkERhy8xo)**
The bottleneck to deploying an army of coding agents is not capability — it is the cognitive load of steering, directing, and reviewing them at scale. Ido Salomon, creator of AgentCraft and MCP-UI, argues the skills already exist in the population: we learned them from real-time strategy games, and demos AgentCraft, an orchestrator modeled after that genre.

- **Steering agents at scale is exhausting and underaddressed.** Salomon frames the core problem as human bandwidth: even highly capable agents are bottlenecked by how many a person can meaningfully supervise at once.
- **RTS games solved a similar coordination problem.** Skills from Warcraft and StarCraft — unit prioritization, map awareness, resource allocation under pressure — map directly onto agent orchestration challenges.
- **Agents rendered as units on a spatial map.** In AgentCraft, agents appear as units, the file system becomes the terrain, and heat maps surface where work is concentrated — translating abstract agent state into an interface humans have already trained themselves to read.
- **The metaphor is also a design constraint.** Framing agents as a strategy game forces the interface to make priorities, positions, and bottlenecks visible — a discipline that purely programmatic orchestrators often skip.

**[How Software Factories Improve Themselves — Suraj Gupta, Warp](https://www.youtube.com/watch?v=TN3mj92oZ8I)**
Building a software factory is the well-covered problem; making the factory itself get better over time is not. Suraj Gupta, who leads harness development at Warp, shows three concrete mechanisms from Warp's own open-source factory, each keeping humans in the review loop.

- **The factory meta-problem is distinct from the factory problem.** Improving what a factory produces is the standard framing; improving the factory's own processes requires different instrumentation and feedback loops.
- **Skills that update themselves via an outer-loop agent.** The first mechanism is an outer-loop agent that watches the triage agent's runs and feedback, then opens a PR to update the skill — change tracked in Git, reviewed by a human before it ships.
- **Human review is a deliberate architectural choice.** Even in a self-improving system, the feedback cycle is automated but human-gated: every update to a skill goes through a PR before it affects production behavior.
- **Warp's factory is open-source.** The demos are from a real, publicly available factory — making the claimed mechanisms reproducible rather than illustrative.

**[We Let Claude Code and Codex Race Human Researchers — Elie Bakouch, Prime Intellect](https://www.youtube.com/watch?v=oVsEddfhdxc)**
Big labs claim recursive self-improvement is within reach, but no independent benchmark existed to test that claim. Elie Bakouch, Research Engineer at Prime Intellect and creator of Hugging Face's SmolLM, ran Claude Code and Codex against human researchers on the community's Optimizer Speedrun — a race to train a GPT-2-level model in the fewest steps — and both agents beat the human record.

- **Both agents beat the community human speedrun record.** The result provides independent evidence — from a community-owned benchmark, not a lab's internal eval — that agents can outperform researchers on constrained optimization tasks.
- **The two agents took markedly different approaches.** Both beat the human record but exhibited distinct behavioral patterns throughout the run; Claude Code's pattern is the documented case.
- **Claude Code was episodically defeatist.** It stopped every nine or ten hours to declare the record couldn't be beaten — a significant failure mode for long-horizon tasks that is distinct from capability limits.
- **Community-owned benchmarks carry different credibility.** The Optimizer Speedrun is not designed or hosted by the labs whose agents were tested, which makes the result harder to dismiss as a curated showcase.

**[Beating RL With Reflection: GEPA and Optimize Anything — Lakshya A. Agrawal, GEPA](https://www.youtube.com/watch?v=OA-Mc60Rboo)**
GEPA — a prompt optimization method built on reflection over full reasoning traces — doubled the gains that the RL algorithm GRPO achieved after 25,000 rollouts, using just three examples and one round of reflection. Lakshya A. Agrawal, PhD student at UC Berkeley's Sky Computing Lab and GEPA's creator, explains why discarding the trace is RL's core structural weakness.

- **One reflection round on three examples vs. 25,000 RL rollouts.** GEPA doubled GRPO's gains with a fraction of the sample cost — a fundamental sample-efficiency advantage, not just a speed tradeoff.
- **RL throws away the reasoning trace.** RL collapses a full rollout to a single reward score, discarding chains of thought, tool calls, and error messages. GEPA reads the complete trace and uses it to write a better prompt.
- **GEPA updates prompts, not weights.** The method stays entirely in the prompt layer: the model reads its own trace and generates an improved prompt, keeping the optimization loop lightweight and interpretable.
- **A Pareto pool prevents premature convergence.** GEPA maintains a population of candidate prompts and uses Pareto selection to keep the search from collapsing into a local optimum.
- **The method is presented as domain-general.** The system is named "Optimize Anything," indicating the reflection-based loop is claimed to generalize across problem domains beyond its original benchmark.

**[Long-Horizon Agents Need Experiments, Not Just Prompts — Erina Karati](https://www.youtube.com/watch?v=x4e5O9zN0TE)**
Project Paradox is a framework for game agents with persistent memory, emotions, and trust scores — and it exposed a pattern: agents that perform well in short scenes break down over long horizons in ways that better prompts alone cannot fix. Erina Karati, formerly at Microsoft and Supercell, argues the fix is to wrap agent behavior in structured experiments.

- **Short-scene success does not generalize to long horizons.** The framework worked well in isolated short interactions but degraded predictably once agents had to maintain coherent state over extended timelines.
- **Rumor propagation is a concrete failure signal.** In the test village, a rumor about a mango sale degraded over a few hops: agents forgot who said it, or began treating probabilistic language ("might") as fact.
- **Persistent state — memory, emotions, trust — amplifies errors.** When agents carry inter-session state, errors in that state accumulate rather than reset, turning small inaccuracies into compounding inconsistencies over long horizons.
- **The fix was experimental structure, not prompt iteration.** Karati's solution was to wrap the village simulation in a systematic experimental loop — testing behavioral changes under controlled conditions rather than chasing failures with prompt edits.

**[How We Built an Agent That Improves Itself — Zubin Aysola, Weights & Biases](https://www.youtube.com/watch?v=XyV6bSMyq-I)**
Weights & Biases' ARIA agent closes the loop on its own quality: it takes a production trace, turns it into an offline eval task, identifies the bug, writes a fix, and benchmarks the new version against production — all demonstrated live. Zubin Aysola, Senior Software Engineer on Weave, shows that the hard part is not the agent's ability to write code; it is keeping the measurement infrastructure trustworthy.

- **The self-improvement loop in four steps.** ARIA takes a production trace → converts it to an offline eval task → finds the bug (e.g., a missing SDK call) → writes a fix and benchmarks the new version against the production baseline.
- **Measurement must be airtight because benchmarks, evals, and agent configs change together.** The core engineering challenge is keeping these three in sync; a mismatch anywhere breaks the validity of the self-improvement signal.
- **Byte-for-byte parity between production and research agents.** The team maintains binary-level identity between the two to ensure evaluation results transfer directly to production — no version drift between what is tested and what ships.
- **The eval infrastructure is the constraint, not the agent capability.** The snippet consistently frames reliable self-improvement as a measurement problem first and a code-generation problem second.

**[Autoresearch Made Our Models 3x Faster — Tejas Bhakta, Morph](https://www.youtube.com/watch?v=vrDvatGtIxs)**
GPU kernels are a near-perfect autoresearch target: correctness is verifiable and speed is directly measurable. Tejas Bhakta, founder of Morph and former inference optimization engineer at Tesla, combined agent-written custom kernels with bare-metal hardware tuning to achieve 3x model speedups on cheaper GPUs.

- **3x speedup on cheaper hardware.** Agent-written kernels combined with bare-metal hardware tweaks tripled model speed while moving to less expensive GPUs — cost and performance improved together.
- **GPU kernels suit autoresearch because both evaluation axes are cheap.** Correctness is deterministic and latency is directly measurable; the agent can close the feedback loop without human judgment on either dimension.
- **Humans set the direction; agents do the parameter tuning.** Bhakta's explicit rule: agents excel at picking block sizes and numerical parameters but are poor at the architectural insight — the big idea that opens a new optimization path. That stays with humans.
- **Bare-metal hardware tuning contributed meaningfully.** Software kernel optimization alone did not account for the full speedup; hardware-level configuration was a distinct and necessary input.

**[An AI Research Agent That Runs Your Experiments — Tim Sweeney, Weights & Biases](https://www.youtube.com/watch?v=hd7TOvmyAxU)**
ARIA, Weights & Biases' autoresearch agent, is shown live on stage launching actual GPU training jobs on Karpathy's autoresearch project and nearly beating its own best result before the talk ends. Tim Sweeney, Principal Engineer at Weights & Biases by CoreWeave, demonstrates the full W&B integration: job launch, monitoring, cross-run pattern finding, and automated reporting.

- **Live demo on real GPU hardware.** ARIA kicked off autoresearch experiments during the talk, running on real GPUs, and approached its own best result before the session concluded — not a recorded or synthetic demo.
- **Cross-experiment intelligence at scale.** ARIA finds patterns across 200+ experiments — a volume of search that is impractical for a human analyst to cover manually.
- **Full integration with the existing W&B workflow.** The agent launches and monitors training jobs, summarizes best runs, and generates reports and dashboards inside W&B — extending the platform rather than running alongside it.
- **Available on the W&B iOS app.** The agent is now on mobile, extending the experiment management loop beyond the desktop environment.

**[The Loop Is the Product — Roland Gavrilescu, Introspection](https://www.youtube.com/watch?v=7taOQBfjDyE)**
The first viral agent loop was commercial, not technical: someone using OpenClaw to pit car dealers against each other for a better price. Roland Gavrilescu, co-founder and CEO of Introspection and formerly at xAI, lays out a blueprint for autoresearch in 2026, with the loop architecture — not any individual output — as its core competitive artifact.

- **The loop is the product.** Agent success depends on the quality of its signals and verifiers; each loop's output feeds the next, making the loop architecture itself the durable competitive advantage rather than any single result.
- **System distillation is the moat.** The second property is that every loop execution distills knowledge back into the system — making the system progressively smarter over time rather than producing one-off outputs.
- **The car-dealer example grounds the pattern outside software.** OpenClaw's negotiation loop shows the blueprint applies wherever there are adversarial or iterative optimization targets — not only to code generation or ML research.
