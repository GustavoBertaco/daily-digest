Z.ai's GLM-5.2 FP8, NVIDIA's Nemotron-Nano-12B-v2, and Z.ai's GLM-OCR are now available on SageMaker JumpStart, covering long-horizon agentic engineering, efficient hybrid reasoning, and advanced document understanding respectively.

**[Amazon GameLift Streams Now Offers Service-managed Shader Caching](https://aws.amazon.com/about-aws/whats-new/2026/08/Amazon-GameLift-Streams-Shader-Caching/)**
Amazon GameLift Streams now manages shader cache capture and distribution automatically, with no application changes required. Designating a session for capture causes the service to make the resulting cache available for future sessions across all streaming locations, reducing loading times and visual stuttering.

**[Amazon EC2 introduces application status checks](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-ec2-application-status-checks)**
Amazon EC2 now offers application status checks that detect application-level failures — including a stopped web server, a non-running Docker daemon, an incorrect networking configuration, or a network interface no longer passing traffic. The feature extends existing instance-level status checks into the application layer.

**[Amazon OpenSearch Serverless now supports up to 10,000 collections per collection group](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-opensearch-serverless-supports-10000-collections-per-collection-group/)**
Amazon OpenSearch Serverless has raised the collection limit per collection group from 1,500 to 10,000. Collection groups allow multiple collections to share OpenSearch Compute Units (OCUs) even across different AWS KMS keys, making large-scale consolidation substantially more practical.

**[AWS Elastic Disaster Recovery now preserves UEFI boot mode for Linux servers](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-drs-linux-uefi)**
AWS Elastic Disaster Recovery now preserves UEFI boot mode when recovering Linux source servers, closing a gap where recovered instances previously launched in legacy BIOS mode. Recovered instances now match the source environment's boot firmware, eliminating manual post-recovery configuration for applications that depend on UEFI boot behavior.

## AI Engineer

**[Agents, codebases, and teams — Aditya Khandelwal, Amazon AGI Lab](https://www.youtube.com/watch?v=aeTb5BdmTTc)**
Aditya Khandelwal, drawing on leading a team of ten through agent adoption, argues that the problem is a leadership one — because the changes that actually work cannot be made by individual contributors acting alone.

- **Unmanaged adoption widens the gap it was meant to close.** When adoption is left to individuals, the early adopter shipping ten PRs a day creates unsustainable review pressure on the colleague still shipping two. The non-adopter falls further behind, reads worse code, and concludes agents are the problem — not the adoption pattern.
- **The fixes require authority to implement.** Restructuring a codebase for progressive disclosure — so agents can navigate it without requiring full context — is an architectural decision one engineer cannot make unilaterally. Converging on a shared approach is equally a leadership call.
- **Adoption is a team-level state, not an individual one.** When individuals drive adoption independently, the resulting review pressure and code degradation cause non-adopters to conclude agents are the problem — making it a team-level failure that individual contributors cannot fix alone.

**[Taking Reinforcement Learning Cross Datacenter — Nan Jiang, Modal](https://www.youtube.com/watch?v=maRzp4kImJ4)**
Nan Jiang presents a method for making cross-datacenter RL practical by collapsing the data volume shipped between training and rollout from a full 500 GB checkpoint down to roughly 500 MB, while preserving bitwise-identical weights on the receiving end.

- **Fewer than 1% of rollout-visible weights change per training step.** The high compressibility of version deltas is not because gradients are sparse — gradients are dense, reaching approximately 99% of parameters — but because the parameter-space displacement of a single training step is small relative to total model size.
- **Delta shipping replaces full checkpoint transfers.** Sending only the changed weight slice lets a rollout fleet in another region absorb a new model version in seconds rather than the minutes-to-hours a 500 GB transfer would require.
- **Bitwise-identical reconstruction is the critical correctness property.** The rollout fleet reconstructs the exact same weights as the training cluster, so there is no behavioral divergence between training-side and rollout-side evaluation.

**[Codex, Behind the Harness — Dominik Kundel, OpenAI](https://www.youtube.com/watch?v=shRR1e2HXMk)**
Dominik Kundel shows how OpenAI's Codex harness evolved once inference ceased to be the bottleneck — once GPT 5.3 Codex Spark reached 1,000 tokens per second on Cerebras, the binding constraint shifted to the network and context design.

- **WebSocket mode replaced server-sent events.** A persistent connection means each turn returns only the tool call result rather than replaying the full accumulated context over HTTP — a direct response to the inference-is-cheap, network-is-the-bottleneck reality.
- **Context construction balances three competing pressures simultaneously.** Size, flexibility, and cacheability pull against each other; the harness makes explicit trade-offs among all three rather than optimizing any single one.
- **Deferred tools stay out of context until actually needed.** Marking a tool deferred excludes it from the active context window entirely, preserving cache hits and reducing token pressure — a mechanism that only matters once per-token generation cost is low enough that context size, not generation latency, dominates.
