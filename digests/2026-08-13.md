## AWS What's New

**[Amazon EC2 R8a instances are now available in Canada (Central) region](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-ec2-r8a-instances-canada-central/)**
Amazon EC2 R8a instances — powered by 5th Gen AMD EPYC (Turin) processors with up to 4.5 GHz max frequency — are now available in Canada (Central). They deliver up to 30% higher performance and up to 19% better price-performance than R7a, with 45% more memory bandwidth, making them suited for latency-sensitive workloads.

**[Amazon Bedrock expands IAM principal cost allocation to the bedrock-mantle endpoint](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-bedrock-expands-iam-principal-cost-allocation-bedrock-mantle/)**
Amazon Bedrock now attributes inference costs by IAM principal — users and roles — for requests through the bedrock-mantle endpoint, extending a capability previously available only on the bedrock-runtime endpoint. This makes per-team or per-role cost visibility consistent across both endpoints.

**[LocateAnything-3B, Qwen-AgentWorld-35B-A3B, and Qwen3.5-122B-A10B models now available on Amazon SageMaker JumpStart](https://aws.amazon.com/about-aws/whats-new/2026/01/locateAnything-3B-qwen-agentworld-35B-A3B-qwen3.5-122B-A10B-on-sagemaker-jumpstart/)**
Three foundation models are now available on SageMaker JumpStart: NVIDIA's LocateAnything-3B (visual grounding), Qwen's Qwen-AgentWorld-35B-A3B (agent environment simulation), and Qwen's Qwen3.5-122B-A10B (large-scale multimodal reasoning). Each covers a distinct enterprise AI capability on AWS infrastructure.

**[NVIDIA Nemotron 3.5 Lightning model is now available on Amazon SageMaker JumpStart](https://aws.amazon.com/about-aws/whats-new/2026/01/nvidia-nemotron-3.5-lightning-on-sagemaker-jumpstart/)**
NVIDIA Nemotron 3.5 Lightning, a hybrid Mixture-of-Experts model with 30B total parameters, is now on SageMaker JumpStart. It targets persistent agent workloads and high-throughput enterprise automation across domains including financial document processing, cybersecurity triage, and telecom operations.

**[AWS Glue adds one-click access to SageMaker Unified Studio from the AWS console](https://aws.amazon.com/about-aws/whats-new/2026/08/smus-glue-access)**
AWS Glue now includes a single-click path to Amazon SageMaker Unified Studio, letting data engineers move directly from viewing the Glue catalog into querying data, running data quality checks, and building pipelines — without navigating separately to SageMaker.

**[AWS Secrets Manager adds managed external secrets support for Jenkins and SonarQube](https://aws.amazon.com/about-aws/whats-new/2026/08/secrets-manager-integration-jenkins-sonarqube/)**
AWS Secrets Manager now auto-rotates Jenkins API tokens and SonarQube tokens as managed external secrets, requiring no custom rotation code. For Jenkins specifically, the service mints a replacement token and revokes the old one only after confirming the new token is active, avoiding CI/CD disruption.

**[Amazon Connect Customer launches performance dashboard for Cases](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-connect-cases-dashboard/)**
Amazon Connect now provides a performance dashboard for cases, giving managers current and prior-period visibility into case volume, average resolution time, first-contact resolution rate, and SLA achievement. Results are filterable by case template, assigned user, or assigned queue.

**[AWS Clean Rooms supports exporting privacy-enhanced analysis logs for SQL](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-clean-rooms-export-analysis-log-sql)**
AWS Clean Rooms can now export privacy-enhanced analysis logs for SQL queries to an S3 bucket, exposing Spark execution details for optimization and troubleshooting. Collaboration owners control which members are permitted to export logs.

**[Amazon RDS for MariaDB now supports MariaDB 12.3](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-rds-mariadb-1232-available/)**
Amazon RDS now supports MariaDB 12.3.2, the latest LTS release. Key additions include Oracle TO_DATE() compatibility to reduce migration friction, a native IS JSON predicate for in-database JSON validation, and query optimizer improvements.

## AI Engineer

**[Evolution of agentic surfaces — Gagan Bhat & Isabella Kai He, Anthropic](https://www.youtube.com/watch?v=K0X9QDRkIdg)**
Gagan Bhat and Isabella Kai He of Anthropic's Applied AI team use a live case study to argue that agent harnesses are fragile to model upgrades — not because models regress, but because harnesses encode behavioral assumptions that silently break when those assumptions no longer hold.

- **Context anxiety was a Sonnet 4.5-specific behavior.** Approaching its context window limit, Sonnet 4.5 would wrap work up early and stop with room to spare — a pattern the Applied AI team named "context anxiety."
- **The workaround became the liability.** The team built context resets into the harness to compensate; when Opus 4.5 shipped without context anxiety, those resets added pure latency and discarded cache that the model should have kept.
- **The principle: a harness encodes model assumptions.** The core lesson Bhat and He frame the session around is that a harness written for one model's behavior becomes overhead — or worse, a regression — when the model changes.
- **Silent breakage is the real risk.** A model upgrade that removes an unwanted behavior can simultaneously degrade a production harness tuned to work around it, with no error thrown — just added overhead and lost efficiency.
