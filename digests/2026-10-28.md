**[Amazon WorkSpaces Core Managed Instances now supports ModifyVolume API](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-workspaces-cmi-modifyvolume/)**
WorkSpaces Core Managed Instances now support in-place volume changes — size up to 16,384 GiB, type, IOPS, or throughput — without detaching or restarting. Previously, any storage or performance change required rebuilding the instance from scratch.

**[Amazon SageMaker Unified Studio adds light mode support for IDC-based domains](https://aws.amazon.com/about-aws/whats-new/2026/10/smus-light-mode)**
SageMaker Unified Studio now offers a light mode theme for Identity Center (IDC)-based domains, joining the already-supported IAM-based domains. Users can switch between dark and light themes to match their preference and working environment.

**[Amazon Connect Customer expands testing and simulation to validate flow action outcomes](https://aws.amazon.com/about-aws/whats-new/2026/10/connect-customer-validate-flow-actions/)**
Amazon Connect now lets you verify the data returned by flow actions — Lambda responses, Lex resolved intents, Agentic CX variables — during testing and simulation, not just confirm that an action started. When a test fails, you can pinpoint the exact action with an unexpected result rather than tracing back from a downstream step.

**[Amazon Connect Customer now lets you view metrics by customer lifetime value and repeat-caller status](https://aws.amazon.com/about-aws/whats-new/2026/10/connect-customer-boma-segment/)**
Amazon Connect now segments contact-center metrics by customer lifetime value (LTV) and repeat-caller status, surfacing how KPIs differ for high-value or repeat contacts before issues show up in aggregates. Where a segment underperforms, you can route those customers to stronger agents or adjust the knowledge bases and self-service flows they hit.

## AI Engineer

**[What a $900M Bank Error Teaches Us About AI Agents - John Feminella, Two Sigma](https://www.youtube.com/watch?v=iniryju23Sk)**
In 2020, Citibank sent $900 million to Revlon's lenders even though the procedure, the warning pop-up, and all three approvers did exactly what they were supposed to — the system had no composable safeguards. Two Sigma's John Feminella uses this case to show how to give AI agents real autonomy without locking everything down.

- **The Citibank failure was structural, not individual.** Every person and step functioned correctly; the gap was in composable controls that could have caught the error at the system level.
- **An agent registry as the first control.** Knowing which agents exist, what they can do, and who owns them is the prerequisite for any governance layer.
- **Risk-based review scales oversight to the action.** Not every agent action warrants the same review overhead; the control scales to the risk level of what the agent is doing.
- **Least-privilege tool access.** Agent permissions should be scoped so agents cannot act beyond their defined mandate.
- **Five composable controls, not a blanket lockdown.** Feminella walks through five specific mechanisms that together enable real autonomy without trading away safety.

**[Why Are We Still Governing AI Agents Like Software? - Tim Tyler, Gravitee](https://www.youtube.com/watch?v=h8jgniNJcbQ)**
Most companies deploy AI agents with no identity, no named manager, and shared credentials — an arrangement no organization would accept for a human employee. Gravitee's Tim Tyler presents the Agent Accountability framework to close this gap.

- **The governance gap is the default.** Agents deployed without IDs, managers, or distinct credentials are ungoverned; the same setup would never be accepted for any human hire.
- **Assignment: establish identity, team, and a named human sponsor.** Every agent gets a unique identity, belongs to a team, and has a named person accountable for its behavior.
- **Alignment: define role, mission, and least-privilege authority.** Agents operate within a scoped mandate rather than with open-ended tool access.
- **Administration: scorecards, guardian agents, and step-by-step recourse.** Ongoing oversight includes scorecards, guardian agents that watch for drift, and a defined process when agents go off course.

**[300 Agents, 60 People: How We Secured Our Own AI Agents - Aiden Sochowski, Runlayer](https://www.youtube.com/watch?v=BgLdvF7Qkh8)**
Runlayer runs more than 300 AI agents every day across a team of about 60 people. When founding engineer Aiden Sochowski added a gateway and logged every session and tool call, a wide range of security and cost problems became visible for the first time.

- **Zero visibility was the first problem.** None of the issues were detectable before the gateway; logging every session and tool call was the prerequisite for finding them.
- **Prompt injection arrived via email.** Agents processing email were susceptible to injection attacks embedded in message content.
- **PR-review agents were manipulated into approvals.** Agents responsible for code review could be talked into approving changes — a high-stakes failure mode.
- **Over-permissioning, cross-contamination, and buggy MCP servers.** One poisoned agent could contaminate others; over-permissioned bots expanded the blast radius; buggy vibe-coded MCP servers burned tokens with no output.
- **A model switch raised costs over 100x in a week.** Swapping underlying models without controls is a fast path to runaway spend; the gateway made it visible.

**[How a Trading Firm Ships New AI Models the Same Day - Noyan Tokgozoglu, Optiver](https://www.youtube.com/watch?v=aGIUg8zKI8A)**
At Optiver, any change reaching traders shows up in P&L within hours — which means AI infrastructure must move fast while remaining measurable. Head of AI Engineering Noyan Tokgozoglu describes how the team built a platform for same-day model adoption without losing cost or quality control.

- **P&L feedback within hours forces infrastructure discipline.** The short feedback loop makes slow or unmeasurable AI deployments immediately costly and visible.
- **An inference gateway handles routing and budgets.** The gateway is the single control plane for directing traffic and enforcing spend limits across models.
- **Same-day frontier model adoption benchmarked on internal golden sets.** New models ship the day they are released — after passing evaluation on Optiver's own test sets, not just vendor benchmarks.
- **A model- and harness-agnostic meta harness.** The evaluation layer works across models and testing frameworks, avoiding lock-in to any single provider.
- **AI spend went out of control after the summer's major model releases.** The gateway provided the visibility needed to bring costs back under control after a period of rapid model churn.

**[Agents That Self Improve While You Sleep - Fuad Ali, Arize AI](https://www.youtube.com/watch?v=UGuNt2_Oz8s)**
Arize AI's Fuad Ali demonstrates a self-improvement loop for AI agents that runs autonomously while keeping humans at the points where their judgment matters most.

- **Trace everything first.** Complete observability is the prerequisite; without traces, there is no raw material for automated improvement.
- **Signal: an always-on agent that reads traces on a schedule.** Signal deduplicates issues from traces and files them automatically, turning passive observability into active issue detection.
- **Failures become evals and living regression datasets.** Each failure is converted into a test case; the dataset grows continuously and tracks regressions over time.
- **Run experiments to prove a fix works before shipping.** Proposed fixes go through experiments against the regression dataset before reaching production.
- **Humans stay at the highest-leverage points.** Eval design, dataset curation, and fix review remain human responsibilities; the loop automates detection and surfacing, not the judgment.

**[How to Test Your Agents on Real Tasks With Harbor - Xander Song, Arize AI](https://www.youtube.com/watch?v=kRJjSOYqW0I)**
Harbor is an open-source framework from Arize AI for evaluating agents on realistic tasks in isolated Docker sandboxes with real data. Engineer Xander Song explains the framework's primitives and shows it in use on a concrete prompt-change experiment.

- **Isolated Docker sandboxes with real data.** Agents run in contained environments against actual data, reducing the gap between eval and production behavior.
- **Core primitives: tasks, verifiers, rewards, trials, and jobs.** These building blocks compose into flexible evaluation pipelines that match the structure of the work the agent actually does.
- **Oracles validate your setup before you spend tokens.** Running an oracle pass first ensures the evaluation environment itself is correct before committing to a full trial run.
- **ATIF trajectories capture agent behavior.** ATIF trajectories record the steps agents take, enabling trajectory-level analysis beyond pass/fail outcomes.
- **A prompt change toward a new SQL tool cut total tool calls.** Running Harbor at scale on Daytona, the team measured a cut in tool calls after a targeted prompt change — a concrete evaluation outcome from a real experiment.
