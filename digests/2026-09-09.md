## NextGenLakehouse

**[Secrets in Unity Catalog](https://www.youtube.com/watch?v=GYIem6iXUxg)**
Unity Catalog extends its governance model to credentials and secrets, treating API keys and tokens as first-class governed objects — subject to the same access controls, audit trails, and lifecycle management applied to tables and volumes.

- **Secrets are catalog-native objects.** The naming pattern `catalog.schema.secret` places credentials inside the Unity Catalog hierarchy, making them subject to the same privilege model used for tables and schemas — no separate secrets store to manage.
- **Access is split across three permission levels.** Read, reference, and write are distinct grants, allowing a service account to be given the minimum privilege it actually needs rather than blanket access.
- **Rotation is decoupled from consumption.** The demo shows rotating a secret via the REST API without touching the notebooks or jobs that consume it, so credential lifecycle is managed independently of workload code.
- **Redaction is built in.** Secret values are automatically redacted from notebook output and Spark job logs, closing a common path for accidental credential exposure.
- **The developer experience is unchanged.** Notebooks continue using `dbutils.secrets.get()` — the governance upgrade is transparent to existing code.
