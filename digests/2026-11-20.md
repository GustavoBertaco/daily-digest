## AWS What's New

**[Amazon Aurora DSQL now supports multi-Region peering across continents](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-dsql-intercontinental-multi-region-clusters/)**
Aurora DSQL can now form multi-Region clusters across different continents — for example, US East (N. Virginia) paired with Europe (Ireland). Applications on both continents read and write to a single strongly consistent database, and if one Region becomes unavailable, committed writes are preserved and operations continue in the remaining Region.

**[AWS Marketplace now supports buyer contact sharing at subscription](https://aws.amazon.com/about-aws/whats-new/2026/11/marketplace-buyer-contact-sharing/)**
When subscribing to a third-party Marketplace product, customers can now optionally share first name, last name, email address, company name, and country or region with the seller. This lets sellers begin onboarding, send deployment guides, and provide technical support from day one of the subscription.

**[AWS Systems Manager Parameter Store raises API throughput limits](https://aws.amazon.com/about-aws/whats-new/2026/11/parameter-store-raises-api-throughput-limits/)**
AWS Systems Manager Parameter Store has raised throughput limits on five API operations for accounts with the higher-throughput setting enabled. GetParametersByPath moves from 100 to 500 TPS, PutParameter from 10 to 50, DeleteParameter from 5 to 50, DescribeParameters from 10 to 100, and GetParameterHistory from 10 to 100.

**[AWS Transform supports optimized storage for server migration](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-transform-optimized-storage/)**
AWS Transform now recommends optimized storage type and configuration for every server in a migration, using each server's observed performance and capacity data to reduce overprovisioning and prevent post-cutover performance issues. Expected cost is shown before migration, and Transform applies the approved settings automatically at launch.

**[AWS Marketplace now supports buyer approval workflows](https://aws.amazon.com/about-aws/whats-new/2026/11/marketplace-buyer-approvals/)**
Buyer approvals are now generally available in AWS Marketplace, letting organizations define policies for which purchases require sign-off based on purchase amount, product type, pricing, and offer type. Approval requests can be routed to the Marketplace console, a chain of email approvers, or external systems.

**[Amazon Connect Customer enables Cases by default for new instances](https://aws.amazon.com/about-aws/whats-new/2026/11/connect-cases-enabled-by-default/)**
New Amazon Connect instances now come with Cases enabled and pre-connected to SLA rules, Customer Profiles, and Amazon EventBridge, so operations teams can begin tracking and resolving customer issues without any setup. Administrators of existing instances can enable the same integrations with one click in the AWS Management Console.

**[AWS Transform automates source and migration target actions to accelerate cutover](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-transform-automates-source-actions/)**
AWS Transform's new source actions capability lets teams define and run actions securely on source servers at the right point in the migration lifecycle, from early preparation through cutover. Post-launch actions complement this by validating servers after they go live on AWS, automating the full migration workflow end to end.

**[Amazon OpenSearch Memory is now generally available](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-memory-generally-available/)**
OpenSearch Memory is a new serverless capability in Amazon OpenSearch Service that gives AI agents persistent memory across sessions. It stores agent interactions as searchable events, derives memories, and retrieves relevant context so agents can recall prior decisions and user preferences without replaying the full conversation history to the model.

**[Introducing the Apache Spark Optimization Agent for AWS Glue ETL](https://aws.amazon.com/about-aws/whats-new/2026/11/apache-spark-aws-glue-etl/)**
AWS Glue ETL's new Apache Spark Optimization Agent analyzes completed Spark job runs and returns cost and performance recommendations within minutes, with specific configuration changes backed by telemetry evidence and reasoning. Users select a cost or performance goal, and the agent is accessible from the Glue console or through the Amazon SageMaker Unified Studio MCP Server.

**[Amazon SageMaker AI now supports cross-Region inference routing](https://aws.amazon.com/about-aws/whats-new/2026/11/sagemaker-cross-region-routing/)**
SageMaker AI's new cross-Region inference routing sends requests to endpoints in other AWS Regions and accounts when a Region runs short of capacity, keeping inference applications available without customer-managed routing logic. Previously, teams had to build and maintain their own health checks, routing, and retry logic across Regions.

## AI Engineer

**[What it takes to set intelligence free — Fabian Hedin, CTO, Lovable](https://www.youtube.com/watch?v=pZWPq_ZAmM4)**
Lovable nearly failed by investing in a sophisticated multi-agent framework before its CTO, Fabian Hedin, identified the real bottleneck: the absence of infrastructure primitives — durable runtimes, recoverable state, and isolated execution — that long-running coding agents actually require to deliver reliable results.

- **Complexity was the trap, not the solution.** The multi-agent framework added orchestration overhead without solving the fundamental reliability problem; simplifying the runtime model was the key shift.
- **Git-inspired histories make agents recoverable.** Forkable computers with version-controlled state let agents backtrack and resume without replaying entire runs from scratch.
- **Sandbox checkpointing with copy-on-write memory.** Agents can now checkpoint mid-run; a failed branch doesn't cost the entire execution, fundamentally changing the cost of iteration.
- **Verification feedback loops close the test-passing gap.** The connection between code generation and product outcomes runs through feedback loops that catch problems the sandbox itself won't surface.
- **A Rust rewrite of Vite was part of the stack.** Performance at the execution layer — not just orchestration — mattered enough to warrant low-level rewrites.

**[Post-Training Gemini 4 for Real Engineering Work — Melvin Johnson, Google DeepMind](https://www.youtube.com/watch?v=fTHByDwTxGM)**
Google DeepMind's Melvin Johnson argues that passing tests does not mean a coding agent solved the problem — Gemini 4's post-training for real engineering work was designed around this gap, using harder tasks, rubric-based grading, and RL-with-anti-reward-hacking measures to push beyond benchmark performance.

- **Test-passing is a proxy, not proof.** The core design premise: binary pass/fail evaluations miss the range of engineering quality and correctness that real work demands.
- **Rubric-based grading enables richer training signal.** Moving beyond pass/fail lets the training reward partial progress and nuanced engineering decisions, not just correct final output.
- **Isolated evaluation environments prevent signal contamination.** Sandboxed eval setups ensure the model is solving problems, not exploiting test infrastructure.
- **Reward hacking is an explicit training hazard.** Reinforcement learning for coding requires deliberate attention to honest model behavior — agents that game the reward signal undermine real-world engineering trustworthiness.
- **Engineer feedback in the loop accelerated releases.** Input from Google's own engineers connected training improvements to faster real-world releases for Gemini 4 Carbon and Hydrogen.
