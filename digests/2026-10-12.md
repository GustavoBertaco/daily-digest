# 🤖 AI & Machine Learning

## AI Engineer

**[Building Self-Learning Loops for Your Agent — Fuad Ali, Arize AI](https://www.youtube.com/watch?v=fnuNVFgLjHA)**
A broken price filter in a shopping assistant becomes the running example for a production observability loop that closes automatically — from trace collection through code investigation to a tested fix — treating telemetry as a feedback driver rather than a passive dashboard.

- **Start with a concrete failure.** The Wonder Toys assistant returns out-of-budget products because its price filter is broken. That single failure drives the whole workshop: collect the trace, investigate the code, propose a fix, and verify it against the exact cases that triggered the problem.
- **Instrument first, then close the loop.** The demo is built on the OpenAI Agents SDK and instrumented with Arize; tracing is not an afterthought but the mechanism that feeds the improvement cycle.
- **Telemetry as a driver, not a dashboard.** The key architectural shift is treating observed failures as inputs to an automated improvement pipeline rather than alerts waiting for a human to open a chart.

**[Can Your Agent Hear You Now? Building Live Voice Agents with Gemini — Thor Schaeff](https://www.youtube.com/watch?v=xfPVBzDYjH4)**
Thor Schaeff, working on developer experience at Google DeepMind, runs live demos of Gemini's real-time and media models — building a multimodal story generator and delivering real-time audience translation from a single session.

- **Real-time multimodal in one demo.** Schaeff combines Gemini Live with a fast Nano Banana image model to produce an illustrated story where the agent hears, sees, and responds in the same session.
- **Stateful Interactions API for consistency.** The API maintains character and visual style between generated images, directly addressing the drift problem that one-shot generation runs into.
- **Live audience translation.** Attendees scan a QR code to hear the talk in their own language in real time, serving as a direct proof of the pipeline's low-latency audio capabilities.

**[Agent Speedrun — Elizabeth Fuentes Leone & Sandhya Subramani, AWS](https://www.youtube.com/watch?v=YXiLj4tJt5A)**
A customer service agent that looks up accounts, checks orders, and handles refunds is the demo vehicle; the harder content is about controlling inter-step behavior and constraining what the agent can do once it reaches production.

- **Start with system prompt and tools.** The workflow is assembled with Strands Agents using a system prompt and three tools backed by mock customer data — the foundation is working quickly before any production concerns are introduced.
- **Inspect before you polish.** The presenters show messages and tool calls explicitly before adding a conversational interface, treating observability as a prerequisite rather than a later optimization.
- **Hooks as a control plane.** A hook is introduced to limit tool invocations, providing a programmable constraint layer between the agent's intent and its execution.
- **Lowering the iteration bar.** Making the loop fast and inspectable is framed as the prerequisite for safe production deployment, not something to tackle after launch.

**[The SDLC You Build Yourself — Andy Wong, Andrei Bocan & Shane Wolf, Atlassian](https://www.youtube.com/watch?v=ojJXgXLUQFc)**
Atlassian moves the demonstration of AI assistance beyond an in-editor coding companion to a workflow that begins with a Jira item, draws on organizational knowledge, and produces a change for human review — with a design token standard turned into an enforceable code review rule as the concrete example.

- **Engineering standards become executable rules.** A design token standard is converted into a reusable code review rule applied across selected repositories, replacing manual enforcement on every PR.
- **Organizational context as input.** The workflow draws on code, documents, and other knowledge artifacts, making org-level standards machine-readable rather than siloed in wikis.
- **The agent works the ticket, not just the file.** The starting point is a Jira item rather than an open editor, connecting task management directly to automated implementation.

**[Agents That Own Their Inference — Du'an Lightfoot & Khaja Omer, Akamai Technologies](https://www.youtube.com/watch?v=4n08JHb90hI)**
A speculative decoding optimization that slows a demo model from roughly 58 tokens per second to 16 — instead of speeding it up — anchors a practical workshop on the gap between inference theory and measured performance on a specific model, hardware, and workload.

- **One failed optimization, one core lesson.** Speculative decoding dropped throughput from roughly 58 to 16 tokens per second on the demo model. The point is not that it fails universally, but that any configuration change must be measured against the actual stack.
- **Hosted API vs. dedicated GPU is the first fork.** Participants work through that decision before touching configuration, framing it as the primary architecture choice rather than an operational detail.
- **Kubernetes + Jupyter + vLLM as the lab environment.** Each participant gets a namespace with a notebook and a vLLM endpoint, keeping the hands-on surface close to a real deployment.
- **Qwen as the reference model.** The workshop uses Qwen for inference exercises, giving participants a concrete open model to benchmark configurations against.

**[AI Security Engineer Foundations + Certificate — Micah Silverman, Snyk](https://www.youtube.com/watch?v=p-2MT8KYZqU)**
A CTF exercise — a student chatbot that refuses to reveal grades but exposes that it has access to them — frames the core argument: system prompt restrictions are not access controls, and the only reliable boundary is removing sensitive data from the model's available context entirely.

- **Prompt instructions are not access controls.** Telling an assistant to keep data private leaves the data reachable within its context. Removing the data from that context is the only reliable boundary.
- **CTF as a teaching device.** The student grade scenario makes the gap between "model behavior" and "data access" concrete and immediately replicable.
- **Six modules, end to end.** The course covers OWASP risks, shadow AI, threat modeling, MCP security, secure agentic development, and red teaming — a broad surface for practitioners who own AI-integrated systems.
- **MCP security as a distinct concern.** Model Context Protocol surfaces as its own security domain in the curriculum, signaling that the attack surface for agentic systems extends beyond the model itself.

**[Vector Isn't Enough: Hybrid Search & Retrieval — Jeff Vestal & James Williams, Elastic](https://www.youtube.com/watch?v=ksjwtQop4os)**
An agent that diagnoses an exit code 137 out-of-memory failure by retrieving documentation depends entirely on the quality of the retrieval layer beneath it — the workshop works backward from that observable behavior to show why pure semantic search is insufficient and why hybrid BM25 plus vector search is necessary.

- **Semantic search misses exact identifiers.** Similar meaning does not reliably surface an exact error code or configuration key; BM25 handles keyword precision that vector similarity cannot guarantee on its own.
- **Work backward from agent behavior.** The diagnostic example — exit code 137, OOM failure, prevention settings — is constructed to show which retrieval configuration produces correct citations and which does not.
- **Hands-on in Elasticsearch.** Labs compare semantic and BM25 retrieval directly, grounding the tradeoffs in observable differences rather than theoretical descriptions.
- **Citations as a retrieval quality signal.** When the agent surfaces documents, its citations become a direct measure of whether the underlying retrieval layer is working correctly.

**[The Data Context Layer for Agents — Yoni Michael & Brandon Callender, Typedef](https://www.youtube.com/watch?v=KhRjivBSwiw)**
The same identifier appearing in two separate contexts can represent two entirely different things — a context graph preserves those identities and their separate dependencies in ways that text search cannot, making it the appropriate foundation for agents that need to reason about data correctness rather than just data retrieval.

- **Identity over proximity.** Two Rust types both named PostingList look identical in text search results but change different code when modified. Context graphs keep their dependency graphs distinct where string matching cannot.
- **Correct SQL is not correct data.** For data systems, valid SQL can still return the wrong answer when a join multiplies rows or a refactor changes a metric's underlying definition.
- **Grain and lineage as computable properties.** The context layer computes grain and lineage as structured properties, turning "is this query correct?" from a human judgment into something a system can evaluate.
- **Connecting data engineering to coding agents.** The framing bridges problems familiar to data practitioners — metric drift, join fan-out — with the context quality problems that coding agents encounter.

**[Turning My Obsidian Vault Into a Local AI Engineer — Filip Makraduli, Superlinked](https://www.youtube.com/watch?v=Ndp5VaqFrl0)**
Sensitive documents — including scanned NDAs — require processing before an agent can use their contents safely; the demo builds that pipeline around an Obsidian vault, an MCP integration, and Superlinked's inference engine, using small open models on controlled infrastructure to handle OCR and redaction before anything reaches a large model.

- **Redact before you ingest.** A scanned NDA is converted to a redacted Markdown document as a pre-processing step; the large model only ever sees the sanitized version.
- **Small models for heavy lifting.** OCR and document processing are offloaded to small open models on infrastructure the team controls, keeping sensitive content off hosted APIs entirely.
- **Obsidian + MCP as the agent interface.** The vault becomes an operational environment for the coding agent rather than just a note store, with MCP providing the integration layer between the vault and external tools.
- **Infrastructure control as the primary design constraint.** The entire architecture is shaped by the requirement to keep sensitive data within a controlled environment — not a preference but a hard requirement driving every other decision.

**[Parsing the Epstein Files for JMail — Palak Agarwal & Omar Alhait, Reducto](https://www.youtube.com/watch?v=HGfsfKaVuGY)**
Handwritten flight logs and heavily redacted PDFs represent the difficult end of document parsing — Palak Agarwal and Omar Alhait show how Reducto turned those materials into structured, searchable records for JMail and the related JFlights application through a schema-driven extraction pipeline.

- **Parsing is the prerequisite.** Before any search or analysis is possible, the difficult document formats must be converted to structured data. The work begins with parsing, not with the model or the product.
- **Schema drives extraction.** JFlights uses a schema to transform difficult pages — handwritten logs, redacted PDFs — into usable records, making schema definition a core product decision rather than a technical implementation detail.
- **Studio for validating extraction output.** Reducto's Studio is used to test extraction results before the pipeline is trusted, inserting a review step between parsing and downstream use.
- **Document variety as the hard problem.** The combination of handwritten content and heavy redaction represents the upper end of document processing difficulty, and using it as the production example demonstrates the pipeline's range.
