## Daniel Pink

**[Counterfactual Thinking](https://www.youtube.com/watch?v=JMQ87GSZxvY)**
Daniel Pink examines how the direction of mental comparison — not the outcome itself — determines emotional response, drawing on Olympic medalist research and three decades of regret science to show that counterfactual thinking is a practical lever for wellbeing and motivation, not just an emotional side effect of losing.

- **Bronze beats silver on happiness, proven across cultures.** David Matsumoto and Bob Willingham coded the faces of 84 judo medalists from 35 countries at the 2004 Athens Games; gold and bronze winners produced genuine smiles (the kind that pull the muscles around the eyes), silver medalists almost never did — because bronze winners compare downward (vs. not placing) while silver winners compare upward (vs. gold).
- **Same podium, radically different emotional experience.** The experimental design isolates the mechanism: objective rank is held constant while only the comparison direction changes, confirming that the comparison does the causal work, not the result.
- **Upward counterfactuals carry a productive edge.** Neal Roese, who has studied regret for three decades, frames upward counterfactuals ("if only I had…") as the "useful half" — the discomfort of upward comparison drives future improvement in a way the comfortable downward form does not.

Psychologist Lisa Feldman Barrett challenges the assumption that emotions and basic perception are biologically fixed, arguing that what we experience as universal signals are cultural and experiential constructions built from prior patterns — including sensory categories most people treat as objective facts about the world.

- **Emotions are pattern completions, not universal readouts.** Barrett argues that emotional perception is based on learned cultural patterns rather than hardwired signals — the same expression can carry different meaning depending on the context in which a person learned to read it.
- **Color perception illustrates the constructivist point.** A hypothetical four-coned visual system would make today's "objective" red appear wrong, just as colorblindness already disrupts what most people treat as an objective property of the world — neither case is anomalous, both reveal the same constructed nature.
- **Prior experience is the active architecture of present perception.** The title's claim — that your past contributes to your present — is Barrett's literal thesis: history is not background context but the mechanism through which current experience is assembled.

## AI Engineer

**[How to Build an AI Code Review Agent - Daksh Gupta, Greptile](https://www.youtube.com/watch?v=4UtrRVtUN_g)**
Daksh Gupta of Greptile — which reviews roughly 1% of all GitHub pull requests — walks through the evolution from a naive code review agent to a production-grade system, detailing why the obvious first approach consistently fails and the specific interventions that fix it.

- **The naive setup is expensive and noisy.** A basic sandbox-plus-webhook agent costs $3–25 per PR and floods developers with nitpicks while missing actual bugs — the wrong outcome on both dimensions simultaneously.
- **Model inversion catches approximately 10% more bugs.** Reviewing Claude-written code with GPT (and vice versa) finds bugs that same-model review misses; Greptile treats cross-model checking as a standard technique rather than an edge-case optimization.
- **Targeted prompts and incident PR datasets are the core fixes.** Rewriting prompts around specific bug classes and building a dataset from past incident PRs moves the agent from generic lint-style comments to catching the failures that actually hurt teams.
- **Codebase context is a structural prerequisite.** The snippet identifies codebase context as a key additional fix — without it, an agent cannot distinguish local conventions from genuine errors.

**[Build Your Own Team of Managed Agents - Jack Wotherspoon, Google DeepMind](https://www.youtube.com/watch?v=Y_p3y6zP5QE)**
Jack Wotherspoon of Google DeepMind introduces Gemini Managed Agents — coding agents that run in cloud sandboxes from a single API call, with built-in multi-agent coordination, shared environments, scheduled triggers, and secret isolation via a proxy layer.

- **Cloud-first execution, not laptop agents.** Managed Agents run in cloud sandboxes from a single API call, removing the local setup overhead that blocks most teams from running persistent or scheduled coding agents today.
- **Shared environments enable multi-agent handoffs.** Multiple agents can access the same environment; a demo shows an SEC filing researcher handing its output directly to a quant agent without manual data transfer.
- **A proxy keeps secrets out of the sandbox.** A dedicated proxy layer handles credential access so sensitive secrets never live inside the sandbox — directly addressing the key blocker for giving agents production access.
- **AGENTS.md and uploaded skills extend capability declaratively.** Reusable behaviors can be codified in AGENTS.md files and uploaded skills, letting teams configure agents without modifying core agent code.

**[How to Build Voice Agents That Don't Fall Apart When You Interrupt - Jesse Hall, LiveKit](https://www.youtube.com/watch?v=OmyqelTwpOo)**
Jesse Hall of LiveKit makes the case that voice agent quality is a conversation-level problem, not a component benchmark problem — and that the right measurements, latency budgets, and turn detection logic must all be designed around the full conversational loop rather than individual model scores.

- **Leaderboards measure the wrong thing.** Model benchmarks score components; you ship a conversation. Optimizing for benchmark scores without measuring end-to-end latency and coherence produces agents that rank well but feel robotic in real use.
- **Measure time-to-first-audio and time-to-first-sentence, not time-to-first-token.** Users perceive the conversation starting when they hear something sensible — not when the first byte leaves the server — so optimizing for the wrong metric produces a technically fast but experientially broken agent.
- **Async tool calls are the latency unlock.** Running slow back-end work asynchronously while keeping the conversation flowing prevents the silent pause that makes voice agents feel mechanical and erodes user trust.
- **The target latency budget is roughly 1.5 seconds; 500–600ms feels truly natural.** This grounds the concrete design target for financial services voice agents, where even brief silences break the conversational illusion.

**[How to Write Your First AI Eval - SallyAnn DeLucia, Arize AI](https://www.youtube.com/watch?v=gv4w23xYj-0)**
SallyAnn DeLucia, head of product at Arize AI, runs through the practical mechanics of building a first AI eval — from defining pass/fail criteria to building and iterating on an LLM-as-judge in a prompt playground — with explicit focus on why vibe checks break down at scale.

- **An eval is not a unit test.** Evals assess non-deterministic behavior, require probabilistic pass/fail criteria, and must be iterated on over time; treating them as write-once artifacts replicates vibe-checking in a more formal wrapper.
- **Five eval types to know.** DeLucia covers LLM-as-judge, decision models, code evals, human annotations, and agent-as-judge — each suited to different output types and quality dimensions.
- **Concrete criteria must come before tooling.** Without specific pass/fail definitions, LLM judges formalize the same vague intuitions behind vibe checks; writing the criteria is the hard work, not setting up the infrastructure.
- **Traces are the foundational input.** The workshop covers how to read a trace, positioning trace data as the prerequisite artifact for any eval pipeline — you cannot evaluate behavior you cannot observe.

**[What Does an AI Engineer Do Now? - Aparna Dhinakaran, Arize AI](https://www.youtube.com/watch?v=ImnZ7s68jw8)**
Aparna Dhinakaran of Arize AI reframes the AI engineering role as building the feedback loop itself — evals, telemetry, and agents that close the loop on non-deterministic systems — illustrated through Arize's own production deployment of Signal, an agent that monitors traces and autonomously opens PRs.

- **The job has shifted from features to loops.** AI engineers now build the infrastructure that reviews and improves AI outputs: evals that watch agents, telemetry agents consume, and automated responses to what that telemetry reveals.
- **Signal is the concrete production example.** Arize's own always-on agent reads traces, retains memory of past issues, and opens PRs in response — running in sandboxes with durable state and addressing the "evaluating the evaluators" problem in production.
- **Durable state and trigger design are the hard problems.** Building an agent that remembers context across runs and fires on the right signals without false-positive noise is the real engineering challenge, not model selection.
- **Non-determinism makes the loop essential.** Standard software QA does not scale to LLM outputs; the eval-telemetry-agent loop is the engineering response to systems that cannot be verified by deterministic tests.

**[Can Your AI Analyst Keep a Secret? - Aaron Linsky, Bridgewater & Nikhil Benesch, turbopuffer](https://www.youtube.com/watch?v=u_jvuCjuvEk)**
Aaron Linsky (Bridgewater) and Nikhil Benesch (turbopuffer) work through permission-aware retrieval at scale: when 100 million documents each carry individual access controls, standard vector search approaches break down, and the fix requires rearchitecting how filtering and indexing interact.

- **Post-filtering destroys recall.** Filtering results after vector search eliminates accessible documents before they reach the user, since the search has no visibility into per-document permissions — at 100 million permissioned documents this becomes a structural recall problem.
- **Pre-filtering is too slow.** Computing the accessible document set per user at query time, before running the search, is too expensive to deliver acceptable latency at Bridgewater's scale.
- **Native filtering solves both.** Turbopuffer integrates permissions directly into the clustered vector index, delivering approximately 120ms P90 latency while preserving the recall that post-filtering sacrifices.
- **Permission-aware retrieval is a distinct architectural problem.** Adding access control to an existing vector search pipeline is not incremental; the Bridgewater Vault experience shows it requires designing the filtering constraint into the index from the start.
