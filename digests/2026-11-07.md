## Daniel Pink

**[Stop Hiring Geniuses](https://www.youtube.com/watch?v=lOVjnrL35tg)**
Research from Rotman School's Grusha Agarwal, George Newman, and Rachel Ruttan shows that organizations systematically screen for "genius" traits over exploratory ones, that this bias is recruiters' unprompted default, and that the fix lies in changing the vocabulary used in job postings.

- **The word gap is empirical.** In a sample of real postings, "genius," "visionary," and "unique" appeared more than twice as often as "curious," "observant," and "experimental."
- **Recruiters default to genius framing from scratch.** When more than 300 hiring managers were asked to write a creative job posting unprompted, most reached for genius-coded language — it is not a template inheritance problem.
- **Reframing the target is a tractable lever.** The 2026 paper "Seeking creative explorers: How dispelling genius myths enhances organizational recruiting" (Agarwal et al.) positions shifting the stated criteria as a direct path to changing who gets hired.

**[One-way doors vs. two-way doors | Dambisa Moyo](https://www.youtube.com/watch?v=112zzmKAfno)**
Economist and UK House of Lords member Dambisa Moyo — author of Dead Aid — distinguishes between irreversible decisions (one-way doors) and reversible ones (two-way doors), arguing that correctly classifying a choice fundamentally changes the appropriate risk calculus.

- **Reversibility lowers the real cost of acting.** Two-way door decisions allow you to exit if the bet fails, which removes the justification for extended deliberation before moving.
- **The framing converts abstract risk into a testable question.** Rather than feeling uncertain about a choice, you ask whether you can exit if the bet fails — and anchor the risk calculus to that answer.
- **The practical rule is asymmetric.** Reserve deep deliberation for genuine one-way doors; the reversibility of two-way doors makes moving quickly the rational choice.

## AWS What's New

**[Capacity Reservation Resource Groups now support Amazon EC2 Capacity Blocks and interruptible Capacity Reservations in AWS GovCloud (US) Regions](https://aws.amazon.com/about-aws/whats-new/2026/11/capacity-reservation-resource-groups-support-in-aws-govcloud-regions)**
Capacity Reservation Resource Groups in AWS GovCloud can now include EC2 Capacity Blocks for ML and interruptible Capacity Reservations, not just On-Demand Capacity Reservations (ODCRs). GovCloud customers can now manage all reservation types within a single group, simplifying capacity planning for ML workloads in regulated environments.

**[AWS Security Hub now provides an SBOM inventory for your compute resources](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-sbom-inventory/)**
Security Hub now aggregates Software Bill of Materials (SBOM) data generated by Amazon Inspector across EC2 instances, ECR container images, and Lambda functions into a continuously updated, organization-wide package inventory with no additional configuration. Each package is listed with its version, giving central security teams a single view of installed software across the entire compute estate.

**[AWS Interconnect - last mile announces new metro in Northern Virginia, USA](https://aws.amazon.com/about-aws/whats-new/2026/11/interconnect-last-mile-northern-virginia/)**
AWS Interconnect last-mile private connectivity is now available in Northern Virginia, joining New York as the second supported metro. Each connection is provisioned by default across two physically diverse locations with four redundant links, delivering managed private AWS connectivity without manual cross-connect ordering or router configuration.

**[Announcing Web Answer on Amazon Bedrock AgentCore](https://aws.amazon.com/about-aws/whats-new/2026/11/web-answer-amazon-bedrock/)**
Web Answer is now generally available on Bedrock AgentCore, providing a managed tool that returns a synthesized, cited, natural-language answer to a natural-language question in a single API call. Agent builders can attach it directly to an agent without building and maintaining their own search, retrieval, synthesis, and citation pipeline.

**[AWS Network Load Balancer is now available in the AWS Phoenix Local Zone](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-nlb-available-phx-local-zone/)**
Network Load Balancer is now available in the Phoenix Local Zone (us-west-2-phx-2a), so workloads running in that zone can use a co-located NLB rather than placing the load balancer in the parent region. Previously, targets in the Phoenix Local Zone required the load balancer to be deployed in the parent region.

**[Amazon DynamoDB now supports bulk put items](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-dynamodb-now-supports-bulk-put-items/)**
DynamoDB's new bulk put items feature writes data from Amazon S3 directly into existing DynamoDB tables as a fully managed operation, eliminating the need for custom ingestion pipelines. It runs without impacting existing workload capacity, removing the previous requirement to manage table throughput during large data loads.

**[Amazon Cognito announces 99.99% Service Level Agreement for the Plus feature plan](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cognito-sla-update/)**
Cognito user pools on the Plus feature plan now carry a 99.99% monthly uptime SLA, up from 99.9%, effective November 1, 2026. Essentials and Lite plans remain at 99.9%; switching to Plus via the console, AWS CLI, or SDK qualifies a user pool for the new commitment with no other changes required.

**[IAM Roles Anywhere now supports automatic certificate revocation checking](https://aws.amazon.com/about-aws/whats-new/2026/11/iam-roles-anywhere-cdp/)**
IAM Roles Anywhere can now automatically fetch and check Certificate Revocation Lists (CRLs) using CDP URLs embedded in authenticating certificates, denying credential requests that present revoked certificates. Enabling this on a trust anchor keeps revocation state continuously in sync with the certificate authority without requiring manual CRL uploads.

**[Amazon OpenSearch Service optimized engine now supports agent traces](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-service-support-traces)**
The OpenSearch Service optimized engine now ingests OpenTelemetry traces alongside logs, enabling end-to-end request and agent session tracing without switching between tools. It maps OpenTelemetry logs and traces to object, nested, and flat object fields with support for multi-valued arrays, span events, span links, prompts, and completions.

**[Amazon FSx for Lustre delivers 16x higher metadata IOPS on Intelligent-Tiering file systems](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-fsx-for-lustre-intelligent-tiering-16x-higher-metadata-iops)**
FSx for Lustre Intelligent-Tiering now supports up to 192,000 metadata IOPS, a 16x increase from the previous maximum of 12,000. # 🤖 AI & Machine Learning

## AI Engineer

**[When We Can Do Anything, Do We Still Know What We Want? — Ryo Lu, ex-Cursor | AI Engineer Shanghai](https://www.youtube.com/watch?v=y9Sg--RDtks)**
Former Cursor founding designer Ryo Lu argues that as AI makes software generation nearly frictionless, the bottleneck shifts from building to deciding what to build — and that most AI-generated products arrive carrying implicit design choices the user never consciously made.

- **Default choices embed design invisibly.** Ask an AI to build a journal and it ships mood scores, streaks, daily reminders, and weekly reports — features with real UX tradeoffs, none of which the user selected.
- **Reconfigurability is the key capability.** A well-designed AI tool makes its implicit decisions explicit and changeable; a poorly designed one locks them in behind a completed artifact.
- **Demonstrated on a live journal demo.** Lu built the case at AI Engineer Shanghai (November 5, 2026), showing both how defaults slip in and how surfacing them changes the product.

**[7 Things Your AI Coworker Needs - Philipp Schmid, Google DeepMind](https://www.youtube.com/watch?v=EtZwTYahfek)**
Google DeepMind's Philipp Schmid breaks an autonomous AI coworker for finance into seven discrete components and constructs each live using Gemini and the Gemini API's Managed Agents.

- **Seven components, each load-bearing.** A brain, a compute sandbox (with skills and files), playbooks, tools, credentials, house rules (approval hooks), and a schedule (cron triggers) — missing any one breaks the system.
- **Credential isolation is non-negotiable for security.** Credentials are injected by a network proxy rather than placed in the prompt, preventing prompt injection from exfiltrating them.
- **Built-in tooling and MCP servers reduce custom code.** Using existing integrations rather than building from scratch keeps the agent maintainable as requirements evolve.

**[Your AI Isn't the Advantage. Your Judgment Is - Sid Pednekar](https://www.youtube.com/watch?v=C2-v6wkHXhY)**
AI and data executive Sid Pednekar examines why most organizations have deployed AI but few see real results, tracing the gap to three execution differences between leaders and laggards illustrated through two hypothetical firms.

- **Concentration beats distribution.** Leaders pick a few high-value workflows and invest deeply; laggards scatter pilots across many areas and get shallow, non-compounding impact.
- **Shared capabilities beat siloed ones.** Standardizing core AI infrastructure and breaking down silos lets each success compound rather than stay local to one team.
- **Feedback loops determine long-run performance.** Every success and failure must feed back into the system; organizations without this loop do not improve over time.

**[Your AI Agent Keeps Making the Same Mistakes - Sparsh Jain, CentralAgent AI](https://www.youtube.com/watch?v=SUqQlvyI3N8)**
CentralAgent AI's Head of AI Sparsh Jain argues that more memory does not equal more learning, and shows how his team rebuilt agent memory as an experiential system after two years of observing the same agent repeat the same mistakes.

- **Volume of memory is not the problem.** An agent can hold extensive memory and still repeat errors if that memory is not structured for updating and pruning.
- **Memory as a lifecycle, not a log.** New experiences form notes; existing notes are updated or deactivated rather than deleted, preserving an audit trail of how judgments evolved; a cleanup loop removes what no longer matters.
- **Regular cleanup is the differentiating mechanism.** Jain describes this loop as working like a good night's sleep — the step that prevents memory from becoming noise rather than signal.

**[AI Agents Will Upend Investing Even More Than Coding - Frank Long, Coatue](https://www.youtube.com/watch?v=AYFcmnQrZCg)**
Coatue investor Frank Long argues that AI agents will have a larger transformational impact on investing than they did on software engineering, then deconstructs a hedge fund's workflow to map where agents fit.

- **A hedge fund is a function.** Long frames it as: inputs (outside and inside context) → outputs (what to buy, how much, when), decomposed into gather, analyze, and decide steps — each of which can be assigned to code, statistics, an LLM, or a person.
- **Decomposition enables auditability.** Breaking the workflow into discrete steps makes it possible to assign the right tool to each step and audit each one, rather than treating the fund's reasoning as a black box.
- **Non-English-language domain news as a case study.** Korean-language semiconductor news illustrates where LLMs provide value that statistics and code cannot replicate, anchoring the agent-value argument in a concrete gap.

**[Stop Giving Your AI Agents API Keys - Kim Maida, Keycard & Mason Egger, Temporal](https://www.youtube.com/watch?v=YqJ4asgj1R8)**
Keycard's Kim Maida and Temporal's Mason Egger demonstrate two orthogonal production properties for AI agents: secure-by-design credential handling and fault-tolerant durable execution.

- **API keys are the wrong trust primitive.** Maida replaces them with OAuth token exchange — each tool call gets a short-lived token scoped to that specific call and tied to both the agent's identity and the user it is acting for.
- **Audit trails are built in, not bolted on.** The live expense-approval demo captured who filed and who approved each action, making every step attributable with no additional instrumentation.
- **Durable execution handles mid-task failure.** Egger used Temporal to kill an agent mid-task and resume it from exactly the point it stopped, eliminating the common failure mode where partial execution leaves state inconsistent.

**[How Netflix Evaluates AI When There's No Right Answer - Cameron Wolfe, Netflix](https://www.youtube.com/watch?v=zLc8zeGeNaY)**
Netflix staff research scientist Cameron Wolfe presents a three-part evaluation framework for AI tasks with no ground truth — such as creative writing — grounded in the principle that human judgment is the only credible reference point.

- **Human evaluation is the North Star.** Calibrated human guidelines set the reference; every other eval method is validated against that standard, not treated as equivalent to it.
- **LLM judges scale offline evaluation.** LLM-based rubrics validated against human "golden" data allow high-volume offline evals without human review of every example.
- **A/B tests and production monitoring close the loop.** Real-world experiments confirm whether offline improvements translate to actual outcomes — the step that prevents eval theater.
- **Statistical rigor is load-bearing.** Wolfe covers power analysis to fight noise and error budgeting, the methodology scaffolding that makes the framework trustworthy rather than aspirational.
