## AWS What's New

**[Announcing Amazon ECS Gateway, a managed ingress solution for your ECS services](https://aws.amazon.com/about-aws/whats-new/2026/10/announcing-amazon-ecs-gateway/)**
Amazon ECS Gateway is a new resource that automates provisioning and management of Application Load Balancers and their supporting resources directly in customer accounts. Platform teams define ingress networking standards once on a gateway and associate it with one or more clusters, centralizing governance over how traffic reaches ECS services without per-service overhead.

**[Amazon DynamoDB global tables now support disassociating replicas](https://aws.amazon.com/about-aws/whats-new/2026/10/dynamodb-global-tables-disassociate/)**
DynamoDB global tables can now stop replication to or from a replica without deleting the table or its data, letting teams continue using the table as a single-region table. This covers both shared multi-account tables leaving a global arrangement and single-region isolation for local workloads, validation, or audit purposes.

New English voices include Kenneth and Nate (US), Russell and Curtis (Australian), and others.

TorchNeuron is an open-source native PyTorch backend for AWS Trainium, now in public beta, enabling AI researchers to run PyTorch workloads on Trainium by switching to `.to('neuron')` without rewriting model code. Trainium is AWS's purpose-built AI chip portfolio targeting high performance and cost efficiency for deep learning training and inference.

**[Structured outputs for Claude models available on Amazon Bedrock](https://aws.amazon.com/about-aws/whats-new/2026/10/claude-structured-outputs-bedrock/)**
Amazon Bedrock now supports structured outputs for all Anthropic Claude models across both the bedrock-runtime and bedrock-mantle endpoints, returning schema-compliant JSON without custom parsing, retry logic, or post-processing. The feature is available whether calling Claude via boto3 or the Messages API.

## AI Engineer

**[One Day, $1,000 in Tokens: An AI War Room for Legacy Code — Ford Prior, GEICO](https://www.youtube.com/watch?v=DouK81O8R3o)**
Ford Prior describes how GEICO attacked the bottleneck that remained after coding got fast: decisions, sign-offs, and context-gathering still moved slowly. His answer was a structured "war room" — the right decision-makers, one human driver, and a fleet of agents wired into GEICO's knowledge and code — running against a fixed budget of one day and $1,000 in tokens.

- **Speed bottleneck is process, not code generation.** Coding with AI accelerated quickly; the surrounding work (approvals, context transfer, domain mapping) did not. The war room targets that gap directly.
- **One driver, many agents.** A single human drives the session rather than multiple engineers working in parallel, preventing divergent context and unclear ownership across the agent fleet.
- **$1,000 token budget as a forcing function.** Constraining the session to one day and a $1,000 token ceiling made the format repeatable and scoped — not an open-ended investigation.
- **Three legacy claims domains validated the pattern.** Prior ran the model in rentals, damages, and salvage, demonstrating the approach generalizes across distinct legacy domains, not just one favorable case.
- **FleetKit as the agent rulebook.** A markdown-based rulebook called FleetKit steers agent fleet behavior, suggesting lightweight structured documentation is sufficient governance for multi-agent sessions.

**[AI Cut Our Research Time From 7 Days to 15 Minutes — Gareth Yoder, Vanguard](https://www.youtube.com/watch?v=uA4ah-dVHvU)**
Gareth Yoder walked through modernizing Vanguard's cash ledger — a system handling up to 30 million calls per day — and how exposing the legacy codebase to AI tools via an MCP server became the inflection point that collapsed mainframe research from seven days to 15 minutes.

- **MCP server as the unlock for legacy code.** The architectural decision that changed everything was building an MCP server to make an opaque mainframe codebase AI-queryable — turning it from a black box into something AI tools could reason over.
- **7 days to 15 minutes.** Research requiring a senior mainframe engineer a full week dropped to 15 minutes once the codebase was accessible, making this the single sharpest productivity metric in the talk.
- **Parallel migration tracks at scale.** Data, producer, and consumer migrations ran concurrently — not sequentially — requiring deliberate coordination discipline on a system processing tens of millions of daily calls.
- **Treat migration docs as product.** Keeping documentation current as a first-class artifact was called out as a specific lesson, important where human knowledge of mainframe systems is scarce and not easily replaced.
- **Reimagine instead of lift-and-shift.** Yoder's framing pushes against direct translation: a modernization is an opportunity to redesign the system, not merely replicate it in a new runtime.

**[Is a Faster Model Actually Faster? Test the Whole Job — Morgan Suo, MiniMax](https://www.youtube.com/watch?v=YvQ4BVTWfHI)**
Morgan Suo challenges the assumption that a faster-generating model produces a faster finished result, using a real analyst research task to show that each optimization inside MiniMax's M3.1 Flash model saves compute but can quietly cost accuracy or wall-clock time elsewhere in the job.

- **Model speed and job speed are different metrics.** A model that generates tokens faster can still slow down the overall job through accuracy degradation, reasoning budget exhaustion, or increased server queue time.
- **Six optimization levers, six specific tradeoffs.** Sparse attention on long inputs, 4-bit KV cache, low-precision experts, speculative decoding, server load, and reasoning budgets each reduce compute — and each has a distinct failure mode that can extend total job duration.
- **Evaluate against a real task, not a synthetic benchmark.** Suo uses one representative research task — an analyst checking whether circuit-board suppliers are converting AI demand into revenue — as the measuring stick, not an abstract speed test.
- **Server load is part of the latency equation.** A model that runs faster in isolation still slows down in production when increased demand shifts to it and queue times rise, an effect invisible in single-request benchmarks.

**[Same GPU, 50% More Output: Why the Operator Matters — Oliver Kennon, SemiAnalysis](https://www.youtube.com/watch?v=3axY1wz2OvA)**
Oliver Kennon frames compute as a commodity market where the GPU hardware is table stakes — the operator running the serving stack is the variable that determines how much useful work actually gets produced from identical silicon.

- **50% more output from the serving stack alone.** On the same B200 chip, operator quality — software, scheduling, inference optimization — can deliver approximately 50% more useful output, making operator selection a strategic decision, not just a procurement one.
- **Rental price and production cost are separate numbers.** What it costs to rent compute and what it costs to produce a unit of intelligence are different figures; conflating them produces broken cost models.
- **Cluster security is part of the capability definition.** Intelligence that can't be acted on safely because the cluster is insecure is less "useful" regardless of throughput — security belongs inside the capability calculus.
- **Your cost position is relative to competitors.** Where you sit on the cost curve is determined not just by your own operational efficiency but by what other operators are achieving on the same hardware generation.

**[A Bank Built Its Own Coding Agent. It Took Off — Felipe Felisola Caso & Francesco Galletta, Monzo](https://www.youtube.com/watch?v=adfw3xJBx1o)**
Monzo's in-house coding agent began as a Slack emoji reaction and now authors over 10% of all merged PRs across the company's engineering teams, running more than 1,800 tasks per day — scaling rapidly because it landed on infrastructure multipliers Monzo already had in place for a regulated banking environment.

- **Started as a Slack emoji.** The entry point was intentionally near-zero friction: engineers reacted to a Slack message to trigger the agent, removing adoption barriers before any serious usage patterns were established.
- **10% of merged PRs, 1,800+ tasks per day.** These are production metrics at a regulated UK bank — a material share of engineering output now flows through the agent at scale.
- **"Lots of little multipliers" explains the speed.** The team attributes rapid adoption to pre-existing infrastructure: an MCP gateway into internal tools and knowledge, a sandboxed agent orchestration layer, and a platform that treats the agent as a composable building block.
- **Regulation shaped the architecture into an accelerant.** Building a sandboxed, governed orchestration system was mandatory for operating as a bank — that compliance investment became a structural advantage once the agent launched, not a constraint.
