## AI Engineer

**[Why We Rebuilt Microsoft Office From Scratch for AI Agents - Yijia Liang, Compound AI](https://www.youtube.com/watch?v=v0UkV5qS9E4)**
Compound AI founder Yijia Liang argues that building autonomous AI analysts for institutional finance requires moving beyond personal agents to multiplayer systems — and that purpose-built infrastructure, including a headless Office engine rebuilt from scratch, is the minimum viable foundation.

- **Personal agents aren't enough for finance.** They run reliably in the background and connect to individual context, but institutional finance demands multiplayer agents: systems with their own inboxes that join deal-team email threads as participants, not observers.
- **The Office rebuild was non-negotiable.** Compound built a headless Office engine from scratch — over 8 million lines of code, processed against 1.5 trillion tokens — because existing Office tooling was not designed to be operated programmatically by agents at scale.
- **Operator experience shaped the architecture.** Liang's years as a finance analyst living in Excel and PowerPoint directly informed the product decisions; the system is built around workflows analysts actually run, not a generalized agent template.

**[Most of Your Docs Readers Are Now AI Agents - Hahnbee Lee, Mintlify & Lincoln Murr, Coinbase](https://www.youtube.com/watch?v=YX4Z4XqZ9Vo)**
Mintlify co-founder Hahnbee Lee and Coinbase head of AI product Lincoln Murr argue that the shift from human to AI-agent readers of developer documentation has already happened at scale, and the implications for docs design, API strategy, and business models are only beginning to land.

- **Agent traffic jumped from 10% to 80% in one year.** On Mintlify docs sites, the share of traffic from AI agents grew from roughly 10% to roughly 80% — a near-complete inversion of who documentation is actually serving.
- **Design for correctness, not for humans.** When agents are the primary readers, visual polish is irrelevant; page size and accuracy are now the dimensions that determine documentation quality.
- **Coinbase is making its whole business API-accessible.** The strategic response for a financial platform is to treat agents as first-class customers — not by adding agent-specific features, but by exposing existing services through APIs.
- **x402 is an early signal of agent-native commerce.** Lee and Murr cite around 100 [figure truncated in excerpt] for the x402 payment standard, pointing to emerging infrastructure for agents to transact, not just retrieve.

**[If Your AI Scores 100%, Your Eval Is Wrong - Ramakrishnan Lokanathan, eslams.com](https://www.youtube.com/watch?v=7WUzHIF32vA)**
Ramakrishnan Lokanathan makes the case that a perfect eval score is a warning sign — indicating a saturated benchmark — and outlines an evaluation methodology for high-stakes AI built around the hardest success criteria, workflow-level testing, and continuous regression coverage.

- **100% is a saturation signal, not a passing grade.** Calibrating to the most ambitious version of success means a perfect score signals the benchmark has been outgrown, not that the system is production-ready.
- **Test the workflow, not just the output.** Evaluating only the final answer hides failures in intermediate steps; every stage of an AI pipeline needs its own targeted checks.
- **Layer automated, human, and adversarial testing.** No single evaluation method catches all failure modes; the combination provides the coverage that matters for high-stakes deployments.
- **Treat model upgrades as regression risks.** Continuously re-running tests that previously passed prevents capability improvements in one area from silently breaking established behaviors elsewhere.
- **Convert production failures into test cases.** Real user failures are the highest-signal input for expanding evals — building a feedback loop from live failures to new tests closes the gap between benchmark performance and real-world reliability.

**[Your AI Agent Wants Your Data. Here's How to Lock It Down - Jeff Smith, Oracle](https://www.youtube.com/watch?v=LnQce-eHm8k)**
Oracle's Jeff Smith, drawing on 25 years building database tools, argues that agent-database integration introduces a new failure class — queries that execute correctly but return wrong answers — and shows how Oracle's MCP server reframes the problem by replacing raw SQL generation with governed, tool-based access.

- **Correct syntax, wrong answer is the real threat.** Natural language to SQL can produce queries that run without error and still return semantically incorrect data. The risk model shifts from access control to output correctness.
- **Vetted reports as tools, not ad hoc SQL.** Oracle's MCP server exposes a team's pre-approved reports as agent tools instead of allowing agents to generate arbitrary queries, narrowing the surface area for wrong-answer results.
- **Read-only standbys isolate performance work.** Routing agents to a read-only standby for performance-tuning queries keeps exploratory agent activity off production systems.
- **Schema annotations stop dictionary brute-forcing.** Annotating schemas with semantic metadata guides agents directly to relevant tables and columns, preventing agents from exhaustively probing the data dictionary to discover structure.

**[Everyone Has the Same AI Models. Here's What Sets Agents Apart - Richmond Alake, Oracle](https://www.youtube.com/watch?v=1_lX0m64-aI)**
Oracle's Richmond Alake argues that foundation model access has become a commodity, and the next layer of differentiation — the intelligence plane — is where agent capability is actually built: what an agent knows, remembers, is permitted to see, and how it improves over time.

- **The intelligence plane sits above the control plane.** Once the mechanics of running an agent are solved, meaningful differentiation moves to knowledge architecture, memory, access controls, and improvement loops — collectively the intelligence plane.
- **Same data is not the same as intelligence.** Alake invokes WWII codebreakers who deduced that "AF" meant Midway — not because they held exclusive information, but because they interpreted shared data with greater semantic precision. Agents face the same challenge.
- **Ontologies and semantic layers produce correctness.** Alake demos an agent built with an explicit ontology and semantic layer that consistently gets answers right, making the case that structured knowledge representations outperform raw retrieval for accuracy.
- **Memory and access control are first-class concerns.** An intelligence plane without principled memory management and access scoping cannot be reliably deployed in production environments.
