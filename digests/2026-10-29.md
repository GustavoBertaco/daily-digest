## Daniel Pink

**[3 Step Shutdown Ritual](https://www.youtube.com/watch?v=GSf0SO2Q1V0)**
Unfinished tasks keep consuming working memory long after you've stepped away — not because the work is hard but because the brain treats open loops as demands for attention. Baumeister and Masicampo's research showed the fix isn't completing the task; it's committing to a concrete plan for it.

- **The Zeigarnik effect is the mechanism.** Psychologist Kurt Lewin observed that waiters held unpaid orders in sharp detail and forgot them the moment the bill was settled. His student Bluma Zeigarnik formalized this: incomplete tasks actively occupy cognitive resources.
- **A plan closes the loop without finishing the work.** Participants who wrote a specific when/where/how plan for an unfinished task stopped being distracted by it — none of the actual work had moved. The brain offloads to the plan.
- **The shutdown ritual applies this daily.** A structured end-of-day routine that captures plans for open tasks is the operational translation of the Masicampo/Baumeister finding — clearing cognitive overhead for the evening rather than carrying it home implicitly.

## AI Engineer

**[Stop Guessing Your vLLM Config: Benchmarking LLMs on Runpod - Chris Vela, Runpod](https://www.youtube.com/watch?v=P_0_Th_ZzIg)**
Most teams deploy open models with default vLLM settings and tune by intuition. Runpod forward-deployed engineer Chris Vela argues for choosing configs from data — starting with use case and concurrency profile — and demos BenchPod, a benchmarking dashboard that tests configurations live against real hardware without requiring restarts.

- **Start with use case, not hardware specs.** The right config follows from workload shape (throughput vs. latency, concurrency level) rather than from model size or GPU tier alone.
- **Batch token limits are a key latency lever.** Tuning max batch tokens is shown to cut inter-token latency in the demo using Kimi K3 on a B300 — a parameter many teams overlook in favor of more visible settings.
- **BenchPod compresses the benchmarking loop.** Testing config variants against live traffic without redeploying removes a major friction point from the iteration cycle.
- **Challenge the model tier assumption.** Vela explicitly raises the question of whether a frontier model is needed at all, pointing toward right-sizing as an underused cost lever.

**[Who Is Making This Request? Agent Auth 101 - Kamil Potrec, Keycard](https://www.youtube.com/watch?v=58ulJViGFgU)**
As agents gain the ability to make requests on behalf of users — sending invoices, calling APIs, managing files — the identity and authority behind those requests becomes a critical and largely unsolved problem. Kamil Potrec surveys how agents currently acquire credentials and what proper agent authentication actually requires.

- **Current credential models are the problem.** Personal tokens, static keys, and over-privileged service accounts are how agents get access today — none of them carry per-agent identity or enable meaningful audit.
- **Proper agent auth has five requirements.** Per-agent identity, delegation chains, short-lived scoped credentials, federation with legacy systems, and policy-plus-audit are the minimum bar Potrec defines.
- **SDKs and gateways offer different tradeoffs.** Both approaches can keep credentials out of an agent's direct reach, but they differ in trust boundary complexity.
- **The invoice scenario is the forcing function.** When an agent sends an invoice using your token, the audit log can't distinguish between the agent and the user — that accountability gap is the core motivation for the whole framework.

**[Exploits Now Beat Patches: Open Source Security in the AI Era - Patrick Smyth, Chainguard](https://www.youtube.com/watch?v=xZX3pmaB8Hk)**
AI has shifted the attacker-defender balance: exploits now land before the patch on average, and AI-assisted attacks and supply chain malware have raised every attacker's effective capability. Patrick Smyth maps the current threat landscape and the practical steps teams can take now.

- **The 30-day remediation window no longer holds.** Average time-to-exploit has dropped below typical patching cycles, making month-long windows a structural liability.
- **Four attack surfaces to cover.** Malware, known CVEs, zero days, and "side doors" — CI/CD pipelines, developer laptops, and agent skills — are the four categories Smyth identifies as the current attack surface.
- **AI-assisted attacks are this year's news, not a future scenario.** The talk covers specific AI-assisted campaigns and supply chain malware waves from the current year.
- **Cooldown periods and signing are the near-term fixes.** Faster CVE remediation, dependency cooldown periods, and signing everything with SLSA and Sigstore are the actionable near-term steps.

**[We Kept Rebuilding Our AI Agent. Here's What Survived - Fuad Ali, Arize AI](https://www.youtube.com/watch?v=YIhvrvHtonk)**
Arize's in-product agent Alex went from a 2023 prototype that was "50% hallucination" to a single agent with planning, memory, and on-demand skills built with custom harness code. AI PM Fuad Ali documents the architectural decisions that survived repeated rebuilds and the ones that didn't.

- **Move the plan into the harness, not the model.** Making planning logic explicit in harness code rather than relying on the model to self-plan was one of the durable decisions across all versions.
- **Make "finish" an explicit gate.** Treating task completion as a named, gated state rather than an implicit exit reduced incomplete outputs.
- **Treat large tool results like files.** Routing large tool outputs through file-like handling rather than injecting them into context keeps the context window manageable.
- **One 8,000-character memory file beat vector stores.** A single per-user memory file outperformed both vector stores and knowledge graphs for the agent's working memory — a counterintuitive result against prevailing infrastructure assumptions.
- **The 50% hallucination baseline is the honest starting point.** Every architectural decision described was a response to observed production failures, not proactive design — a useful frame for teams still in early iteration.

**[Stop Giving Your Agent Tools. Give It a Sandbox - Mikyo King, Arize AI](https://www.youtube.com/watch?v=dAoOYFx7ZYw)**
Classic tool-calling agents fill their context windows with tool catalogs and raw outputs. Mikyo King argues for code mode — giving the agent a sandbox where it searches for and composes tools in code, returning only what it needs — and presents production eval results from Phoenix showing measurable gains.

- **Code mode trades catalog overhead for composition.** Instead of listing available tools and injecting each output verbatim, the agent searches for tools and combines them inline, returning only the relevant result.
- **Phoenix implements it across four surfaces.** Bash, a Python sandbox, SQL, and UI control are the four environments Arize built code mode into for Phoenix.
- **43% fewer tokens, 31% lower cost.** Harbor evals on the code-mode approach showed meaningful gains on both token consumption and cost compared to classic tool-calling.
- **Hidden costs need planning.** Secrets management, permissions, durability, and double sandboxing — sandboxing inside an already-sandboxed agent — are real operational costs to account for before adopting code mode at scale.
