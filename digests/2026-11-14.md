**[Your SKILL.md Is 70% Stuff the Model Already Knows - Nikolay Petrov, Intel](https://www.youtube.com/watch?v=yzx4IuEh_tU)**
Nikolay Petrov presents a methodology for auditing SKILL.md files by decomposing them into individually testable claims, revealing that most skill content duplicates what models already know — and that the genuinely valuable portion is the content most likely to be cut by naive pruning.

- **Skills grow without discipline.** Because adding a line is cheap and removing one feels risky, skill files accumulate bloat that crowds out the content that actually changes model behavior.
- **Decompose into checkable claims.** Petrov's approach splits each skill into small atomic claims and tests the model with and without each one, producing a line-level map of what the model learns from each rule versus what it already knew.
- **70/30 as a starting benchmark.** The first skill Petrov tested was 70% things the model already knew, with value concentrated in the remaining 30% — suggesting auditing most skill files would reveal similar proportions.
- **Naive shorteners cut the wrong things.** The 30% that actually matters — precise, edge-case-specific details — is exactly what a human pruning by gut feel tends to remove first, making systematic testing essential rather than optional.

**[Your Spec Has Bugs. Catch Them Before Your Agent Codes. - Rajath Mahendrappa Kotyal, AWS](https://www.youtube.com/watch?v=0EnLxIbAvYk)**
Rajath Kotyal argues that spec-driven agent development has a silent failure mode — the spec itself contains contradictions, ambiguities, and missing cases that agents faithfully implement — and presents Kiro's approach of pairing LLMs with SMT solvers to surface these before code generation begins.

- **The agent faithfully implements your bugs.** When a spec contains contradictory rules or ambiguous sentences, a coding agent doesn't surface the conflict — it just builds what it infers, potentially implementing both interpretations in different places.
- **LLM disagreement is the signal.** Kiro detects ambiguity by watching for cases where the model's outputs conflict with the spec or with each other, treating internal disagreement as a symptom of an underspecified requirement.
- **SMT solvers catch what LLMs miss.** Pairing language models with SMT (Satisfiability Modulo Theories) solvers enables formal checking of logical consistency — detecting requirements that cannot simultaneously hold even when the natural language looks plausible.
- **Knowing when each tool applies.** The presentation covers which class of spec bugs solvers catch better than LLM-as-judge and vice versa, providing a practical decision framework for spec validation tooling.

**[Agents Made Code Free. Maintaining It Didn't Get Cheaper. - Dmitry Buykin, Maersk](https://www.youtube.com/watch?v=oeknLUsN_GE)**
Dmitry Buykin presents a post-mortem from Maersk: once agents write most of a large production codebase, maintenance costs don't shrink — they shift and accumulate in ways human review processes weren't designed to catch.

- **Code generation cost went to near zero; maintenance didn't.** The asymmetry Buykin identifies is that agents eliminate the write-phase cost but have no effect on the ongoing cost of understanding, debugging, and extending a large codebase.
- **New failure modes emerge at scale.** Agent-generated codebases develop specific pathologies: tests that pass but don't reflect production behavior, uncommissioned features, contradictory rules across different agent sessions, and sprawl that grows faster than review capacity.
- **The countermeasures require deliberate process.** Replaying real tasks against existing code, maintaining expert-owned evaluations, applying runtime guardrails, and running weekly pruning sessions don't happen automatically — they require engineering discipline to institutionalize.
- **Weekly pruning as a forcing function.** Scheduled review and pruning sessions prevent the organic sprawl that accumulates when agents generate code continuously without consolidation gates.
