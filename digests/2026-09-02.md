## The Knowledge Project Podcast

**[How Failure Created the Steve Jobs We All Know | Geoffrey Cain](https://www.youtube.com/watch?v=eU4WlADVgM8)**
Geoffrey Cain spent years reconstructing the decade Steve Jobs spent outside Apple between his 1985 ouster and his late-1990s return — arguing that the NeXT years, not the original Apple run, were the actual forge of the leader who came back and transformed the company.

- **Failure as formation.** The Jobs celebrated as a visionary was shaped by sustained adversity at NeXT, not by early success. The hidden decade is the actual biography.
- **NeXT came within days of collapse.** Investors lost faith, co-founders left, the fortune nearly disappeared, and at one point the company was a weekend away from shutting down entirely.
- **The public narrative skips the hard part.** The standard Jobs story jumps from the 1985 exile to the late-1990s comeback, eliding the decade that explains the difference between Jobs v1 and Jobs v2.

**[What Is LTAP? Lakebase + Genie Explained by Databricks CTO](https://www.youtube.com/watch?v=8x6MvzAfvtw)**
Databricks CTO Matei Zaharia walks through the two launches he considers most significant from Databricks: LTAP (Lake Transactional/Analytical Processing), which eliminates separate transactional and analytic data copies in favor of a single unified store, and Genie, which applies AI-driven analytics to unstructured data sources — alongside how Unity AI Gateway governs enterprise AI at scale.

## AWS What's New

**[Amazon CloudWatch now supports warm-up periods for alarms](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-cloudwatch-alarms-warmup-period)**
CloudWatch now lets you configure a warm-up period for metric and log alarms, delaying evaluation for a set time after the alarm is created. This reduces noise from missing data while a new resource or service is still starting up and has not yet begun publishing metrics — a common pain point in CI/CD pipelines that provision alarms alongside the services they monitor.

**[Amazon DocumentDB now supports direct major version upgrades to version 8.0](https://aws.amazon.com/about-aws/whats-new/2026/08/documentdb-major-version-upgrade-8-0/)**
DocumentDB now supports in-place major version upgrades directly from engine versions 3.6 and 4.0 to 8.0, removing the need for intermediate version hops. Existing data, configurations, and cluster settings are preserved, and version 8.0 delivers the latest security patches and performance improvements.

**[Partner Revenue Measurement expands service coverage for User Agent string capability](https://aws.amazon.com/about-aws/whats-new/2026/08/partner-revenue-measurement-user-agent-expansion/)**
The Partner Revenue Measurement User Agent string now covers additional AWS services that log control plane activity in CloudTrail, significantly increasing Partners' visibility into attributed revenue and product consumption patterns.

**[AWS Agent Registry agents and MCP servers now available in Amazon Quick](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-agent-registry-agents-mcp-servers-quick/)**
Amazon Quick now integrates with AWS Agent Registry, letting users browse and enable MCP servers and agents from their organization's registry directly within the interface — connection details auto-populate from the registry. Enabled resources can then be shared with teammates, making org-wide agent discovery self-service.

**[Amazon Redshift now supports AWS IAM Identity Center authentication with enhanced VPC routing](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-redshift-supports-idc-evr)**
Redshift now supports IAM Identity Center single sign-on with corporate credentials for clusters and serverless workgroups configured with enhanced VPC routing, keeping all traffic within the AWS network and off the public internet. This directly addresses customers with data residency, regulatory, or network-isolation requirements.

**[Amazon Timestream for InfluxDB is now available in 8 additional AWS Regions](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-timestream-influxdb-regions/)**
Timestream for InfluxDB expands to eight new regions including Africa (Cape Town), Asia Pacific (Bangkok, Hong Kong, Hyderabad, Melbourne, Seoul), Europe (Zurich), and Israel (Tel Aviv). The service provides fully managed InfluxDB databases with Multi-AZ high availability for real-time time-series applications using open-source APIs.

**[Amazon Connect Global Resiliency now supports cross-region routing of contacts across two active AWS regions](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-connect-global-resiliency-cross-region-routing/)**
Connect Global Resiliency now routes contacts to the longest-available matching agent across two linked regions simultaneously — a contact arriving in US East is offered to agents in either US East or US West — so neither region sits idle as an untested standby. Managers see unified analytics and contact search across both regions as a single contact center view.

**[Amazon Redshift now supports Apache Iceberg v3 tables](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-redshift-supports-apache-iceberg-v3)**
Redshift now reads from and writes to Apache Iceberg v3 tables, introducing support for default column values, row lineage, and deletion vectors. Default column values simplify schema evolution when adding columns; row lineage tracks data origin for auditing and compliance use cases.

**[Amazon EC2 R9g and R9gd memory optimized instances are now available](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-ec2-r9g-and-r9gd-memory-optimized-instances-are-now-available/)**
R9g and R9gd instances, powered by AWS Graviton5 processors, are now generally available for memory-intensive workloads including databases, in-memory caches, real-time big data analytics, and containerized microservices. Graviton5 is AWS's fifth-generation custom CPU, targeting best price performance for memory-intensive workloads running on Amazon EC2.

**[Amazon Cognito now supports machine-to-machine authorization without a user pool domain](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-cognito-get-client-token/)**
Cognito's new GetClientToken API operation lets app clients obtain access tokens for machine-to-machine authorization through the AWS SDK, CLI, or API without needing to configure a user pool domain. App clients authenticate with their client ID and secret, simplifying service-to-service auth setup for microservices and automated workloads.
