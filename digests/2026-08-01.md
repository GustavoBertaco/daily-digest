## AWS What's New

**[Amazon SageMaker Unified Studio brings richer Git version control to all project tools](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-sagemaker-unified-studio-git/)**
SageMaker Unified Studio now provides flexible, file-level Git version control across Query Editor, Visual ETL, Workflows, and Notebooks — the last of which previously had no Git support at all. The previous automatic-sync approach is replaced with explicit file-level control, giving teams a consistent source-control experience across all project tools.

**[AWS Direct Connect now supports BGP route visibility on Virtual Interfaces](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-direct-connect-bgp-visibility/)**
AWS Direct Connect now surfaces BGP route visibility across private, transit, and public virtual interfaces, showing which routes AWS accepted from your on-premises router and which it is advertising back — along with AS path and BGP community values. Network administrators can use this to troubleshoot routing issues and verify propagation without out-of-band tooling.

**[Amazon Redshift RG large and 12xlarge instances now available on the trailing track](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-redshift-rg-large-12xlarge-trailing-track)**
Graviton-based rg.large and rg.12xlarge Redshift instances are now available on the trailing track starting with patch P202, giving stability-focused production workloads access to Graviton-powered performance. The trailing track runs on versions already validated through the leading track, making this a low-risk path to RG instance benefits.

**[IAM Policy Simulator moves to the IAM console and adds additional capabilities](https://aws.amazon.com/about-aws/whats-new/2026/07/iam-policy-simulator-iam-console/)**
IAM Policy Simulator is now integrated into the IAM console and gains support for testing service control policies (SCPs) alongside standard IAM policies. Security and platform teams can now model and validate a wider range of permission scenarios — including org-level SCPs — without leaving the console or using the old standalone URL.

**[Amazon Bedrock announces up to 80% lower prices for OpenAI GPT-5.6 models](https://aws.amazon.com/about-aws/whats-new/2026/07/openai-gpt-terra-luna-pricing-bedrock/)**
Effective July 30, 2026, Amazon Bedrock on-demand prices for GPT-5.6 Luna drop by 80% and GPT-5.6 Terra by 20%, matching OpenAI's own first-party pricing changes for the same date. GPT-5.6 Luna is optimized for fast, high-volume workloads with multi-step tool use.

**[AWS announces general availability of Policy-Based Routing on AWS Transit Gateway](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-transit-gateway-policy-based-routing/)**
Transit Gateway now supports Policy-Based Routing (PBR) in GA, enabling forwarding decisions based on source/destination IP, port, and protocol — not just destination IP alone. Customers who previously required multi-VPC architectures with extra routing hops for traffic steering or workload isolation can now achieve that with a single policy at the gateway.

**[Amazon MSK Express brokers now delivers Apache Kafka data to Amazon S3](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-msk-express-brokers-delivers-to-amazon-s3)**
MSK Express brokers can now deliver Kafka data directly to Amazon S3 general purpose buckets as a fully managed, auto-scaling capability, with costs reduced by up to 60% compared to self-managed alternatives. This closes the managed-path gap for teams that need to land Kafka data in S3 for downstream processing without building their own connector infrastructure.

**[Amazon MSK Express brokers now deliver data to streaming tables for Apache Iceberg](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-msk-streaming-tables-for-apache-iceberg)**
MSK Express can now continuously materialize Apache Kafka topics as Apache Iceberg tables on Amazon S3 Tables, reducing ingestion and delivery costs by up to 60% versus self-managed Kafka deployments and cutting downstream query costs by up to 30%. This creates a managed path from real-time Kafka topics to open-table-format storage without custom pipeline work.

# 🤖 AI & Machine Learning

## AI Engineer

**[Agents at Scale: Inside MiniMax's Model and the Infrastructure Behind It — Olive Song](https://www.youtube.com/watch?v=AVMr9PMINyo)**
Olive Song, who leads reinforcement learning at MiniMax, walks through the design decisions behind the company's open-weight model releases and the infrastructure required to serve them — grounded in a conviction that releasing weights publicly lets the builder ecosystem compound optimization work the internal team alone could not do.

- **Open weights as a distribution and leverage strategy.** MiniMax's starting premise is that putting weights out publicly — rather than locking capability behind an API — lets external builders optimize on them and share the gains widely, multiplying the impact of each internal training run.
- **Breadth of agent tasks as the evaluation surface.** The model targets agentic coding that also understands and builds games, plus computer-use problems — a wider benchmark surface than coding alone, designed to stress multi-step and interactive agent capabilities.
- **RL against environment feedback for computer use.** Computer-use problems are trained with RL against environment signals rather than pure human preference labels, making the environment itself the reward signal for interactive tasks.
- **"Landing well" is a full-stack problem.** Song frames a model landing well in production as requiring training coverage, serving infrastructure, and developer tooling together — benchmark performance is necessary but not sufficient.

**[fighting slop with slop — Vaibhav Gupta, Boundary](https://www.youtube.com/watch?v=AMiyLItEtLA)**
Vaibhav Gupta's thesis is that because you increasingly cannot tell what an agent did — just as you cannot direct a great engineer prescriptively — the right response is to deploy equally cheap, fast generation as a continuous auditing layer: using the same sloppy output to catch slop in other agents.

- **Agents monitoring agents as a runtime discipline.** Boundary runs lightweight agents continuously over the transcripts of other agents, flagging hallucinations and identifying which tool calls produced errors — making evaluation a live, ongoing process rather than a periodic batch review.
- **Comparison-as-signal without a curated benchmark.** The auditing agents compare approaches head-to-head to find which produced fewer errors, approximating automated eval without needing a ground-truth dataset.
- **Hard invariants as the non-negotiable ground wire.** Cheap generation cannot stand alone; Gupta pairs auditing agents with deterministic checks — design docs, rules, and CLI checks — that do not flex regardless of what the monitored agent produces.
- **The observability reframe.** The core problem is that directing an agent is as hard as directing a great engineer. The answer is not tighter control but better observability: instruments that reveal what happened after the fact, enabling diagnosis and correction.

**[First Steps Toward Automated AI Research — Richard Socher, CEO Recursive AI](https://www.youtube.com/watch?v=pWXUkLP9uWM)**
Richard Socher argues that automating the scientific loop itself — hypothesis, test, critique, revise — could compress the pace of discovery across disciplines, just as the prior few centuries compressed the distance from the Enlightenment to the moon landing.

- **The Eureka machine as the design target.** Socher's goal is not AI that assists researchers but a system that runs the full Popperian loop autonomously: conjecture, find shortcomings, fix — without a human in the critical path — across medicine, economics, astrophysics, and more.
- **Popper as the architecture spec.** Science advances by trying things, finding failures, and iterating; framing research automation through conjecture-and-refutation suggests the key capability is not just hypothesis generation but reliable falsification.
- **Historical compression as the ROI argument.** Humanity went from the Enlightenment to the moon landing in a few hundred years; Socher's wager is that automating research compresses the next equivalent leap by that same order.
- **No single-discipline bottleneck.** Agent swarms can run the research loop in parallel across multiple fields simultaneously, removing the per-domain human expert as the rate-limiting step for scientific progress.
