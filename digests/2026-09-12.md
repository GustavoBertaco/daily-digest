## AWS What's New

**[AWS Lambda recursive loop detection is now available in Europe Sovereign Cloud](https://aws.amazon.com/about-aws/whats-new/2026/09/lambda-recursion-europe-sovereign-cloud)**
Lambda's recursive loop detection — which automatically stops runaway recursive invocations between Lambda and services like S3, SQS, and SNS — is now supported in Europe Sovereign Cloud. The feature protects against unexpected billing caused by misconfiguration or code defects that cause events to feed back into the same function.

**[AWS Transform for .NET now generates unit tests for modernized code](https://aws.amazon.com/about-aws/whats-new/2026/09/aws-transform-net-unit-tests)**
AWS Transform for .NET can now automatically generate unit tests targeting testable classes — business logic, controllers — in applications it modernizes, delivered as part of the same migration job. This gives teams an automated test safety net on the transformed .NET codebase without a separate test-writing step.

**[Amazon API Gateway now supports 1 MB execution logs with configurable delivery destinations](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-api-gateway-1-mb-execution-logs/)**
API Gateway REST API execution logs now support events up to 1 MB — up from a previous 1 KB limit that truncated request and response data — and can be routed simultaneously to custom CloudWatch Logs groups, S3 buckets, or Firehose streams. Multiple delivery destinations can receive the same logs concurrently.

**[AWS Lambda durable functions integrates with Pydantic AI](https://aws.amazon.com/about-aws/whats-new/2026/09/aws-lambda-durable-pydantic-ai/)**
Lambda durable functions now integrates with Pydantic AI, automatically checkpointing agent progress so that after a timeout or interruption the agent resumes from the last completed step rather than restarting from scratch. Each model and tool call is persisted without requiring custom checkpoint or retry logic in the application code.

**[Amazon MQ now supports RabbitMQ 4.3](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-mq-rabbitmq-43/)**
RabbitMQ 4.3 on Amazon MQ adds quorum queue compaction to reduce disk usage, 32 strict priority levels (compared to 2 relative levels in prior versions), native delayed retries, and graceful consumer timeouts. The release also includes bug fixes and memory management performance improvements.

**[Announcing second-generation single-rack AWS Outposts](https://aws.amazon.com/about-aws/whats-new/2026/09/single-rack-aws-outposts/)**
Second-generation single-rack Outposts is now generally available: a self-contained 42U unit combining compute, storage, and networking, delivering up to 2,688 vCPU and 100 TB of EBS storage. It is purpose-built for workloads requiring low latency, local data processing, and data residency in space- and power-constrained locations.

**[Amazon OpenSearch Serverless is now available on v0 by Vercel](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-opensearch-serverless-available-V0-vercel/)**
Amazon OpenSearch Serverless is now accessible from v0 by Vercel, allowing teams to use natural language prompts to build production-ready full-stack search and AI applications without managing cluster infrastructure. OpenSearch Serverless automatically scales capacity up and down based on demand.

**[Amazon ECS expands IAM condition key support for RunTask and StartTask APIs](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-ecs-expands-condition-key-support/)**
The `ecs:task-cpu` and `ecs:task-memory` IAM condition keys are now supported on the RunTask and StartTask APIs, letting administrators enforce consistent CPU and memory limits across all task-launch methods. Previously these keys were only available at task definition registration, leaving runtime launches ungoverned and exposing teams to unexpected cost overruns.

**[Amazon Redshift RG instances now available in Europe (Zurich) Region](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-redshift-rg-available-zurich)**
Redshift RG instances — Graviton-powered, running data warehouse and data lake workloads up to 2.4x faster than previous-generation RA3 instances at 30% lower price per vCPU — are now available in the Europe (Zurich) region. RG instances include a custom-built vectorized query engine for Apache Iceberg and Parquet analytics.

## AI Engineer

**[One Designer + AI. Hundreds of Deliverables. — Vincent Wendy, AI Engineer](https://www.youtube.com/watch?v=O1FN4awNEtM)**
At AI Engineer, senior creative designer Vincent Wendy — the sole designer at a company of roughly 12-15 people — describes how he used agents to manage the design workload for a conference that grew to 7,000 attendees, 140+ sponsors, 300+ speakers, and 600+ sessions.

- **Agents as quality-control, not generation.** Wendy pointed an agent at the sponsor banner carrying more than 140 logos and asked which ones were missing. It caught every omission he then verified. He applied the same technique to the conference shirt. The primary value was systematic verification at a scale where humans miss things, not creative output.
- **The team size is the argument.** AI Engineer runs on 12-15 people and Wendy is its only designer. The conference has grown to 7,000 attendees, 140+ sponsors, 300+ speakers, and 600+ sessions — all managed by one designer.
- **The division of labor is specific.** Agents absorb repetitive, high-volume verification — logo coverage and completeness checks across 140+ logos and conference merchandise — while Wendy owns the design work.

**[Generative UI... in Python? — Jeremiah Lowin, Prefect](https://www.youtube.com/watch?v=Krzs8GeiWTc)**
Jeremiah Lowin (Prefect founder and FastMCP author) argues that MCP apps — a protocol extension that routes tool results directly to the user as rendered HTML, CSS, and JavaScript rather than through the agent — eliminates the architectural bottleneck of agent-mediated data transfer.

- **The naive file upload problem is structural, not incidental.** Without MCP apps, an agent relaying a file to an MCP server must retype it character by character. Lowin calls this "the world's most expensive copy-paste operation." It is not a bug but an unavoidable property of a protocol that forces all data through the model.
- **MCP apps bypass the agent for delivery.** A tool result can now skip the agent entirely and arrive at the user as a real, clickable interface. The protocol shifts from "LLM as mediator" to "tool communicates with user directly."
- **The FastMCP author's critique is from inside the protocol.** Lowin is founder and CEO of Prefect and the author of FastMCP; his concern about MCP's file-transfer limitation comes from direct experience building on the protocol, not from outside observation.

**[Training Taste — Thais Castello Branco, Taste Labs](https://www.youtube.com/watch?v=sDMGWK4wZ_w)**
Thais Castello Branco (founder, Taste Labs, out of stealth weeks before this talk) presents analysis of over two million websites across a decade to argue that aesthetic homogenization on the web predates AI tools — and that AI has since accelerated the collapse while stripping out contextual sensitivity.

- **The data precedes the argument.** Taste Labs analyzed more than two million websites going back a decade. The finding is specific: palettes and layouts were converging, and trends were spreading faster, before AI design tools became widespread. Attributing homogenization solely to AI misdiagnoses the timeline.
- **AI made convergence context-blind, not just faster.** The new failure mode is sameness without situational awareness. A pet shop and a finance firm end up with the same page.
- **The dataset spans more than two million websites over a decade.** The homogenization finding — palettes converging, layouts converging, trends spreading faster — comes from that data, not from aesthetic opinion.

**[Design at the Speed of Adjectives — Paul Bakaus, Renaissance Geek, Inc.](https://www.youtube.com/watch?v=v42opQpCy60)**
Paul Bakaus presents Impeccable, a design skill layered on top of AI coding agents (Claude Code, Copilot, Cursor, Codex) that makes aesthetic refinement a prompt-drivable operation — with the explicit rule that success means the output reads as intentional human design, not AI work.

- **The failure test is direct.** Bakaus's rule: show someone the output, say "AI made this bolder," and if they believe you, the skill failed. The goal is results that register as deliberate design judgment, not generated suggestions.
- **It runs on infrastructure teams already have.** Impeccable is not a separate design tool — it is a skill that layers on coding agents teams already use. Any engineer on Claude Code or Cursor can adopt it without adding a new toolchain.
- **The same-prompt comparison is the benchmark.** Running the same prompt on the same page with and without the skill, then letting the room judge the delta, is Bakaus's demonstration method.
- **Twenty-plus years of tool-building is the credibility basis.** Bakaus has built developer tools for over two decades.

**[Mousepower: agents that can't be measured, can't be managed. — Maximillian Piras, Yutori](https://www.youtube.com/watch?v=8KkibGU_DDY)**
Maximillian Piras (founding designer, Yutori) argues that computer-use agents — models that operate a computer via mouse and keyboard where no API or MCP endpoint exists — need a legible unit of capability measurement to cross the adoption gap, drawing the direct analogy to James Watt creating "horsepower" to sell steam engines to buyers who thought in horses.

- **The horsepower analogy is prescriptive, not decorative.** Watt's number was not scientific and was arguably not accurate. It did not need to be accurate — it made an abstract improvement legible to people whose frame of reference was the horse. Piras's argument is that computer-use agents face exactly the same legibility problem.
- **Computer-use agents reach software with no API.** Yutori's models operate at mouse-and-keyboard level, which means they can interact with any desktop application without requiring that application to build an integration. This is the structural difference from MCP-based agents, which require a server on the other side.
- **Measurement is the product problem, not the engineering problem.** The title makes the claim direct: agents that can't be measured can't be managed. "Mousepower" is a framing proposal for what that unit should look like.

**[The Design-Code Roundtrip That Isn't — Jonathan Gordon, ReWeaver AI](https://www.youtube.com/watch?v=NW-jwOVr32w)**
Jonathan Gordon (30+ years building developer tools and IDEs) argues that current vibe-coding workflows break the design-code roundtrip at the provenance layer — you cannot tell which decisions originated in which surface — and that this invisible gap creates security exposure you will miss unless you happen to be reading the output.

- **innerHTML was the specific wake-up moment.** Gordon was ignoring the output stream from a vibe-coding session when the string "innerHTML" caught his eye. He recognized it as an injection risk, stopped the agent, and made it revert. The lesson is operational: security review requires actively reading generated code, not trusting the pipeline.
- **A roundtrip without persistent provenance is not a roundtrip.** Gordon defines a design-code roundtrip precisely: a full loop in both directions with no fidelity loss and persistent provenance, so you always know which layer — design or code — originated each decision.
- **Thirty-plus years of IDE work frames the definition.** Gordon has spent more than thirty years building developer tools and IDEs; his precise definition of what a design-code roundtrip requires comes from that background.

**[The Spatial Harness: Bringing Agents to the Canvas — Max Drake, tldraw](https://www.youtube.com/watch?v=XWcXwnysmpY)**
Max Drake, product engineer at tldraw — the London company behind the free infinite canvas app and the SDK powering other teams' canvases including Replit's — covers why tldraw exists and how it is extending into agent workflows.

- **The window-manager-Pong story opens the talk.** A tldraw colleague turned the canvas into a window manager and used it to play Pong with real desktop windows.
- **tldraw's SDK exists because canvas primitives stopped every team at the same place.** Teams building canvas apps kept getting stuck on selection, resizing, and matrix math before reaching their actual product. The SDK separates that solved infrastructure from the application logic.
