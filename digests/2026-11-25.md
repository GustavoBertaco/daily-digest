## The Knowledge Project Podcast

**[Ex-Amazon Board Member Reveals Everything Bezos Does to Win](https://www.youtube.com/watch?v=EsNvJrkgAr4)**
Bing Gordon — former Chief Creative Officer of Electronic Arts and partner at Kleiner Perkins — spent over a decade on Amazon's board after presenting Jeff Bezos with five ideas in writing, the first of which was Amazon Prime. The episode surfaces the board-level practices and operating norms Bezos used to maintain focus and trust.

- **A written proposal earned the board seat.** Gordon secured his Amazon board position by bringing Bezos five ideas in writing; Amazon Prime was the first. The format itself signaled rigor before any conversation started.
- **Memos over slides as a structural fix.** When two directors wanted to resign, Gordon proposed a two-part remedy: Bezos opens each board meeting with what's on his mind, and six-page written memos replace slide decks — forcing clarity before discussion begins.
- **"First, do no harm."** Bezos set this as his primary rule for the board, grounding leadership behavior in restraint rather than intervention.

## Daniel Pink

**[Art Could Be As Healthy As Exercise](https://www.youtube.com/watch?v=CXgfFLd949o)**
A UCL longitudinal study tracked cultural attendance — museums, galleries, concerts, theatres — in 6,710 adults over 50 across roughly 14 years, finding that frequency of attendance predicts mortality risk even after controlling for wealth, education, and existing illness.

- **Frequency gradient is significant.** Attending cultural venues every few months correlated with a 31% lower risk of dying during the 14-year window; even once or twice a year tracked with a 14% lower risk.
- **Confounders were controlled.** The study accounted for wealth, education, and pre-existing illness, and the mortality gap held — ruling out the most common alternative explanations.
- **Scale and duration give the finding weight.** 6,710 adults tracked for approximately 14 years in the English Longitudinal Study of Ageing provides a dataset large enough to take seriously.
- **One number to remember:** Attending every few months was associated with a 31% lower mortality risk over 14 years — a magnitude that places cultural engagement alongside recognized health interventions.

## AWS What's New

**[Amazon EC2 X8i instances are now available in the Asia Pacific (New Zealand) Region](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-ec2-x8i-new-zealand/)**
Amazon EC2 X8i instances, powered by custom Intel Xeon 6 processors exclusive to AWS, are now available in the Asia Pacific (New Zealand) Region. These SAP-certified instances deliver up to 43% higher performance, 1.5x more memory capacity (up to 6 TB), and 3.3x more memory bandwidth compared to the previous generation.

**[AWS Sign-In introduces configurable Sign-in duration of up to 90 days](https://aws.amazon.com/about-aws/whats-new/2026/11/configurable-aws-sign-in-duration/)**
AWS Sign-In now lets administrators configure OAuth session duration up to 90 days for individual IAM users and roles, reducing authentication interruptions for long-running workflows and AI agents. The capability offers a more secure alternative to static access keys through short-lived, renewable credentials.

**[Amazon SageMaker HyperPod now supports managed observability and user management extensions for Slurm clusters](https://aws.amazon.com/about-aws/whats-new/2026/11/sagemaker-hyperpod-extensions/)**
SageMaker HyperPod now supports managed cluster extensions for Slurm, covering observability and user management. Previously, any change required editing lifecycle scripts and replacing or rerunning nodes; extensions let HyperPod manage these features without touching lifecycle scripts or custom AMIs.

**[Amazon API Gateway announces API Portal](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-api-gateway-announces-api-portal/)**
API Gateway's new API Portal discovers, governs, and documents APIs and AI endpoints behind API Gateway, Application Load Balancer, and CloudFront across an AWS organization. It builds a continuously updated inventory from AWS-side traffic logs and service configuration records, surfacing unregistered, unmaintained, or unprotected endpoints with no agent installation required.

**[Amazon OpenSearch Service now supports OpenSearch version 3.9](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-opensearch-3-9)**
OpenSearch 3.9 on Amazon OpenSearch Service introduces a half-float vector type and bf16 encoder — storing each vector dimension in 16 bits — alongside 2-bit and 4-bit scalar quantization options to reduce vector memory and storage. The release also expands LLM provider support for search quality evaluation and adds access controls for shared resources.

**[AWS WAF introduces simplified pricing](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-waf-introduces-simplified-pricing/)**
AWS WAF moves from per-ACL, per-rule, and per-rule-group charges to three dimensions: the resources protected, traffic inspected, and protection level applied. Adding or changing rules no longer affects the bill, removing cost friction from security decisions.

**[AWS WAF announces automated discovery and protection for LLM, MCP, and A2A endpoints using Amazon Bedrock Guardrails](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/)**
AWS WAF now automatically discovers LLM, MCP, and Agent2Agent (A2A) endpoints behind API Gateway, Application Load Balancers, and CloudFront across an AWS Organization and protects them via Amazon Bedrock Guardrails. Discovery runs through the new API Gateway API Portal, which identifies AI endpoints automatically from traffic logs.

## AI Engineer

**[How to Ship Millions of Lines of Agent-Written Code — Jarred Sumner, Anthropic](https://www.youtube.com/watch?v=TvsF67C2F54)**
Jarred Sumner, creator of Bun, describes merging several million lines of agent-written code that added an ahead-of-time compiler to Bun — the runtime behind Claude Code — across five rewrites in roughly a month, achieving approximately 4x less memory use and 2x faster startup.

- **Pre-existing tests are what make agent code trustworthy.** The team's ability to validate agent-written changes at scale rested on a test suite that predated the project — tests agents didn't write are the check on what agents produce.
- **JavaScript over Rust was a deliberate choice.** Rather than rewriting Claude Code in Rust, the team focused on making the JavaScript runtime faster through the AOT compiler, which delivers the memory and startup gains.
- **Five rewrites in a month is a workflow, not a failure.** The iterative pace reflects the low cost of regenerating large code volumes when agents do the writing, changing what "good enough to ship" means in practice.
- **140 agents in parallel shifts the bottleneck.** The work moves from writing code to orchestration, context management, and knowing when to intervene — Sumner describes what he actually does while agents write.

**[Software Factories: Escape from Trash Mountain — Steve Yegge, Gas Town](https://www.youtube.com/watch?v=SRhXgeNluIk)**
Steve Yegge, creator of Beads and Gas Town, argues that software factories — agents generating code at high velocity — accumulate a "trash mountain" of unclean code unless teams adopt deliberate management practices across the full factory lifecycle.

- **Velocity creates a cleanup deficit by design.** Factories can produce code faster than any team can maintain it, and the pile grows unless addressed structurally from the start.
- **"Five horsemen of automation."** Yegge identifies five failure modes for automated code generation at the 5:53 mark — the snippet names the topic without enumerating each one.
- **Context management and cost are the operational levers.** The talk dedicates time to work and context management and fuel/cost optimization as the practical disciplines for running a factory sustainably.
- **Wyvern RPG as a concrete case study.** Yegge grounds the talk in a game project to give teams a reference point for evaluating factory practices against real output.
