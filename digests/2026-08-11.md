# 🤖 AI & Machine Learning

## AI Engineer

**[Multiplayer agentic engineering — Arjun Singh, Superconductor](https://www.youtube.com/watch?v=OL7kfezynJM)**
Superconductor's demo of a meeting-room agent shows that ambient listening can compress the gap between an idea floated in casual conversation and a ticket on the backlog — with no human deciding to file the issue.

- **Passive listening as a work input channel.** A bot sitting silently in a four-hour Google Meet picked a feature request out of conversation — someone wanted coding agents to have clear acceptance criteria before declaring work done — and opened a ticket without anyone prompting it to do so.
- **The agent modified its own tooling.** After opening the ticket, the agent started working on the feature and added two acceptance criteria fields to the product's own ticket form, improving the very workflow it operates inside.
- **Screenshot on demand as a lightweight trust signal.** When asked, the bot produced a screenshot of the completed result — a minimal but concrete verification step that requires no formal review cycle.

**[Guide, Verify, Solve — Anirban Chatterjee, Sonar](https://www.youtube.com/watch?v=03l29gJXpCE)**
Sonar's Anirban Chatterjee frames AI-generated code as producing "verification debt" — a quality gap that lingers after the initial productivity gain fades, with a cost that scales directly with codebase criticality and adversarial exposure.

- **Productivity gains are front-loaded.** A Carnegie Mellon study of GitHub projects found the boost from AI coding tools ran out around three months in, while static analysis warnings and added complexity did not.
- **The acceptable debt ceiling depends on context.** A short-lived internal tool can absorb the gap between model-generated quality and what the application actually needs; a large codebase with adversarial users cannot.
- **Complexity is the residue, not just defects.** Static analysis warnings and structural complexity persist long after the AI writes the code — costs that are invisible in initial velocity metrics but show up later in maintenance burden.

**[Velocity Sickness: What Happens When Your Whole Team Gets 10x Faster — Matt Dailey, Ref.](https://www.youtube.com/watch?v=Kz4QJmNrVXU)**
Matt Dailey names the organizational strain that emerges when AI-amplified output outpaces a team's or audience's ability to absorb and act on it — throughput increases but impact does not keep pace.

- **Output and impact decouple.** A newsletter writer using an agentic pipeline was effectively producing a book every week, but the audience was not reading at that rate. The content existed; the impact did not.
- **Engineering teams surface the same symptom.** On a development team, velocity sickness arrives as too many pull requests to merge — work that technically ships but stalls before it lands in users' hands.
- **The bottleneck shifts from creation to consumption.** When generation is cheap, the binding constraint becomes whether people downstream can process and act on the output at the new rate — a coordination problem, not a tooling one.

**[Always-on agents run production without the on-call tax — Justin Smith, Resolve AI](https://www.youtube.com/watch?v=vSx5IULvBns)**
Resolve AI's Justin Smith shows an agent that reads a GitHub release tag, reasons about which telemetry matters for that specific change, and writes an adaptive monitoring plan for the release — rather than applying fixed alert thresholds or hardcoded schedules.

- **Release-aware monitoring, not static dashboards.** When a release tag appears in Slack, the agent reads what actually changed and derives the relevant telemetry: a currency service replacement means watch checkout latency and error rates, then trace the causal chain into the Kafka pipeline.
- **Nothing about the timing is hardcoded.** The agent can decide to check again in an hour because the behavior it observed warrants it — the monitoring cadence is reasoned, not scheduled.
- **Causal chain traversal over alert breadth.** Rather than alerting on everything, the agent follows a reasoned path through the stack from the changed service into downstream dependencies, maintaining coverage while reducing noise.
