## AI Engineer

**[The AI Bill Is Too Damn High: Tokenomics 101 — Eugene Cheah, Featherless AI](https://www.youtube.com/watch?v=Ti-BmGU1_mQ)**
Eugene Cheah presents a four-step framework for controlling AI inference costs at scale — measure, right-size, buy capacity strategically, and fix processes — with a focus on organizations where token spend is outpacing productivity gains.

- **Measurement is the prerequisite.** Splitting API keys per team surfaces where spend is actually going before any optimization can be targeted correctly.
- **Right-sizing requires matching model to task.** Using classifiers and fine-tuning to route to open models that match frontier performance on specific tasks is a direct cost lever, not just a quality trade-off.
- **Agentic and process workloads need separate budgets.** They have fundamentally different token consumption patterns; treating them the same leads to distorted unit economics.
- **Capacity purchasing strategy is a multiplier.** How compute is bought — on-demand versus committed — has a significant impact on inference costs at scale, independent of model choice.
- **"Slop grenades" are a process problem, not a model problem.** Poorly scoped prompts that generate wasteful output require process fixes; no model choice resolves them.

**[Memory-Aware Agent Harnesses for Anti-Money Laundering — Nacho Martinez, Oracle](https://www.youtube.com/watch?v=KtBivPzmOM8)**
Nacho Martinez argues that the model is the fixed constraint — the agent harness (loop architecture, short- and long-term memory, context engineering, toolbox and skillbox patterns) is where real engineering leverage lives. Applied to an autonomous AML agent that flags suspicious transactions around the clock.

- **The model is the part you can't change.** Competitive differentiation between agent deployments comes from harness design, not from model selection.
- **Short- and long-term memory serve distinct roles.** Working memory handles the active agent loop; long-term memory supports skill distillation and continual learning across episodes.
- **Context engineering is a first-class discipline.** What the agent sees at each step — and how that context is curated and compressed — determines outcome quality more directly than model capability.
- **Skillbox patterns enable compounding improvement.** Abstracting successful action sequences into reusable skills lets the agent improve over time without full retraining cycles.
- **24/7 AML monitoring is the target state.** The use case — autonomous flagging of suspicious bank transactions — illustrates how agent harnesses replace manual review workflows in high-stakes, continuous monitoring domains.

**[AI Agents Cut 3-Day Portfolio Builds to Minutes — Jack McDonald, Apollo & Michael Manapat, Rowspace](https://www.youtube.com/watch?v=BOWYujhIQuo)**
Apollo's CLO business compressed 2–3 day manual Excel-based mock portfolio builds to minutes, and automated a weekly trade reconciliation that previously required 2–3 people. The conversation examines what makes AI mission-critical rather than merely convenient in finance.

- **The portfolio build compression is the headline number.** A single mock CLO portfolio that used to take 2–3 days of manual Excel work now takes minutes — not incremental improvement but a step-change in the planning cycle.
- **Trade reconciliation is an archetypal automation target.** A repetitive, structured weekly process requiring 2–3 people is a near-universal pattern in financial operations, and this case shows how it collapses with agents.
- **Generic LLMs are insufficient for specialized finance data.** When one data point can come from multiple conflicting sources, domain-specific data handling — not a larger model — is what makes outputs reliable enough for capital decisions.
- **Mission-critical means the decision depends on it.** The framing distinguishes AI as infrastructure for decisions that move capital, not just a productivity layer on top of existing workflows.

**[Why One AI Agent Isn't Enough (And How to Run 1,000) - CJ Avilla & Harrison Stall, Anthropic](https://www.youtube.com/watch?v=kiClTcJUnhc)**
Anthropic's CJ Avilla and Harrison Stall introduce Flows in Claude Managed Agents — a system where you hand Claude a single goal and it plans and executes its own multi-agent topology of up to 1,000 agents through the API, drawing a parallel to historical limits on human team scaling.

- **Managing agent graphs is the new coordination bottleneck.** Just as managing large human engineering teams hit coordination limits (the OS/360 vs. Unix anecdote), manually wiring individual agent topologies is becoming the constraint on AI-powered work.
- **Flows abstracts the topology layer entirely.** Rather than specifying which agents run in what configuration, you provide a goal and Claude determines the appropriate multi-agent structure dynamically.
- **Up to 1,000 agents per goal via API.** The system scales to 1,000 parallel agents and allows compute to be concentrated on the phases of a task that benefit most from parallelism.
- **A stock watchlist scanner demos the pattern.** The hands-on example shows how compute allocation can be asymmetric across task phases rather than uniformly distributed across all agents.
