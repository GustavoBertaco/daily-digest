## AWS What's New

**[Amazon CloudWatch Omni now supports Microsoft Azure platform logs, metrics and traces](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-omni-microsoft-azure)**
CloudWatch Omni now collects Azure resource logs, Azure Monitor platform metrics, VNet flow logs, and Application Insights traces alongside AWS telemetry. Teams running workloads across both clouds no longer need separate monitoring tools or custom pipelines for unified visibility.

**[Web Search on Amazon Bedrock expands language support and country-aware search](https://aws.amazon.com/about-aws/whats-new/2026/11/web-search-amazon-bedrock/)**
Web Search on Bedrock adds Spanish, French, German, Italian, and Japanese — plus non-US English — for agents on Amazon Bedrock AgentCore and Bedrock. A new optional country field biases results toward sources from a specific country using an ISO 3166-1 alpha-2 code.

**[Amazon RDS for Oracle now supports Primary Endpoint](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-oracle-primary-endpoint-v2/)**
RDS for Oracle now provides a Primary Endpoint DNS name that always resolves to the current primary DB instance in a replica configuration. After a switchover, the endpoint automatically points to the new primary, eliminating manual connection string or DNS record updates.

**[AWS Lambda now publishes Event Function state change events to Amazon EventBridge](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-function-state-events/)**
Lambda now emits an event to EventBridge each time an Event Function version changes state due to a create, update, publish, or delete action. Platform and DevOps teams can trigger automation on function readiness or failure without polling the GetFunction API.

**[AWS Network Firewall introduces automated Internet firewall in public preview](https://aws.amazon.com/about-aws/whats-new/2026/11/network-firewall-automated-internet/)**
AWS Network Firewall's new automated Internet firewall mode, in public preview, adds native NAT capability at internet gateways and allows centrally defined security rules to be enforced across all inbound and outbound internet traffic for every VPC in an environment from a single configuration.

**[Amazon RDS for Oracle now supports Replica First Patching for reduced downtime](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-oracle-replica-first-patching/)**
RDS for Oracle Enterprise Edition now supports Replica First Patching, applying minor version upgrades to a replica while the primary continues serving traffic. The operator chooses when to complete the switchover, reducing downtime during minor version upgrades.

**[Amazon Cognito extends multi-Region replication to additional AWS Regions](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-mrr-opt-in-regions/)**
Cognito multi-Region replication now covers additional AWS Regions, extending near-real-time synchronization of user and machine identity data, credentials, user pool configurations, and federation setups to a standby Region to more workloads.

**[Amazon Neptune Serverless now delivers up to 30% better performance and smarter scaling](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-neptune-serverless-r8g-generally-available)**
Neptune Serverless now runs on AWS Graviton4 processors, delivering up to 30% better performance at the same price per Neptune Capacity Unit. An improved scaling algorithm adjusts NCUs more closely to actual workload demand, particularly for applications with many concurrent graph queries such as fraud detection, recommendation engines, and generative AI graph lookups.

**[Amazon CloudWatch extends the PromQL query window to 30 days](https://aws.amazon.com/about-aws/whats-new/2026/11/cloudwatch-promql-query-30days/)**
CloudWatch now supports a 30-day query window for PromQL against OpenTelemetry metrics, up from 7 days. This enables month-over-month and week-over-week trend charts, 30-day SLO calculations, and alarms on a full 30-day baseline in a single query.

**[Account Mapping and Planning now available in AWS Partner Central](https://aws.amazon.com/about-aws/whats-new/2026/11/account-mapping-and-planning/)**
AWS Partners can now upload a target account list via CSV, API, or CRM integration and have accounts automatically matched against AWS records to identify co-sell opportunities before a formal opportunity exists. This replaces the previous manual, spreadsheet-based account mapping process.

# 🤖 AI & Machine Learning

## AI Engineer

**[How to build an agent that builds the culture — Zach Bruggeman, Ramp](https://www.youtube.com/watch?v=MDI81OaZAD4)**
Ramp's Inspect tool now writes and ships around 75% of the company's code — Zach Bruggeman's CODE Summit 2026 talk argues that reaching that number required building an engineering culture around AI coding, not just deploying a tool.

- **The 75% figure is a cultural outcome, not just a technical one.** Bruggeman attributes it to shared agent tooling, open internal sessions, and visible verification — practices that made AI-assisted development legible and trustworthy across the whole team.
- **Multiplayer AI coding breaks information silos.** When agent runs are open and verifiable internally, knowledge doesn't stay locked in individual developer sessions; it circulates and builds collective confidence.
- **The Review Buddy code review agent as a trust-builder.** A purpose-built agent gave colleagues a concrete, legible artifact demonstrating how AI participation in the development workflow actually looked, reducing skepticism about its reliability.
- **A telemetry bug as a cultural proof point.** Using a real production incident to show how AI tools surface and address problems together — rather than in isolated developer contexts — made the case for broader adoption more convincingly than any demo.

**[Engineer Your Coding Agents Like Any Other System — Zach Lloyd, Warp](https://www.youtube.com/watch?v=0LeT996Hz3E)**
Zach Lloyd argues that the dominant pattern — running coding agents locally, one at a time — caps throughput and makes cost, security, and governance unmanageable; his answer is the software factory: a code-defined, closed-loop system for running and improving cloud coding agents at scale.

- **The local, one-at-a-time model is a throughput ceiling.** Treating coding agents as interactive single-session tools limits parallelism and makes systematic measurement or governance of agent behavior nearly impossible.
- **A software factory treats agents as a production system.** Lloyd's stack includes factories-as-code, recorded agent runs, sandboxed compute, swappable models and harnesses, and orchestration — the same reliability properties applied to any other production service.
- **Recorded runs are the feedback mechanism.** Capturing agent run history is what makes the system "closed-loop," enabling continuous measurement and improvement rather than one-off prompting with no audit trail.
- **Swappable models and harnesses reduce lock-in.** Building the factory so models can be exchanged without re-engineering the surrounding infrastructure keeps cost and capability options open as the model landscape shifts.
