## NextGenLakehouse

**[Coding and Custom AI Agents: Adoption, Governance and Design with Matei Zaharia](https://www.youtube.com/watch?v=sdUifFykb-I)**
A clip from a Matei Zaharia talk argues that enterprise AI agent adoption splits into two distinct tracks — coding agents being secured today and custom AI solutions being designed for tomorrow — and that success on both tracks lies in balancing governance with continuous evaluation.

- **Two tracks, two problem sets.** Coding agents and custom agents are not the same adoption challenge. Treating them as one category obscures the different governance, design, and evaluation requirements each demands.
- **Governance is the immediate work for coding agents.** Organisations securing AI coding tools today face policy gaps, data exposure risk, and tool sprawl that must be addressed before agents touch production systems.
- **Continuous evaluation, not one-time validation.** Both agent types require ongoing evaluation loops to remain effective; the framing explicitly rejects a deploy-and-move-on approach as a path to failure.

## AWS What's New

**[AWS IoT Core now supports native InfluxDB routing for time-series data](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-iot-core-influxdb/)**
AWS IoT Core now routes time-series data from IoT devices directly to InfluxDB databases via a new rule action, removing the need for custom device-side code or intermediate cloud services. The action automatically converts device data to InfluxDB's line protocol format.

**[AWS Batch now supports Amazon ECS Managed Instances](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-batch-on-ecs-managed-instances/)**
AWS Batch now supports Amazon ECS Managed Instances (ECS MI) as a compute option, enabling GPU-accelerated and compute-intensive workloads on AWS-managed infrastructure. AWS handles AMI updates, security patching, and instance lifecycle, eliminating the operational overhead of customer-managed EC2.

**[Capacity Reservation Resource Groups now support Amazon EC2 Capacity Blocks and interruptible Capacity Reservations](https://aws.amazon.com/about-aws/whats-new/2026/08/capacity-reservation-resource-groups-ec2)**
Capacity Reservation Resource Groups can now include EC2 Capacity Blocks for ML and interruptible Capacity Reservations alongside the previously supported On-Demand Capacity Reservations. This consolidates all reservation types under a single grouping mechanism for simpler instance launching.

**[AWS Lambda MicroVMs now supports AWS PrivateLink](https://aws.amazon.com/about-aws/whats-new/2026/08/lambda-microvms-supports-privatelink)**
Lambda MicroVMs now support AWS PrivateLink, enabling private VPC connectivity without routing traffic over the public internet. The feature targets regulated workloads in financial services, healthcare, and government that face strict network isolation requirements.

**[Amazon RDS for PostgreSQL supports minor versions 18.6, 17.11, 16.15, 15.19, and 14.24](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-rds-postgresql-18-6-17-11-16-15-15-19-14-24/)**
Amazon RDS for PostgreSQL now supports minor versions 18.6, 17.11, 16.15, 15.19, and 14.24, addressing CVEs in prior versions and incorporating community bug fixes. Upgrades are available through scheduled maintenance windows with automatic minor version upgrade support.

**[Amazon Connect Customer now lets you update the customer profile on a case or add a profile after a case is opened](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-connect-cases-flexible-profiles/)**
Amazon Connect Cases now allows agents to swap a customer profile on an open case or add one post-creation. Addresses scenarios such as incorrect initial profile associations and cases opened before identity verification — for example, calls from shared phone numbers.

**[IAM Roles Anywhere now provides a Java plugin for the AWS SDK](https://aws.amazon.com/about-aws/whats-new/2026/08/iam-roles-anywhere-java/)**
IAM Roles Anywhere now provides an AWS SDK for Java v2 plugin that obtains temporary AWS credentials from within the JVM, removing the requirement to run the credential helper as a separate process or configure `credential_process` in AWS profiles. Simplifies credential management for Java workloads running outside AWS.

**[AWS Lambda introduces managed runtimes in public preview for Node.js 26 and Python 3.15](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-lambda-node-js-python-public-preview/)**
Lambda introduces a new public preview stage for managed runtimes, launching with Node.js 26 and Python 3.15. This pre-GA phase lets customers and upstream language communities test and provide feedback before the Lambda team locks the runtime for general availability — a change from the previous direct-to-GA model.

## AI Engineer

**[The Missing Layer in Agentic AI — Giedrius Šteimantas, Oxylabs](https://www.youtube.com/watch?v=XsvUhpnHepE)**
Giedrius Šteimantas argues that web data access is the unaddressed layer in most agentic stacks: agents receive HTTP 200 responses with reasonable payload sizes, conclude the fetch succeeded, and forward useless content — CAPTCHAs, bot-deflection pages — to the model as if it were real data. Most teams never detect the problem because no error surfaces.

- **HTTP 200 is not a signal of real content.** Anti-bot responses arrive with valid status codes and plausible response sizes — the two indicators agents normally use to confirm a fetch succeeded. A 200 does not mean the page is real.
- **Token waste is the visible symptom.** Point an agent at ten product pages, get real content back from three, and send all ten to the model anyway: seventy percent of those tokens go to reading CAPTCHAs rather than actual data.
- **The problem stays invisible inside model context.** Because status codes and response sizes look clean, there is no error log to alert on — the degradation manifests only in the quality of model outputs, where it is easily misattributed to the model itself.
- **The motivating example: a personal shopping agent.** A friend vibe-coded a shopping assistant that captures style preferences then hands prompts to a second agent to execute purchases — a real-world agentic pipeline where data quality at the web-access layer directly determines whether the end-to-end workflow functions at all.

**[Einstein Arena: Harnessing Collective Agent Intelligence for Open Science — James Zou, Together AI](https://www.youtube.com/watch?v=mMNkdYnIVC4)**
James Zou and collaborators at Together AI and Stanford built Einstein Arena on the thesis that prescribing how an agent reasons caps what it can achieve, while designing the right environment and reward signal does not — making it an environment for AI agents to tackle open scientific problems rather than a guided workflow.

- **Environments over workflows.** Telling an agent step-by-step how to work imposes a ceiling on its performance. Defining where it operates and what it is rewarded for allows capability to emerge without that constraint.
- **Humans are locked out by design.** Entry requires solving a puzzle that proves the entrant is an AI agent. Keeping the arena agent-only ensures the collaboration dynamics and feedback signals remain agent-native from the start.
- **Deterministic verifiers make progress measurable.** Each open problem in the arena comes with a verifier that checks answers objectively, removing the need for human evaluation and enabling automated scoring at scale.
- **Collective intelligence through failure-sharing.** Agents can query a forum to learn what approaches have already failed, enabling a form of collaborative problem-solving where negative results reduce redundant exploration across the agent population.
