## AI Engineer

**[Your Voice Agent is Just a Walkie Talkie — Neil Zeghidour, Gradium](https://www.youtube.com/watch?v=a8EcVumh71E)**
Neil Zeghidour, co-founder and CEO of Gradium, argues that every production voice model shipping today is half-duplex — it either listens or speaks, never both — and that closing this gap is the defining unsolved problem in real-time voice AI.

- **The 20% overlap problem.** On a typical phone call between people who know each other, both parties speak simultaneously roughly 20% of the time. Half-duplex systems cannot model this at all, which is why they feel mechanically unnatural regardless of voice quality.
- **A decade-long trajectory.** Zeghidour traces the arc from a 2011 phone assistant that mapped transcripts to app actions through the first open-ended voice chat, framing full-duplex not as a new idea but as the long-deferred step the field has been building toward.
- **Audio-native training as the path forward.** Gradium trains audio foundation models — the transcript excerpt is truncated before Zeghidour completes the argument for how this approach addresses the half-duplex gap.

**[Voice Agents Can Just Do Things — Charlie Guo, OpenAI](https://www.youtube.com/watch?v=OpY6MmZFeHo)**
Charlie Guo from OpenAI's developer experience team challenges the near-universal assumption that a voice agent must respond in speech, arguing that conflating input modality with output modality causes builders to miss large classes of more useful interactions.

- **The three modes of voice interaction are decades old.** Moviefone was speech-to-speech; a car GPS was event-to-speech. Guo's point is not that new things are newly possible but that we stopped noticing the full design space that has always existed.
- **Voice in, action out.** Software spends most of its time doing things, not narrating them. A voice agent that triggers a workflow and stays silent is frequently better UX than one that reads a confirmation back at the user.
- **The assumption goes unexamined.** Guo frames "voice in means voice out" as a default that almost every builder carries into a project without questioning it — which makes it a high-leverage design decision hiding in plain sight.

**[Speech-to-Speech Model Research at Google DeepMind — Valeria Wu Fon & Tom Ouyang, Google DeepMind](https://www.youtube.com/watch?v=18Um2VjMM_g)**
Valeria Wu Fon and Tom Ouyang describe how training on audio, video, and text jointly — rather than pipelining separate models — produces emergent multilingual behaviors that no explicit rule could have specified.

- **The mid-century sofa example.** Asked in Spanish about a mid-century sofa, the model answers in Spanish but retains "mid century" in English, because that is how Spanish speakers actually use the term. No rule was written for this; it falls out of joint training.
- **Before roughly 2018, everything was pipelines.** The field was built from stitched-together ASR, NLU, and TTS components, and that architecture imposes a ceiling on naturalness that no amount of component improvement can break through.
- **Multimodal training is the unlock.** Audio and video carry social and pragmatic signals that text strips out. The language-mixing behavior the model demonstrates is not achievable by training on text alone.

**[Agents Without Code: Skills, YAML, and Filesystems Replaced Python — Philipp Schmid, Google DeepMind](https://www.youtube.com/watch?v=fjF8EKnxKCU)**
Philipp Schmid builds the same GitHub pull request review agent three times on stage, deleting code with each pass, to demonstrate that Python tool definitions and JSON schemas are a transitional layer that modern models no longer require.

- **Version one: hand-written tool definitions.** Full Python, explicit JSON schemas, verbose boilerplate. Functional, but tightly coupled to a specific model interface.
- **Version two: framework-managed tools.** Schema boilerplate disappears; the logic remains but is now abstracted.
- **Version three: no source directory.** What remains is an AGENTS.md holding the system instruction and a small bash script for first-run setup. No tool definitions, no Python. The model reads the markdown and acts.
- **The test for equivalence is a throwaway question.** After each pass, Schmid applies the same question — what is the weather in San Francisco? — to verify the agent does not answer it, using a consistent behavioral check to confirm that successive simplification preserved the original scope.

**[How We Solved Agent Building — Andrew Qu, Vercel](https://www.youtube.com/watch?v=9dYcwOkpCE8)**
Vercel's Chief of Software shares a year-long arc of building an internal data science agent: from a system clearing 30% of evals that its first real users called "awful," to a tool that actually shipped inside the company.

- **Find the right problem before writing agent code.** Qu spent months interviewing marketing, sales, finance, and legal before settling on a use case. The winning answer came from a lean data team overwhelmed by one-off questions from a faster-growing company around it.
- **30% evals felt like progress; users disagreed.** The first version passed nearly a third of automated evaluations and the team thought they were on track. Real users handed it back. The gap between benchmark performance and user satisfaction was the central lesson of the project.
- **The iteration loop is the whole job.** The talk covers the cycle between eval metrics, user feedback, and product decisions — a grounded account of what closing the gap between 30% benchmark performance and an "awful" user verdict actually requires.

**[No Memory, No Harness: Why the Database Is the Last Line of Defense — Kay Malcolm, Oracle](https://www.youtube.com/watch?v=jA_x7F8caHI)**
Kay Malcolm from Oracle's outbound database product team argues that AI made individuals on her distributed team faster without making the team more productive, and that the missing layer is structured, queryable context — not more tooling on top of the model.

- **Git records what, not why.** When the Netherlands half of her team commits code at 4 AM her time, the US half wakes to the diff but not the reasoning behind it. AI amplified the output gap without closing the context gap.
- **Individual speed without team throughput.** The team got individually faster with AI assistance; collective productivity did not improve proportionally. Malcolm frames this as a structural problem with a database-layer solution, not a tooling problem that more AI can fix.
- **The database as the missing context layer.** The decision history, constraints, and design rationale that AI agents need live in the database rather than in the model weights or the agent harness. Malcolm's twenty years in database product management ground this as an engineering argument, not a product pitch.

**[We let an AI agent execute Bash and lived to talk about it — Sarah Sanders, PostHog](https://www.youtube.com/watch?v=4lXks428C9o)**
Sarah Sanders, context engineer at PostHog, describes the security architecture required to ship a public agentic CLI (Wizard) that reads codebases, installs SDKs, and executes commands on developer machines — and the prompt injection attack chain that nearly made the whole thing untenable.

- **The injection surface is the content pipeline.** Someone opens a PR on an open-source repo and drops a line into a markdown file. Automated code review reads it and says "looks good." That file feeds an agent running on thousands of developer machines. The review system was the vector, not the agent itself.
- **Wizard's privilege footprint is real.** The agentic CLI reads a codebase, installs the right SDK, instruments events, and builds dashboards — high-privilege operations on arbitrary developer environments. The threat model is not theoretical.
- **Executing Bash was a deliberate design choice.** The talk frames the decision to allow arbitrary command execution as an explicit tradeoff, then covers the mitigations that made it shippable — rather than treating shell access as an inherently bad idea to be avoided.
- **The attack chain Sanders describes is concrete, not hypothetical.** The specific path from open-source PR to prompt injection payload to remote execution is grounded in PostHog's actual architecture, making this one of the more actionable security talks on agentic systems from this conference.
