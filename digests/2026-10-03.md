## AWS What's New

**[GuardDuty Runtime Monitoring is now included in the AWS Security Hub Threat Analytics plan](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-security-hub-runtime-monitoring/)**
GuardDuty Runtime Monitoring — which inspects OS, network, and file activity to detect container escapes, privilege escalation, and cryptomining on EC2, EKS, and ECS on Fargate — is now billed through Security Hub's Threat Analytics plan. Customers with Security Hub already enabled in an account and region no longer need a separate GuardDuty subscription to get this runtime coverage.

**[AWS Well-Architected Agent is now available in preview](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-well-architected-agent/)**
AWS Well-Architected Agent is an AI-powered service positioned as the next generation of Trusted Advisor and the Well-Architected Tool, analyzing cost, security, performance, and reliability by correlating key metrics and application topology against Well-Architected best practices. It can parse Terraform, CDK, and CloudFormation templates and delivers contextualized recommendations prioritized by business goals.

**[Amazon Redshift now supports cross-Region queries for your data lake](https://aws.amazon.com/about-aws/whats-new/2026/10/redshift-cross-Region-queries-for-data-lake)**
Redshift can now query Amazon S3 data lake tables located in a different AWS Region, with enhanced VPC routing keeping query traffic within the customer's own VPC. Both the cross-Region query capability and VPC routing run on the integrated data lake query engine directly on RG provisioned and Serverless cluster compute, targeting enterprises with globally distributed data and security-sensitive workloads requiring tight network control.

**[Amazon DynamoDB introduces filtered export to Amazon S3](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-dynamodb-introduces-filtered-export/)**
DynamoDB's export-to-S3 now supports filtered exports, letting customers specify a key condition expression on a key attribute and a filter expression on non-key attributes to export only the items and attributes relevant to a use case. Both full and incremental exports support filtering, reducing the dataset size delivered to downstream analytics or data-sharing pipelines.

**[Amazon DynamoDB Accelerator (DAX) is now available in additional Regions](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-dynamodb-accelerator/)**
DAX is now available in 17 additional AWS Regions: Asia Pacific (Hong Kong, Hyderabad, Jakarta, Malaysia, Melbourne, New Zealand, Osaka, Seoul, Taipei, Thailand), Canada West (Calgary), Europe (Milan, Zurich), Israel (Tel Aviv), Mexico (Central), and both AWS GovCloud (US-East and US-West) regions.

**[Amazon GuardDuty now supports centralized management using AWS Organizations declarative policies](https://aws.amazon.com/about-aws/whats-new/2026/10/guardduty-org-enablement-policies/)**
GuardDuty can now be enabled and configured across all accounts and Regions in an AWS Organization through a single declarative policy. The configuration applies to existing accounts and propagates automatically as new accounts join the organization, ensuring comprehensive threat detection coverage without per-account manual enablement.

**[Amazon Corretto 8 September 2026 Patch Updates](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-corretto-8-sept-2026-updates/)**
Corretto 8u504 is now available, released September 30, 2026. This patch update includes the tzdata 2026d timezone data updates.

## AI Engineer

**[Your Coding Agent Is 6 Months Out of Date — Jakub Hojsan, Exa](https://www.youtube.com/watch?v=cKhpeEBnT1o)**
Models ship roughly six months behind their knowledge cutoff, meaning coding and code-review agents are evaluating changes they have never seen — Exa's argument is that targeted, policy-driven search is the only real fix, and that generic web search does not close the gap.

- **The blind spot is structural, not a prompt problem.** Every model ships about six months behind its knowledge cutoff; a code review agent is reviewing code it literally has no training signal on, regardless of model quality.
- **Generic web search doesn't solve it.** Hojsan shows why bolting on a plain web search tool is insufficient — without retrieval discipline, it returns noise and burns tokens without surfacing the actually relevant context.
- **Agents need explicit rules for when to search.** The fix is not just having a search tool but defining the policy conditions under which the agent invokes it; unguided search invocation is itself a failure mode.
- **Query-dependent highlights cut context dramatically.** Exa built a mechanism that reduces a 100,000-character page down to the query-relevant excerpt, making retrieval tractable within real-world context window limits.
- **A real PR grounds the failure mode.** The talk walks through an actual pull request that falls in a model's blind spot, making the problem concrete rather than theoretical.

**[MCP Doesn't Suck. Your Agent Does. — Jan Čurn, Apify](https://www.youtube.com/watch?v=pAnLpiAG6Es)**
Jan Čurn, founder and CEO of Apify, argues that the MCP backlash misidentifies the failure layer — context bloat and token burn are agent harness implementation problems, not protocol problems, and the industry has already converged on three fixes.

- **The backlash misidentifies the failure layer.** Context bloat and token burn come from naive client implementations that load all tools into context at once; the MCP protocol specification is not the source of these symptoms.
- **Three industry fixes have emerged.** Sub-agents, progressive tool discovery, and Code Mode are the patterns the industry has converged on to address naive MCP client behavior.
- **CLIs fit how agents reason better.** Čurn argues that command-line-style interfaces are a better match for LLM reasoning patterns, with implications for how tool interfaces should be designed.
- **MCP for remote access; CLI for local execution.** The recommended split: use MCP when remote tool access is needed, and a CLI-style interface for local agent execution contexts.

**[Stop Renting Your AI's Memory — Dylan Couzon, Qdrant](https://www.youtube.com/watch?v=apyrzaWj0Z4)**
Dylan Couzon of Qdrant argues that frontier-class models can now run on hardware you own, but the memory layer — what actually makes an assistant useful and personalized — still resides in vendor clouds, and that is the real leverage point worth owning.

- **The lock-in is memory, not compute.** Frontier models are increasingly runnable on owned hardware; the strategic dependency is the memory layer that contextualizes those models, which currently lives in third-party infrastructure.
- **Memory decomposes into three operations: write, retrieve, forget.** Couzon's framing breaks memory down into these primitives, using them as the design vocabulary for what an ownable assistant memory layer requires.
- **Retrieval beats a folder of markdown at scale.** A structured retrieval system outperforms flat file storage as the knowledge base grows.
- **A fully offline drone demo grounds the architecture.** The live demo shows a drone building its own searchable memory store locally, demonstrating the pattern works without any cloud dependency.
